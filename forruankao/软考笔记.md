### 1.1.2 CPU 核心组成：运算器 vs 控制器

CPU 核心功能包括：**程序控制**（按顺序执行指令）、**操作控制**（下发各部件微操作信号）、**时间控制**（严格的时钟节拍）、**数据处理**（算术与逻辑运算）以及**中断处理**。

#### 1. 运算器（Arithmetic and Logic Unit, ALU）
> **核心职责**：执行所有的**算术运算**（加、减、乘、除）和**逻辑运算**（与、或、非、异或、位移）。

| 部件名称 | 英文缩写 | 核心功能与记忆关键词 |
| :--- | :---: | :--- |
| **算术逻辑单元** | **ALU** | 运算器的核心计算引擎，负责执行具体的算术与逻辑指令。 |
| **累加寄存器** | **AC** | ⭐ **暂存操作数或 ALU 计算产生的中间结果**（为 ALU 提供操作数并存储输出）。 |
| **数据缓冲寄存器** | **DR** | 作为 CPU 与外界传输的临时中转站，**暂存刚从内存读出或即将写入内存的数据/指令字**。 |
| **状态条件寄存器** | **PSW** | ⭐ **保存当前运算结果的状态标志位**（进位 `C`、溢出 `V`、零标志 `Z`、符号 `N`）及中断屏蔽标志。 |

#### 2. 控制器（Control Unit, CU）
> **核心职责**：计算机的“神经中枢与指挥官”，负责**取指令、译码分析、发出控制信号**，协调整机各部件步调一致运行。

| 部件名称       |    英文缩写    | 核心功能与记忆关键词                                             |
| :--------- | :--------: | :----------------------------------------------------- |
| **程序计数器**  |   **PC**   | ⭐ **必考核心**：**存放 CPU 即将执行的下一条指令在内存中的物理地址**（执行时自动自增 +1）。 |
| **指令寄存器**  |   **IR**   | ⭐ **必考核心**：**存放当前正在执行的指令本身**（包含操作码 OP 与地址码 AD）。        |
| **指令译码器**  |   **ID**   | 对 IR 中的**操作码进行分析与解释**，识别指令含义并驱动微操作控制逻辑。                |
| **地址寄存器**  |   **AR**   | **暂存当前 CPU 正在访问的内存单元地址**（连接地址总线 AB）。                   |
| **时序控制逻辑** | **Timing** | 产生高精度的机器周期、节拍脉冲与时钟同步信号。                                |

#### 3. 软考真题快速归属与秒杀口诀
- **运算器 4 大件**：`ALU`（算术逻辑单元）、`AC`（累加器）、`DR`（数据缓冲）、`PSW`（程序状态字）。
- **控制器 5 大件**：`PC`（程序计数器）、`IR`（指令寄存器）、`ID`（指令译码器）、`AR`（地址寄存器）、时序发生器。
- **秒杀定性口诀**：
  - “**下一条指令地址**” $\longrightarrow$ 锁定 **PC**
  - “**当前正在执行的指令**” $\longrightarrow$ 锁定 **IR**
  - “**分析/解释操作码**” $\longrightarrow$ 锁定 **ID**
  - “**暂存运算中间结果**” $\longrightarrow$ 锁定 **AC**
  - “**溢出/进位/状态标志**” $\longrightarrow$ 锁定 **PSW**

### 1.1.3 一条指令的完整执行流程（指令周期）

![[一条指令的执行过程.png]]

#### 📝 四阶段数据流核心提炼
1. **取指令（Fetch）**：
   - `PC` 寄存器输出目标指令地址 $\to$ `AR` $\to$ 地址总线（AB） $\to$ 访问主存；
   - 主存读出指令内容 $\to$ 数据总线（DB） $\to$ `DR` $\to$ 存入 `IR`；
   - **`PC` 自动自增 (+1)**，提前指向紧随其后的下一条指令。
2. **分析指令 / 译码（Decode）**：
   - `IR` 中的操作码（OP）送入 `ID`（指令译码器）进行译码；
   - 控制器根据地址码（AD）计算操作数的真实**有效地址（EA）**。
3. **执行指令（Execute）**：
   - 根据有效地址从内存/寄存器取出操作数送入 `ALU`；
   - `ALU` 执行运算，将最终结果写入 `AC` 或主存，并同步刷新 `PSW` 标志位。
4. **中断检查与下一周期**：
   - 检查是否有外设中断请求，若无中断则直接进入下一条指令的取指周期。

## 1.2 计算机数制与进制转换

计算机底层均采用二进制存储和处理数据，在程序设计与软考分析中常用八进制、十进制和十六进制进行表示与计算。

---

### 1.2.1 常见四种数制的基本特征

| 进制名称 | 英文标识 / 前缀与后缀 | 基数 | 组成数字与字符 | 位权底数 |
| :--- | :--- | :---: | :--- | :---: |
| **二进制 (Binary)** | `0b` 或 `0B` 开头；以 `B` 结尾（如 `0b1011` 或 `1011B`） | 2 | `0, 1` | $2^i$ |
| **八进制 (Octal)** | `0` 开头；以 `O` 或 `Q` 结尾（如 `0127` 或 `127O`） | 8 | `0 ~ 7` | $8^i$ |
| **十进制 (Decimal)** | 默认无前缀；以 `D` 结尾（如 `189` 或 `189D`） | 10 | `0 ~ 9` | $10^i$ |
| **十六进制 (Hexadecimal)** | `0x` 或 `0X` 开头；以 `H` 结尾（如 `0x2F` 或 `2FH`） | 16 | `0 ~ 9, A ~ F`（A=10, B=11, C=12, D=13, E=14, F=15） | $16^i$ |

---

### 1.2.2 核心进制转换方法全解

#### 1. 十进制 $\longleftrightarrow$ 二进制互转

- **① 十进制 $\longrightarrow$ 二进制**：
  - **整数部分（除 2 取余法）**：十进制整数不断除以 2，直到商为 0，将每次所得余数**由下往上（逆序）**排列。
    > **例**：将 $(13)_{10}$ 转为二进制：  
    > $13 \div 2 = 6 \dots 余\ 1$（低位 LSB）  
    > $6 \div 2 = 3 \dots 余\ 0$  
    > $3 \div 2 = 1 \dots 余\ 1$  
    > $1 \div 2 = 0 \dots 余\ 1$（高位 MSB）  
    > 余数逆序读取为：`1101B`。
  - **小数部分（乘 2 取整法）**：小数部分不断乘以 2，每次取乘积的整数部分，剩下的小数部分继续乘 2，直到小数为 0 或达到指定精度，将整数部分**由上往下（顺序）**排列。
    > **例**：将 $(0.625)_{10}$ 转为二进制：  
    > $0.625 \times 2 = 1.25 \to 取整数\ 1$  
    > $0.25 \times 2 = 0.5 \to 取整数\ 0$  
    > $0.5 \times 2 = 1.0 \to 取整数\ 1$  
    > 顺序读取为：`0.101B`。
  - **减权凑数法（考场心算推荐）**：
    - 熟记 2 的各次幂权值：$128, 64, 32, 16, 8, 4, 2, 1$
    - $13 = 8 + 4 + 1 \longrightarrow 1101_B$
    - $93 = 64 + 16 + 8 + 4 + 1 \longrightarrow 0101\ 1101_B$

- **② 二进制 $\longrightarrow$ 十进制**：
  - **按权展开法**：各位数字乘以 $2^i$ 并求和。
    $$\text{例：}(1011.01)_2 = 1\times 2^3 + 0\times 2^2 + 1\times 2^1 + 1\times 2^0 + 0\times 2^{-1} + 1\times 2^{-2} = 8 + 0 + 2 + 1 + 0 + 0.25 = 11.25$$
  - **8421 编码法（单字节速算）**：8 位二进制位权 `[128, 64, 32, 16, 8, 4, 2, 1]`，直接将值为 1 的对应权值累加。

---

#### 2. 二进制 $\longleftrightarrow$ 八进制互转（3 位分组 / 4-2-1 法则）

- **① 二进制 $\longrightarrow$ 八进制**：
  - 以小数点为界，**整数向左、小数向右**，每 **3 位** 为一组（高位/低位不足补 `0`），每组转换为对应的 1 位八进制数（$2^3=8$）。
  - **例**：`011 101 010 . 100 B` $\longrightarrow$ `(352.4)O`
- **② 八进制 $\longrightarrow$ 二进制**：
  - 每一位八进制数直接按 4-2-1 码展开为 3 位二进制。
  - **例**：`(753)O` $\longrightarrow$ $7(111), 5(101), 3(011) \longrightarrow$ `111101011B`

---

#### 3. 二进制 $\longleftrightarrow$ 十六进制互转（4 位分组 / 8-4-2-1 法则）

- **① 二进制 $\longrightarrow$ 十六进制**：
  - 以小数点为界，**整数向左、小数向右**，每 **4 位** 为一组（不足补 `0`），每组转换为 1 位十六进制字符（$2^4=16$）。
  - **例**：`0010 1101 1010 . 1100 B` $\longrightarrow$ `0x2DA.C`（或 `2DA.CH`）
- **② 十六进制 $\longrightarrow$ 二进制**：
  - 每一位十六进制字符按 8-4-2-1 展开为 4 位二进制。
  - **例**：`0x3FA8` $\longrightarrow$ $3(0011), F(1111), A(1010), 8(1000) \longrightarrow$ `0011 1111 1010 1000 B`

---

#### 4. 十六进制 $\longleftrightarrow$ 十进制互转

- **① 十六进制 $\longrightarrow$ 十进制**：按权展开（$\sum d_i \times 16^i$）。
  $$\text{例：}(2\text{AF})_{16} = 2 \times 16^2 + 10 \times 16^1 + 15 \times 16^0 = 512 + 160 + 15 = 687$$
- **② 十进制 $\longrightarrow$ 十六进制**：
  - **速算路线**：十进制 $\longrightarrow$ 二进制 $\longrightarrow$ 4 位一组转十六进制。
    > **例**：$200 \to 128 + 64 + 8 \to 1100\ 1000_B \to \text{0xC8}$。

## 1.3 计算机码制（原码 / 反码 / 补码 / 移码）与数值表示范围

在计算机内部，所有数据均采用二进制编码存储。为了表示正负号并简化硬件运算，计算机体系设计了四种主要机器码制。

---

### 1.3.1 机器数与真值
- **真值**：带正负号的实际物理数值（人类习惯形式），如 $+13$、$-13$、$+0.5$。
- **机器数**：在计算机内部用二进制编码表示的数。最高位固定为**符号位**（`0` 正 `1` 负），其余位为数值位。常用机器码包括原码、反码、补码和移码。

---

### 1.3.2 四大码制核心定义与转换

以 **8 位字长（1 位符号位 + 7 位数值位）定点整数** 为例：

```
8 位二进制结构： [ 符号位 b7 ] [ 数值位 b6 b5 b4 b3 b2 b1 b0 ]
                   0 为正 (+)
                   1 为负 (-)
```

#### 1. 原码（True Form）
- **定义**：最高位为符号位（`0` 正 `1` 负），数值位直接采用真值的绝对值二进制表示。
- **正负数规则**：
  - 正数：如 $+13 \longrightarrow [X]_{原} = \mathbf{0}000\ 1101_B$
  - 负数：如 $-13 \longrightarrow [X]_{原} = \mathbf{1}000\ 1101_B$
- **零的双重表示（致命缺陷 1）**：
  - $[+0]_{原} = \mathbf{0}000\ 0000_B$
  - $[-0]_{原} = \mathbf{1}000\ 0000_B$
- **不能直接做减法运算（致命缺陷 2）**：
  若直接用原码计算 $1 + (-1)$：
  $$[1]_{原} + [-1]_{原} = 00000001_B + 10000001_B = 10000010_B = (-2)_{10} \quad (\text{结果错误})$$
  硬件若要支持原码减法，必须设计复杂的符号判断逻辑和独立的硬件减法器电路，成本极高。

---

#### 2. 反码（1's Complement）
- **定义**：为了解决原码减法问题而引入的过渡编码。
- **正负数规则**：
  - **正数**：反码与原码完全相同（正数“三码合一”）。如 $+13 \longrightarrow [X]_{反} = \mathbf{0}000\ 1101_B$
  - **负数**：**符号位保持 1 不变，其余数值位按位取反（0 变 1，1 变 0）**。如 $-13 \longrightarrow [X]_{反} = \mathbf{1}111\ 0010_B$
- **零的双重表示**：
  - $[+0]_{反} = \mathbf{0}000\ 0000_B$
  - $[-0]_{反} = \mathbf{1}111\ 1111_B$
- **缺陷**：运算时逢最高符号位进位需要加回到最低位（**端面循环进位**），且依然存在 $+0$ 与 $-0$ 两种编码，硬件判零复杂，未被现代计算机作为最终存储标准。

---

#### 3. 补码（2's Complement · 现代计算机底层基石 ⭐）
- **定义**：现代 CPU 内部**存储、传输和计算带符号整数的标准编码**。其本质是模运算（Modular Arithmetic）。
- **正负数规则**：
  - **正数**：补码与原码完全相同。如 $+13 \longrightarrow [X]_{补} = \mathbf{0}000\ 1101_B$
  - **负数**：**负数的反码加 1**（即符号位为 1，数值位按位取反后在最低位 $+1$）。  
    如 $-13 \longrightarrow [X]_{原} = 1000\ 1101_B \to [X]_{反} = 1111\ 0010_B \xrightarrow{+1} [X]_{补} = \mathbf{1}111\ 0011_B$
- **⚡ 软考考场求补码/原码秒杀捷径（从右向左扫描法）**：
  > 对于负数：从二进制最低位（最右边）开始向左扫描，**找到第一个出现的 `1`**：
  > 1. 这个 `1` 以及它右边的所有 `0` 保持原样不动；
  > 2. 这个 `1` 左边的所有位（除最高符号位外），**全部按位取反**。
  >
  > *例：$-13$ 原码为 $1000\ 110\mathbf{1}$，从右往左第一个 1 在最后一位，保持不动，左边取反得 $1111\ 0011$（一秒得补码）！*
- **零的唯一表示（彻底消除 -0 歧义）**：
  - $[+0]_{补} = 0000\ 0000_B$
  - $[-0]_{补} = 1111\ 1111_B + 1 = [1]\ 0000\ 0000_B$（最高进位溢出自动丢弃）$= 0000\ 0000_B$
  - 因此在补码中 **零只有唯一表示：`00000000`**。
- **独占编码 $-128$**：原码中表示 $-0$ 的无用编码 `10000000`，在补码中被赋予特殊定义，人为规定为 **$-2^{n-1} = -128$**。因此 **$n$ 位补码的表示范围比原码和反码多能表示一个最小负数**。

---

#### 4. 移码（Offset Binary / Excess Code）
- **定义**：在数轴上将数据统一平移一个固定偏移量（通常为 $2^{n-1}$）。移码在数轴上与真值大小保持严格单调递增。
- **转换关系（一秒互转法则）**：
  $$\mathbf{[X]_{移} = [X]_{补} 的符号位取反（数值位完全保持不变）}$$
  - 例：$[+13]_{补} = \mathbf{0}000\ 1101_B \longrightarrow [+13]_{移} = \mathbf{1}000\ 1101_B$
  - 例：$[-13]_{补} = \mathbf{1}111\ 0011_B \longrightarrow [-13]_{移} = \mathbf{0}111\ 0011_B$
- **零的表示**：$[0]_{移} = \mathbf{1}000\ 0000_B$（移码中 0 的符号位为 1）。
- **核心应用场景（必考点）**：
  - 移码最高位为 1 代表正数、0 代表负数，硬件比较大小极快。
  - **在 IEEE 754 浮点数规范中，移码被专门用于表示浮点数的“阶码”（Exponent）**。

---

### 1.3.3 补码加法器实现减法与溢出判断

#### 1. 补码加法实现减法
现代计算机硬件中，**减法统一转化为补码加法**：
$$[A - B]_{补} = [A + (-B)]_{补} = [A]_{补} + [-B]_{补}$$
- **工程价值**：CPU 内部只需设计高速二进制加法器与取反门电路，无需单独设计减法器，大幅精简了 ALU 芯片面积并提升运算频率。

> **实战计算示例**：计算 $13 - 13$（即 $13 + (-13)$）：
> - $[+13]_{补} = 0000\ 1101_B$
> - $[-13]_{补} = 1111\ 0011_B$
> - 补码相加：
>   $$\begin{array}{r@{\quad}l}
>     0000\ 1101 \\
>   + 1111\ 0011 \\
>   \hline
>   [1]\ 0000\ 0000
>   \end{array}$$
> - 最高进位自然溢出丢弃，结果为 `0000 0000`（真值为 0，结果绝对正确！）。

---

#### 2. 运算溢出及其硬件判断方法
当两个同符号数相加（或异符号数相减），运算结果超出了当前字长能表示的数值极值时，即发生**溢出（Overflow）**。

| 溢出判断方法 | 硬件实现与判定逻辑 |
| :--- | :--- |
| **单符号位进位法<br>（PSW 状态位判断）** | 设符号位产生的进位输出为 $C_s$，最高数值位产生的进位输出为 $C_p$。<br>$$\text{溢出标志 } V = C_s \oplus C_p$$<br>若 $C_s \neq C_p$（异或为 1），则表明**发生溢出**；若 $C_s = C_p$（异或为 0），则**无溢出**。 |
| **双符号位判溢法<br>（变形补码 / 模 4 补码）** | 寄存器中用 **2 位** 表示符号位：`00` 表示正数，`11` 表示负数。<br>- 运算结果符号为 `00`：正数，无溢出；<br>- 运算结果符号为 `11`：负数，无溢出；<br>- 运算结果符号为 `01`：**正溢出（上溢）**；<br>- 运算结果符号为 `10`：**负溢出（下溢）**。 |

> 💡 **溢出判断实战计算示例**：  
> 设字长为 8 位，计算 $(+70) + (+80)$：
> - $[+70]_{补} = 0100\ 0110_B$，$[+80]_{补} = 0101\ 0000_B$
> - **方法 1（单符号位法）**：
>   $$\begin{array}{r@{\quad}l}
>     0100\ 0110 \\
>   + 0101\ 0000 \\
>   \hline
>     1001\ 0110
>   \end{array}$$
>   最高数值位向符号位有进位 $C_p = 1$，符号位向更高位无进位 $C_s = 0$。  
>   溢出标志 $V = C_s \oplus C_p = 0 \oplus 1 = \mathbf{1} \implies \mathbf{发生正溢出}$（两个正数相加结果变成了负数）。
> - **方法 2（双符号位法）**：
>   $[+70]_{变形补} = 00,1000110_B$，$[[+80]_{变形补} = 00,1010000_B$  
>   相加得：$01,0010110_B$。双符号位为 $\mathbf{01} \implies \mathbf{发生正溢出}$。

### 1.3.4 定点数数值表示范围公式全矩阵

设机器字长为 $n$ 位（含 1 位符号位，数值位占 $n-1$ 位）：

#### 1. 定点整数数值范围表

| 码制 | $n$ 位通用公式范围 | 8 位字长范围 ($n=8$) | 16 位字长范围 ($n=16$) |
| :--- | :--- | :--- | :--- |
| **原码** | $-(2^{n-1}-1) \sim +(2^{n-1}-1)$ | $-127 \sim +127$ | $-32767 \sim +32767$ |
| **反码** | $-(2^{n-1}-1) \sim +(2^{n-1}-1)$ | $-127 \sim +127$ | $-32767 \sim +32767$ |
| **补码** ⭐ | $\mathbf{-2^{n-1} \sim +(2^{n-1}-1)}$ | $\mathbf{-128 \sim +127}$ | $\mathbf{-32768 \sim +32767}$ |
| **移码** ⭐ | $\mathbf{-2^{n-1} \sim +(2^{n-1}-1)}$ | $\mathbf{-128 \sim +127}$ | $\mathbf{-32768 \sim +32767}$ |

#### 2. 定点小数数值范围表

| 码制 | $n$ 位通用公式范围 | 8 位字长范围 ($n=8$) |
| :--- | :--- | :--- |
| **原码** | $-(1 - 2^{-(n-1)}) \sim +(1 - 2^{-(n-1)})$ | $-(1 - 2^{-7}) \sim +(1 - 2^{-7})$ |
| **反码** | $-(1 - 2^{-(n-1)}) \sim +(1 - 2^{-(n-1)})$ | $-(1 - 2^{-7}) \sim +(1 - 2^{-7})$ |
| **补码** | $\mathbf{-1 \sim +(1 - 2^{-(n-1)})}$ | $\mathbf{-1 \sim +(1 - 2^{-7})}$ |
| **移码** | $\mathbf{-1 \sim +(1 - 2^{-(n-1)})}$ | $\mathbf{-1 \sim +(1 - 2^{-7})}$ |

> 💡 **数值范围真题实战示例**：  
> 某计算机字长为 16 位，采用补码表示带符号整数，则该计算机能够表示的整数范围是多少？  
> - 代入补码整数公式，其中 $n = 16$：
>   $$\text{最小值} = -2^{16-1} = -2^{15} = \mathbf{-32768}$$
>   $$\text{最大值} = +(2^{16-1} - 1) = +(2^{15} - 1) = \mathbf{+32767}$$
> - 若改用原码表示，则范围缩小为 $\mathbf{-32767 \sim +32767}$（因原码存在 $+0$ 与 $-0$ 两个编码）。

### 1.3.5 软考第一章核心真题速记口诀

1. **正数三码合一**：正数的原码、反码、补码完全相同，移码只需将符号位由 0 变 1。
2. **负数补码转换**：原码 $\to$ 反码（符号不变其余取反） $\to$ 补码（反码加 1）。
3. **移码等于补码变符号**：$[X]_{移}$ 与 $[X]_{补}$ 仅符号位相反，其余数值位完全相同（专门用于浮点阶码）。
4. **范围补移多一个**：原码、反码有正负零之分，对称分布；补码、移码零的表示唯一，负数端多能表示一个最小值（$-2^{n-1}$ 或 $-1$）。
5. **减法变加法**：$[A - B]_{补} = [A]_{补} + [-B]_{补}$，硬件只需加法器即可实现加减运算。
6. **寄存器功能秒杀**：
   - 下一条指令地址 $\to$ **PC**
   - 当前正在执行指令 $\to$ **IR**
   - 操作码译码 $\to$ **ID**
   - 暂存运算中间值 $\to$ **AC**
   - 进位/溢出标志 $\to$ **PSW**
## 1.4 指令系统与寻址方式

---

### 1.4.1 指令与指令格式基础

- **指令（机器指令）**：指示计算机执行某种特定操作的二进制代码命令，是计算机运行的**最小功能单位**。一台计算机所支持的全部机器指令的集合称为该计算机的**指令系统（Instruction Set）**。
- **指令的标准格式**：一条典型的机器指令通常由 **操作码字段（OP）** 和 **地址码字段（AD / A）** 两大部分组成。

```
┌───────────────────────────┬───────────────────────────────────────────┐
│     操作码字段 (OP)       │             地址码字段 (AD / A)            │
│   (指明“做什么操作”)      │        (指明“对谁操作 / 操作数地址”)        │
└───────────────────────────┴───────────────────────────────────────────┘
```

1. **操作码（Operation Code, OP）**：指明计算机要执行的操作性质（如加法 `ADD`、传送 `MOV`、跳转 `JMP`、停机 `HALT` 等）。$n$ 位操作码最多可表示 $2^n$ 条不同指令。
2. **地址码（Address Code, AD）**：指明操作数所在的主存地址、寄存器编号或操作数本身。根据地址码数量，指令可分为**三地址指令、二地址指令、一地址指令和零地址指令**。

---

### 1.4.2 软考核心寻址方式全解

> **寻址方式概念**：寻找**操作数有效地址（Effective Address, EA）**以及寻找**下一条将要执行的指令地址**的方法。软考重点考查**操作数寻址方式**。

```
寻址速度总体排序（由快到慢）：
【立即寻址】 > 【寄存器寻址】 > 【直接寻址】 > 【寄存器间接寻址】 > 【间接寻址】
```

#### 1. 立即寻址（Immediate Addressing）
- **寻址原理**：**形式地址码部分直接就是操作数本身**（称为立即数 `#DATA`）。
- **访存次数**：取指令时访问主存 **1 次**，执行阶段**无需访问主存（0 次访存）**。
- **优点**：指令执行阶段不访问主存，**运算执行速度最快**。
- **缺点**：地址码字段的字长位数限制了立即数的表示范围和精度。

#### 2. 直接寻址（Direct Addressing）
- **寻址原理**：**指令中的地址码直接给出操作数在主存中的绝对有效地址**：$EA = A$。
- **访存次数**：取指令访问主存 1 次，取操作数访问主存 1 次，执行一条指令**共需访存 2 次**。
- **优点**：硬件实现简单，执行阶段直接按地址取数，无需进行复杂的地址折算。
- **缺点**：地址码长度限制了最大寻址空间，地址固定不便于程序动态重定位。

#### 3. 间接寻址（Indirect Addressing）
- **寻址原理**：**指令中的地址码给出的是操作数有效地址所在的存储单元地址**（即“地址的地址”）：$EA = (A)$。
- **访存次数**：
  - 一次间址：取指 1 次 + 取有效地址 1 次 + 取操作数 1 次 $\longrightarrow$ **共需访存 3 次**；
  - 多次间址：按间址级数增加访存次数。
- **优点**：极大地**扩大了指令的寻址范围**，便于编写通用子程序与指针跳转。
- **缺点**：需要多次访问主存，**指令执行速度显著变慢**。

#### 4. 寄存器寻址（Register Direct Addressing）
- **寻址原理**：**指令中的地址码直接给出存放操作数的 CPU 内部通用寄存器编号 $R_i$**：$EA = R_i$。
- **访存次数**：取指令访问主存 **1 次**，取操作数直接在 CPU 寄存器内部进行（**执行阶段 0 次访存**）。
- **优点**：寄存器访问速度极快，指令字长较短，不占总线。
- **缺点**：CPU 内部寄存器数量有限，存储容量小。

#### 5. 寄存器间接寻址（Register Indirect Addressing）
- **寻址原理**：**指令中的寄存器 $R_i$ 中存放的不是操作数，而是操作数在主存中的有效物理地址**：$EA = (R_i)$。
- **访存次数**：取指 1 次 + 根据寄存器地址访问主存取操作数 1 次 $\longrightarrow$ **共需访存 2 次**。
- **优点**：兼具寄存器的高速灵活性与主存的大容量寻址，比纯内存间接寻址少 1 次访存。

#### 6. 相对寻址（Relative Addressing）
- **寻址原理**：**以当前程序计数器（PC）的内容为基准，加上指令中的形式地址偏移量 $D$**：
  $$EA = (PC) + D$$
- **核心特点与考点**：
  - 主要用于**转移指令（条件跳转 / 循环跳转）**。
  - **最大优势**：操作数的地址随指令在内存中的位置变化而相对不变，非常**便于程序在内存中浮动和动态重定位**。
- 💡 **相对寻址计算示例**：  
  设当前转移指令存放在主存地址 `2000H` 处，指令长度为 2 字节（CPU 取指后 PC 自动加 2 变为 `2002H`），指令中的相对偏移量 $D = +08\text{H}$，则跳转的目标有效地址为：
  $$EA = (PC) + D = \text{2002H} + \text{0008H} = \mathbf{200AH}$$

#### 7. 基址寻址 vs 变址寻址（软考常考对比）

| 寻址方式 | 有效地址计算公式 | 寄存器修改权限 | 主要应用场景 |
| :--- | :--- | :--- | :--- |
| **基址寻址<br>(Base)** | $$EA = (BR) + D$$<br>*(BR 为基址寄存器)* | **操作系统内核控制**<br>(用户程序不可修改 BR) | 用于**多道程序设计**和程序的动态重定位，扩大寻址空间。 |
| **变址寻址<br>(Indexed)** | $$EA = (IX) + D$$<br>*(IX 为变址寄存器)* | **用户程序自由修改**<br>(指令执行中自动自增/修改) | 专门用于**数组遍历、循环程序、字符串与数据块处理**。 |

- 💡 **基址/变址寻址计算示例**：  
  - **基址寻址示例**：操作系统为当前程序分配的基址寄存器 $(BR) = \text{3000H}$，指令中给出的逻辑形式地址 $D = \text{0100H}$，则访问的实际物理有效地址为：
    $$EA = (BR) + D = \text{3000H} + \text{0100H} = \mathbf{3100H}$$
  - **变址寻址示例**：数组首地址形式地址 $D = \text{2000H}$，变址寄存器 $(IX)$ 作为数组下标偏移量，当前循环中 $(IX) = \text{0004H}$，则当前访问的数组元素有效地址为：
    $$EA = (IX) + D = \text{0004H} + \text{2000H} = \mathbf{2004H}$$

### 1.4.3 软考寻址方式核心特征与访存矩阵表

| 寻址方式 | 操作数所在位置 | 有效地址 $EA$ 公式 | 执行阶段访存次数 | 核心特性速记 |
| :--- | :---: | :--- | :---: | :--- |
| **立即寻址** | 指令内部 | 无 ($A$ 即为操作数) | **0 次** | 速度最快，数在指令中 |
| **直接寻址** | 主存单元 | $EA = A$ | **1 次** | $A$ 就是内存地址 |
| **间接寻址** | 主存单元 | $EA = (A)$ | **$\ge 2$ 次** | 扩大寻址范围，速度最慢 |
| **寄存器寻址** | CPU 寄存器 | $EA = R_i$ | **0 次** | 操作数在寄存器中，速度快 |
| **寄存器间接** | 主存单元 | $EA = (R_i)$ | **1 次** | 寄存器里存的是内存地址 |
| **相对寻址** | 主存单元 | $EA = (PC) + D$ | **1 次** | 常用于跳转与代码相对浮动 |
| **基址寻址** | 主存单元 | $EA = (BR) + D$ | **1 次** | OS 管理，多道程序重定位 |
| **变址寻址** | 主存单元 | $EA = (IX) + D$ | **1 次** | 用户管理，数组/循环利器 |

### 1.4.4 CISC vs RISC 体系结构对比（⭐ 软考上午必考 1 题）

现代计算机指令系统架构主要分为 **复杂指令集（CISC）** 与 **精简指令集（RISC）** 两大流派：

| 对比维度 | 复杂指令集计算机 (CISC) | 精简指令集计算机 (RISC) ⭐ |
| :--- | :--- | :--- |
| **代表架构** | Intel x86、AMD x86-64 | ARM、MIPS、RISC-V |
| **指令数量** | 数量庞大（几百到上千条），使用频率差异大 | 只保留**高频使用的简单指令**（通常小于 100 条） |
| **指令字长** | **指令长度不固定**，指令格式多 | **指令长度固定**（如 32 位），格式规范统一 |
| **寻址方式** | 支持**多种复杂的寻址方式** | **寻址方式极少**（通常仅 2～3 种） |
| **访存限制** | 绝大多数指令均可直接访问内存 | **仅 Load（加载）/ Store（存储）指令可访存**，其余指令均在寄存器间操作 |
| **实现机制** | 大多采用 **微程序控制器（Microcode）** | 大多采用 **硬布线逻辑控制器（门电路硬件组合）**，速度极快 |
| **通用寄存器** | 数量较少 | **配置大量通用寄存器**（数十到上百个） |
| **流水线支持** | 难以实现高效流水线 | **天然适合单周期指令流水线技术**（通常 1 个时钟周期执行 1 条指令） |
| **编译器优化** | 编译器负担较轻 | **重度依赖高级语言优化编译器**将复杂逻辑拆解为精简指令 |

1. **寻址速度看位置**：立即寻址不访存，寄存寻址内芯转；直接寻址访存一，间接寻址最耗时。
2. **专用寻址记场景**：
   - 相对寻址配 **PC**，代码浮动好跳转；
   - 变址寻址配 **IX**，数组循环最常见；
   - 基址寻址配 **BR**，系统分配重定位。
3. **RISC 架构五大特征（选择题必选）**：
   - **定长指令**、**简寻址**；
   - **硬布线控制**、**多寄存器**；
   - **仅 Load/Store 能访存**、**流水线效率高**。



## 1.5 指令流水线技术（⭐ 软考高频必考计算题）

---

### 1.5.1 指令流水线基本概念

- **流水线原理**：将一条指令的执行过程分解为若干个互不相关的子过程（子阶段），每个子阶段由专门的独立功能部件并行处理。多条指令在空间上重叠推进，实现**时间上的并行**（类似工业装配流水线）。
- **典型的三级流水线划分**：
  $$\text{取指令 (Fetch, IF)} \longrightarrow \text{分析/译码 (Decode, ID)} \longrightarrow \text{执行 (Execute, EX)}$$

```
时钟周期:  1    2    3    4    5    6    7
指令 1:  [IF] [ID] [EX]
指令 2:       [IF] [ID] [EX]
指令 3:            [IF] [ID] [EX]
指令 4:                 [IF] [ID] [EX]
指令 5:                      [IF] [ID] [EX]
```

---

### 1.5.2 流水线四大核心性能指标与计算公式（必背）

设一条指令分解为 $k$ 个流水段，各段所需执行时间分别为 $t_1, t_2, \dots, t_k$，需要连续执行 $n$ 条指令：

#### 1. 流水线周期（$\Delta t$）
- **定义**：流水线中各子过程执行时间中的**最长耗时**（即流水线的“瓶颈段”耗时）。
- **公式**：
  $$\mathbf{\Delta t = \max(t_1, t_2, \dots, t_k)}$$

---

#### 2. 流水线执行时间（$T_k$ · 核心考点）
执行 $n$ 条指令的总耗时分为**理论公式**与**实践公式**（软考选择题优先采用理论公式，若无理论公式选项则选实践公式）：

- **① 理论公式（软考首选 ⭐）**：
  $$\mathbf{T_{理论} = 一条指令的完整执行时间 + (n - 1) \times \Delta t = \sum_{i=1}^{k} t_i + (n - 1) \times \Delta t}$$
  > **口诀**：**首条指令走完全程，剩余指令每拍一条**。

- **② 实践公式 / 简化公式**：
  将每个流水段的耗时均视为最长段 $\Delta t$：
  $$\mathbf{T_{实践} = (k + n - 1) \times \Delta t}$$

> 💡 **真题实战计算示例**：  
> 一条指令由 取指（$2\text{ns}$）、分析（$2\text{ns}$）、执行（$1\text{ns}$）三段组成，连续执行 100 条指令：
> - 流水线周期 $\Delta t = \max(2, 2, 1) = 2\text{ns}$
> - 单条指令总耗时 $= 2 + 2 + 1 = 5\text{ns}$
> - 理论执行时间 $T = 5 + (100 - 1) \times 2 = 5 + 198 = \mathbf{203\text{ ns}}$
> - 实践执行时间 $T = (3 + 100 - 1) \times 2 = \mathbf{204\text{ ns}}$

---

#### 3. 流水线吞吐率（Throughput Rate, $TP$）
- **定义**：单位时间内流水线所完成的指令数量或输出结果的数量。
- **实际吞吐率（$TP$）**：
  $$\mathbf{TP = \frac{n}{T_k} = \frac{n}{\sum_{i=1}^k t_i + (n-1)\Delta t}}$$
- **最大吞吐率（$TP_{\max}$ · 渐进极限）**：
  当连续执行的指令数 $n \to \infty$ 时，吞吐率达到理论最大极限（受制于瓶颈段周期）：
  $$\mathbf{TP_{\max} = \lim_{n \to \infty} \frac{n}{T_k} = \frac{1}{\Delta t}}$$
- 💡 **吞吐率计算示例**：  
  延续上述例题（$n=100$，理论总耗时 $T=203\text{ns}$，流水线周期 $\Delta t = 2\text{ns}$）：
  - 实际吞吐率 $TP = \frac{100}{203\text{ ns}} \approx \mathbf{0.4926 \text{ 条/ns}}$
  - 最大吞吐率 $TP_{\max} = \frac{1}{\Delta t} = \frac{1}{2\text{ ns}} = \mathbf{0.5 \text{ 条/ns}}$

---

#### 4. 流水线加速比（Speedup Ratio, $S$）
- **定义**：**不采用流水线**时的顺序执行总时间与**采用流水线**时的执行总时间之比。
- **公式**：
  $$\mathbf{S = \frac{T_{非流水}}{T_{流水}} = \frac{n \times \sum_{i=1}^k t_i}{\sum_{i=1}^k t_i + (n-1)\Delta t}}$$
- **最大加速比**：当 $n \to \infty$ 且各流水段耗时相等时，$S_{\max} = k$（流水段数）。
- 💡 **加速比计算示例**：  
  延续上述例题（非流水线顺序执行单条指令需 $5\text{ns}$，100 条指令非流水耗时 $T_{非流水} = 100 \times 5 = 500\text{ns}$，流水线耗时 $T_{流水} = 203\text{ns}$）：
  $$S = \frac{T_{非流水}}{T_{流水}} = \frac{500\text{ ns}}{203\text{ ns}} \approx \mathbf{2.463}$$
  *(表明采用流水线后指令执行速度提升了约 2.46 倍)*

---

#### 5. 流水线效率（Efficiency, $E$）
- **定义**：流水线各功能部件的**时间有效利用率**（即时空图中设备忙碌面积与总时空面积之比）。
- **公式**：
  $$\mathbf{E = \frac{n \text{ 条指令的实际时空面积}}{k \text{ 个部件的总时空面积}} = \frac{T_0}{k \times T_k} = \frac{n \times \sum_{i=1}^k t_i}{k \times T_k} = \frac{S}{k}}$$
- 💡 **效率计算示例**：  
  延续上述例题（流水段数 $k=3$，加速比 $S \approx 2.463$）：
  $$E = \frac{S}{k} = \frac{2.463}{3} \approx \mathbf{82.1\%}$$
  *(或按面积计算：$E = \frac{100 \times (2+2+1)}{3 \times 203} = \frac{500}{609} \approx \mathbf{82.1\%}$)*

---

### 1.5.3 流水线冲突与阻滞（软考定性考点）

流水线在实际运行中可能因为资源争用或逻辑依赖产生停顿（气泡 Bubble），主要包含以下三大冲突：

| 冲突分类 | 产生原因 | 常见解决方案 |
| :--- | :--- | :--- |
| **结构冲突<br>(资源冲突)** | 多条指令在同一时刻争用**同一硬件资源**（如同时访问同一个主存端口）。 | 1. 指令 Cache 与数据 Cache 分离（哈佛结构）；<br>2. 插入空操作周期（气泡 Stall）。 |
| **数据冲突<br>(数据相关)** | 下一条指令需要使用上一条指令的运算结果，但该结果尚未写回寄存器。 | 1. **定向技术（旁路转发 Forwarding）**（最有效）；<br>2. 编译器插入 NOP 指令或指令重排；<br>3. 硬件阻塞挂起。 |
| **控制冲突<br>(分支冲突)** | 遇到**条件转移指令（Branch）**或中断，下一条指令的地址无法在取指阶段确定。 | 1. **分支预测技术（静态/动态预测）**；<br>2. 延迟转移（Delay Slot）；<br>3. 尽早计算出分支目标地址。 |

---

### 1.5.4 超标量与超流水线处理机（高频概念）

- **超标量（Superscalar）流水线**：
  - CPU 内部配置**多个独立的执行部件（ALU）**；
  - 每个时钟周期可以**同时发射多条独立指令（$IPC > 1$）**，属于空间并行。
- **超流水线（Superpipelining）**：
  - 将每个流水段再细分成更多的小段，极大地提高时钟主频；
  - 属于时间上的深度并行。

---

### 1.5.5 流水线秒杀速记口诀

1. **周期找最大**：$\Delta t = \max(t_1, t_2, \dots, t_k)$。
2. **总时理论先**：首条走完全程，余条每拍一个（$T = 首条 + (n-1)\Delta t$）。
3. **极限看周期**：最大吞吐率 $TP_{\max} = \frac{1}{\Delta t}$，与指令条数无关。
4. **加速比看倍数**：不流耗时比上流，理想上限为段数 $k$。
5. **数据冲突靠旁路**，**分支冲突靠预测**，**结构冲突分 Cache**。


## 1.6 主存编址与存储系统（⭐ 软考高频必考计算题）

---

### 1.6.1 主存基本概念与编址方式

- **存储元（Bit，位）**：存放 1 位二进制代码（`0` 或 `1`）的最小物理半导体器件。
- **存储单元（Storage Unit）**：由若干个存储元组成，是**CPU 访问存储器的基本信息单位**。
- **存储体（Memory Bank）**：由大量存储单元构成的矩阵阵列。
- **编址（Addressing）**：为每个存储单元分配一个唯一的二进制物理编号（称为**地址**）。在逻辑上构成线性的物理地址空间，通常用**十六进制数**表示（如 `0x0000` 到 `0xFFFF`）。

#### 💡 编址两大方式对比（软考核心审题点）

| 编址方式                                 | 核心特征与定义                                                                       |          1 个地址对应的容量           |
| :----------------------------------- | :---------------------------------------------------------------------------- | :---------------------------: |
| **按字节编址<br>（Byte Addressing · 最常见）** | 每个存储单元的大小为 **1 字节（$1\text{ Byte} = 8\text{ bit}$）**。<br>若题干未特别指明，**默认按字节编址**。 |      **$8\text{ bit}$**       |
| **按字编址<br>(Word Addressing)**        | 每个存储单元的大小为 **1 个机器字（Word）**。<br>字长（Word Length）由机器决定（如 16 位、32 位、64 位）。       | **$16 / 32 / 64\text{ bit}$** |

---

### 1.6.2 存储容量与地址范围计算（生活比喻 + 核心公式）

#### 💡 秒懂模型：储物柜（酒店房间）比喻
理解主存计算，只需要建立一个**“储物柜”**的直观画面：
- **内存地址** = 储物柜的**门牌号**（例如从 `AC000H` 到 `CFFFFH`）；
- **存储单元个数（地址数）** = 这一排一共有**多少个储物柜（抽屉数）**；
- **编址方式** = 每个储物柜**内部有多大空间（能放几颗糖/几个比特）**：
  - **按字节编址**：每个柜子正好放 **1 字节（$1\text{ Byte} = 8\text{ bit}$）** 的数据；
  - **按字编址**：每个柜子放 **1 个字（例如 $16\text{ bit}$ 或 $32\text{ bit}$）** 的数据。
- **总容量** = **储物柜总数 $\times$ 每个柜子的大小**。

```
储物柜编号 (地址):    [0000H]      [0001H]      [0002H]   ......   [FFFFH]
                   ┌──────────┐ ┌──────────┐ ┌──────────┐        ┌──────────┐
每个柜子放的数据:   │  8 bit   │ │  8 bit   │ │  8 bit   │ ...... │  8 bit   │ (按字节编址)
                   └──────────┘ └──────────┘ └──────────┘        └──────────┘
总容量 = 【柜子总数量 (大地址 - 小地址 + 1)】 × 【每个柜子装 8 bit / 1 Byte】
```

---

#### 1. 存储单元个数（抽屉总数）计算
给定起始内存地址（小地址）和结束内存地址（大地址）：
$$\mathbf{\text{存储单元总数（抽屉数）} = \text{结束地址（大地址）} - \text{起始地址（小地址）} + 1}$$

> ⚡ **为什么要 $+1$？**（植树原理）：从 1 号柜到 5 号柜，共有 $5 - 1 + 1 = 5$ 个柜子。  
> ⚡ **十六进制极速相减技巧**：
> 先把大地址末位 $+1$（如 `CFFFFH + 1 = D0000H`），再直接做不带借位的减法：`D0000H - AC000H = 24000H`。

---

#### 2. 总存储容量计算公式
$$\mathbf{\text{总存储容量} = \text{存储单元个数（抽屉数）} \times \text{每个抽屉的大小（编址单位）}}$$

- **若题目说明“按字节编址”（最常见，考试没说明默认按字节）**：
  $$\text{总存储容量} = \text{存储单元个数} \times 1\text{ Byte} = \text{存储单元个数 (B)}$$
  *(即算出来有多少个抽屉，就有多少个 Byte！)*
- **若题目说明“按字编址”（设字长为 16 位）**：
  $$\text{总存储容量} = \text{存储单元个数} \times 16\text{ bit} = \text{存储单元个数} \times 2\text{ Byte}$$

---

#### 3. 十六进制抽屉数 $\to$ KB/MB 极速换算方法

考场上算出十六进制数（如 `24000H` 个抽屉）后，如何换算为多少 KB？

- **方法 1：基准常数缩放法（考场最快推荐 ⭐）**：
  - 牢记基准：**$10000\text{H} = 16^4 = 65536 = 64\text{ K}$**；**$1000\text{H} = 16^3 = 4096 = 4\text{ K}$**。
  - 把 `24000H` 拆开：$20000\text{H} + 4000\text{H} = (2 \times 64\text{K}) + (4 \times 4\text{K}) = 128\text{K} + 16\text{K} = \mathbf{144\text{ K}}$。
- **方法 2：化成十进制再除以 1024**：
  - $\text{24000H} = 2 \times 16^4 + 4 \times 16^3 = 2 \times 65536 + 4 \times 4096 = 131072 + 16384 = 147456$。
  - 换算成 $\text{KB} = 147456 \div 1024 = \mathbf{144\text{ KB}}$。

---

#### 4. 存储容量单位换算表（必须熟记 $2^n$ 对照）

| 单位缩写 | 英文全称 | 换算字节数（Byte） | $2^n$ 幂次表示 |
| :---: | :---: | :---: | :---: |
| **B** | Byte（字节） | $1\text{ B} = 8\text{ bit}$ | $2^0\text{ B}$ |
| **KB** | Kilobyte | $1\text{ KB} = 1024\text{ B}$ | **$2^{10}\text{ B}$** |
| **MB** | Megabyte | $1\text{ MB} = 1024\text{ KB}$ | **$2^{20}\text{ B}$** |
| **GB** | Gigabyte | $1\text{ GB} = 1024\text{ MB}$ | **$2^{30}\text{ B}$** |
| **TB** | Terabyte | $1\text{ TB} = 1024\text{ GB}$ | **$2^{40}\text{ B}$** |

---

### 1.6.3 存储芯片扩展与所需芯片片数计算

在实际计算机中，主存由多个小容量的半导体芯片拼接扩展而成：

$$\mathbf{\text{所需芯片总数} = \frac{\text{目标总存储容量}}{\text{单片芯片容量}} = \frac{\text{目标单元数} \times \text{目标位宽}}{\text{单片单元数} \times \text{单片位宽}}}$$

```
三种芯片扩展方式：
1. 位扩展（字长扩展）：芯片单元数相同，位宽不够 -> 并联扩展数据总线（如用 8 片 1K × 1bit 组成 1K × 8bit）
2. 字扩展（容量扩展）：芯片位宽相同，单元数不够 -> 串联通过片选信号 CS 扩展地址空间
3. 字位同时扩展：单元数和位宽均不够 -> 矩阵二维排列扩展
```

---

### 1.6.4 软考经典真题演算范例

> 📝 **真题典型例题**：  
> 内存地址空间为 `AC000H` 到 `CFFFFH`，若按字节编址，则该内存区域的容量为多少 KB？若用容量为 $16\text{K} \times 4\text{bit}$ 的存储芯片构成该内存，共需多少片？

- **解题步骤**：
  1. **算单元数**：
     $$\text{单元数} = \text{CFFFFH} - \text{AC000H} + 1 = \text{CFFFFH} + 1 - \text{AC000H} = \text{D0000H} - \text{AC000H} = \text{24000H}$$
  2. **十六进制转容量（KB）**：
     $$\text{24000H} = 2 \times 16^4 + 4 \times 16^3 = 2 \times 65536 + 4 \times 4096 = 131072 + 16384 = 147456 \text{ 字节}$$
     $$\text{容量} = \frac{147456}{1024} = \mathbf{144\text{ KB}}$$
     *(速算法：$\text{24000H} = 24\text{H} \times 16^3 = (2\times 16 + 4) \times 4096 = 36 \times 4096 = 36 \times 4\text{ KB} = 144\text{ KB}$)*
  3. **按字节编址总容量**：
     $$\text{总容量} = 144\text{ KB} \times 8\text{ bit} = 144\text{K} \times 8\text{ bit}$$
  4. **算芯片片数**：
     $$\text{芯片数} = \frac{144\text{K} \times 8\text{ bit}}{16\text{K} \times 4\text{ bit}} = \frac{144}{16} \times \frac{8}{4} = 9 \times 2 = \mathbf{18\text{ 片}}$$

### 1.6.5 常见半导体存储器分类对比（SRAM vs DRAM）

| 存储器类型 | 中文全称 | 基本存储元原理 | 核心特性与应用场景 |
| :--- | :--- | :--- | :--- |
| **SRAM** | 静态随机存取存储器 | 双稳态触发器电路（无需刷新） | **存取速度极快、价格昂贵、集成度低**。<br>⭐ **主要用于 CPU 内部的高速缓存（Cache）**。 |
| **DRAM** | 动态随机存取存储器 | 电容充放电存储电荷（**需周期性动态刷新**） | **存取速度较快、容量大、成本低、集成度高**。<br>⭐ **主要用于计算机的主存储器（内存条）**。 |
| **ROM** | 只读存储器 | 掩膜/浮栅器件 | **断电后数据不丢失（非易失性）**。<br>主要用于存放 BIOS、固件程序。 |

---

### 1.6.6 主存编址秒杀速记口诀

1. **容量计算三步走**：大地址减小地址加一，化成千字节（KB），再乘编址位宽。
2. **芯片片数看比值**：总容量除以单片容量，字对字、位对位分别相除再相乘。
3. **Cache 用 SRAM（快且贵无需刷）**，**主存用 DRAM（电容充电需刷新）**。

## 1.7 层次化存储体系与 Cache 高速缓存（⭐ 软考高频必考核心）

---

### 1.7.1 层次化存储体系金字塔结构

现代计算机采用**多级分层存储架构**，其核心设计目标是：在合理成本范围内，构建**容量足够大、存取速度足够快、每位价格足够低**的理想存储系统。

```
                   ▲ 存取速度由快到慢
                   │ 每位成本由高到低
                   │
         ┌───────────────────┐  ──► 纳秒级 (0.5~1ns) · 几十字节到几KB
         │   CPU 内部寄存器   │
        ┌┴───────────────────┴┐ ──► 纳秒级 (1~10ns)  · 几MB到几十MB (SRAM)
        │   高速缓存 (Cache)   │ 
       ┌┴─────────────────────┴┐ ──► 十纳秒级 (50~100ns) · 8GB~64GB (DRAM)
       │    主存储器 (RAM/ROM)  │ 
      ┌┴───────────────────────┴┐ ──► 毫秒/微秒级 · 512GB~4TB (SSD/NVMe/HDD)
      │      辅助存储器 (硬盘)    │ 
     ┌┴─────────────────────────┴┐ ──► 秒级/分钟级 · PB级 (磁带库/光盘阵列)
     │     海量脱机后备存储器     │ 
     └───────────────────────────┘
                   │
                   ▼ 存储容量由小到大
```

#### 💡 层次化存储解决的两大核心矛盾

| 存储层级 | 组成结构 | 核心解决矛盾 | 软考重点考查机制 |
| :--- | :--- | :--- | :--- |
| **“Cache — 主存” 层次** | 高速缓存 + 物理内存 | 解决 **CPU 超高运算速度与主存较慢存取速度不匹配** 的瓶颈。 | **纯硬件自动实现**（对所有程序员透明）。 |
| **“主存 — 外存” 层次** | 物理内存 + 磁盘虚拟内存 | 解决 **主存容量严重不足与高成本** 之间的矛盾。 | **软硬件协同实现**（虚存对应用程序员透明，由 OS 管理）。 |

---

### 1.7.2 常见半导体存储器分类全景表

```
半导体存储器
 ├── RAM (随机存取存储器 · 易失性/断电丢数据)
 │    ├── SRAM (静态RAM): 触发器存储, 快/贵/无需刷新, 做 Cache
 │    └── DRAM (动态RAM): 电容电荷存储, 慢/便宜/需周期性刷新, 做主存(内存)
 └── ROM (只读存储器 · 非易失性/断电不丢数据)
      ├── MROM (掩膜只读): 厂家出厂写入, 无法修改
      ├── PROM (可编程只读): 用户只能写入一次
      ├── EPROM (紫外线擦除): 紫外线照射全擦除
      ├── EEPROM (电可擦除): 电信号逐字节/块擦除
      └── FLASH (闪存): 电可擦除、寿命长、块擦写, 广泛用于U盘/SSD/手机存储
```

#### 💡 存储器类别对比矩阵表

| 类别 | 细分类型 | 存储介质 / 原理 | 读写特性 | 易失性 | 典型应用 |
| :--- | :--- | :--- | :--- | :---: | :--- |
| **RAM** | **SRAM**（静态） | 双稳态触发器电路 | 可高速随机读写，**无需刷新** | **易失（断电丢失）** | **CPU 内部 Cache 高速缓存** |
|  | **DRAM**（动态） | MOS 管电容充放电 | 随机读写，**必须周期性动态刷新** | **易失（断电丢失）** | **计算机主内存（RAM条）** |
| **ROM** | **ROM / PROM** | 熔丝/抗熔丝结 | 只读（PROM 允许用户烧录 1 次） | **非易失（断电保留）** | 早期主板 BIOS、字符发生器 |
|  | **EPROM** | 浮栅雪崩注入 | 紫外线整片擦除后电写入 | **非易失** | 旧式设备固件 |
|  | **EEPROM** | 浮栅隧道氧化层 | **电信号擦除与写入**（可按字节改写） | **非易失** | 嵌入式配置参数、路由器 NVRAM |
| **Flash** | **闪存芯片** | 浮栅晶体管（NAND / NOR） | 电擦除，**按“块”擦除、按“页”读写** | **非易失** | **固态硬盘（SSD）、U盘、手机存储** |

### 1.7.3 局部性原理（Locality Principle · Cache 与虚存的理论基石）

计算机在执行程序时，对存储器的访问呈现出高度的**非均匀性与局部聚集特征**：

#### 1. 时间局部性（Temporal Locality）
- **核心定义**：如果程序中的某条指令或某个数据一旦被访问，则在**不久的将来它很可能再次被访问**。
- **产生原因**：程序中大量存在**循环结构、重复调用的子函数、计数器变量**。
- **典型考题例证**：
  - `for(int i = 0; i < 1000; i++)` 中的变量 `i` 和循环体指令，呈现强烈的**时间局部性**。

#### 2. 空间局部性（Spatial Locality）
- **核心定义**：如果程序访问了某个存储单元，则在**不久的将来，与其物理地址相邻的邻近单元也很可能被访问**。
- **产生原因**：程序指令多为**顺序执行**；数据多以**一维/多维数组、结构体、表格、栈等连续空间**方式组织。
- **典型考题例证**：
  - 数组元素 `a[0]`, `a[1]`, `a[2]`, ... 的连续遍历，呈现强烈的**空间局部性**。
  - **行优先存储**的二维数组按行遍历（空间局部性好） vs 按列跨步长遍历（空间局部性差、Cache 命中率低）。

#### 3. 工作集理论（Working Set）
- 进程在某段时间内频繁访问的页面/数据集合称为工作集。保持主存分配页面大于工作集大小可彻底避免系统“抖动”（Thrashing）。

### 1.7.4 Cache 基本工作原理与性能指标计算（必考算式）

Cache 位于 CPU 与主存之间，存放主存中最活跃的部分副本。CPU 访存时首先查询 Cache：

```
CPU 发出访存物理地址
         │
         ├───► Cache 命中 (Hit) ────► 直接从 Cache 高速读出数据 (耗时 tc)
         │
         └───► Cache 未命中 (Miss) ──► 访问主存读取数据 (耗时 tm)，并同步将该数据块调入 Cache
```

#### 1. Cache 命中率（Hit Rate, $h$）
设在某段时间内，CPU 访问 Cache 命中次数为 $N_c$，访问主存未命中次数为 $N_m$：
$$\mathbf{h = \frac{N_c}{N_c + N_m}} \quad (0 \le h \le 1)$$
- **失效率（Miss Rate）**：$r = 1 - h$。

#### 2. 平均访问时间（$t_a$ / AMAT · 必背公式）
设 Cache 命中率为 $h$，未命中率（失效率）为 $(1 - h)$；命中时间（Cache 存取周期）为 $t_c$；未命中代价（未命中时访问主存所需时间）为 $t_m$：

$$\mathbf{\text{平均访问时间} = \text{命中率} \times \text{命中时间} + \text{未命中率} \times \text{未命中代价} = h \times t_c + (1 - h) \times t_m}$$

- **命中时间（Hit Time）**：$t_c$（在 Cache 中命中并直接读写数据的时间）
- **未命中率（Miss Rate）**：$1 - h$（访问未命中 Cache 的概率）
- **未命中代价（Miss Penalty）**：$t_m$（发生未命中时，从主存中查找、读取并调入 Cache 所需的全部时间）

> 💡 **真题实战计算示例**：  
> 某计算机 Cache 存取时间（命中时间）为 $5\text{ns}$，主存存取时间（未命中代价）为 $50\text{ns}$，若 Cache 命中率为 $95\%$（未命中率为 $5\%$）：
> $$\text{平均访问时间 } t_a = 95\% \times 5\text{ns} + (1 - 95\%) \times 50\text{ns} = 0.95 \times 5 + 0.05 \times 50 = 4.75 + 2.5 = \mathbf{7.25\text{ ns}}$$

#### 3. 访问效率（Efficiency, $e$）
Cache-主存系统的访问效率定义为 Cache 访问时间与平均访问时间之比：
$$\mathbf{e = \frac{t_c}{t_a} = \frac{t_c}{h \times t_c + (1 - h) \times t_m}} \quad (0 < e \le 1)$$

- 💡 **访问效率计算示例**：  
  延续上述例题（命中时间 $t_c = 5\text{ns}$，平均访问时间 $t_a = 7.25\text{ns}$）：
  $$e = \frac{t_c}{t_a} = \frac{5\text{ ns}}{7.25\text{ ns}} \approx \mathbf{68.97\%}$$

### 1.7.5 Cache 的三种地址映射方式（⭐ 软考上午必考对比）

主存与 Cache 之间按**固定大小的“块（Block / Line）”**为单位交换数据。主存地址映射到 Cache 的方式有三种：

| 映射方式                             | 映射规则                                                                                                                                          |          硬件复杂度 / 成本          |        块冲突率        |   灵活性 / Cache 利用率   |
| :------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------: | :----------------: | :-----------------: |
| **直接映射<br>(Direct)**             | 主存中的每一块**只能映射到 Cache 中唯一固定的行**。<br>$$\text{Cache 行号} = \text{主存块号} \pmod{\text{Cache 总行数}}$$                                                  |  **最简单、成本最低**<br>(地址变换速度最快)  | **最高**<br>(极易发生抖动) | **最差**<br>(空闲行不能利用) |
| **全相联映射<br>(Fully Associative)** | 主存中的任意一块**可以映射到 Cache 中的任意一行**。                                                                                                               | **最高、最复杂**<br>(需昂贵的大容量相联比较器) |       **最低**       |       **最高**        |
| **组相联映射<br>(Set Associative)**   | **前两者的折中折衷方案**（现代 CPU 主流）：<br>Cache 分成若干组，**组间采用直接映射，组内采用全相联映射**（如 2路/4路/8路组相联）。<br>$$\text{Cache 组号} = \text{主存块号} \pmod{\text{Cache 总组数}}$$ |            **适中**            |       **适中**       |       **适中**        |

> 💡 **Cache 映射计算实战示例**：  
> 1. **直接映射计算例题**：  
>    某 Cache 共有 8 个 Cache 行（行号 0～7）。主存中的第 19 块在 Cache 中应映射到哪一行？  
>    $$\text{Cache 行号} = 19 \pmod 8 = \mathbf{3} \implies \text{必须装入 Cache 第 3 行}$$
> 2. **组相联映射计算例题**：  
>    某 Cache 共有 16 行，采用 4 路组相联映射（即每组包含 4 行，共有 $16 \div 4 = 4$ 个组，组号 0～3）。主存第 25 块应映射到 Cache 的哪一组？  
>    $$\text{Cache 组号} = 25 \pmod 4 = \mathbf{1} \implies \text{可装入 Cache 第 1 组内的任意一行（共 4 行可选）}$$

### 1.7.6 Cache 替换算法与写策略

#### 1. Cache 块替换淘汰算法（当 Cache 已满时）
- **RAND（随机算法）**：随机选取一行淘汰，实现简单但未利用局部性原理，命中率低。
- **FIFO（先进先出算法）**：先调入的先淘汰，容易把频繁使用的全局变量换出（贝拉迪异常）。
- **LRU（近期最少使用算法 · 最优常用）**：根据时间局部性，淘汰**最长时间未被访问过的行**，命中率最高。
- **LFU（最不经常使用算法）**：淘汰一段时间内**访问频次计数最低的行**。

#### 2. Cache 更新写策略（保持 Cache 与主存数据一致性）
- **全写法 / 直写式（Write-Through）**：
  - 写命中时：**同时写入 Cache 和主存**。
  - 优点：主存数据始终是最新的，简单可靠；缺点：写操作耗时长，频繁占用总线。
- **写回法 / 回写式（Write-Back）**：
  - 写命中时：**只写入 Cache，并标记该行被修改过（脏位 Dirty Bit = 1）**；仅当该行被替换淘汰出 Cache 时，才一次性写回主存。
  - 优点：大幅减少主存写操作，速度快；缺点：存在数据不一致窗口，需硬件标记控制。

### 1.7.7 存储体系考点秒杀速记口诀

1. **两级层次分工明**：
   - Cache-主存靠**硬件**，解决 CPU 速度差；
   - 主存-外存靠**软硬**，解决容量大问题。
2. **易失判断看类型**：RAM 掉电全丢失（SRAM做Cache，DRAM需刷新做内存），ROM/Flash 断电永保留。
3. **局部性判断秒选**：循环计数选**时间**，数组顺序选**空间**。
4. **Cache 映射三字经**：
   - 直接映射：**固定占位冲突高，硬件便宜最快跑**；
   - 全相联映射：**任意安放冲突少，相联比较代价高**；
   - 组相联映射：**组间直接组内全，兼顾成本与效能**。
5. **平均访问时间公式**：$\text{平均访问时间} = \text{命中率} \times \text{命中时间} + \text{未命中率} \times \text{未命中代价} = h \cdot t_c + (1-h) \cdot t_m$。

### 1.8.1 I/O 接口与端口编址方式（⭐ 高频概念对比）

I/O 接口（控制器）内部包含**数据寄存器（数据端口）**、**状态寄存器（状态端口）**和**控制寄存器（控制端口）**。CPU 与 I/O 接口通信时，必须对这些端口进行编址：

| 编址方式 | 编址机制与实现原理 | CPU 指令系统支持 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- | :--- |
| **统一编址<br>（内存映射 I/O / Memory-Mapped I/O）** ⭐ | **将 I/O 端口地址与主存物理地址统一合并编址**，把 I/O 端口当作主存单元来看待，占用部分主存地址空间。 | **无需专用 I/O 指令**。<br>直接使用常规的内存访问指令（如 `MOV`, `LOAD`, `STORE`）即可访问外设。 | 1. 访问内存的全部指令和寻址方式均可用于 I/O；<br>2. 硬件译码电路简洁通用。 | I/O 端口占用了宝贵的主存物理地址空间，使得可用主存容量减少。 |
| **独立编址<br>（专门 I/O 编址 / Isolated I/O）** ⭐ | **I/O 端口地址空间与主存地址空间相互独立、完全分开**。<br>I/O 端口拥有独立的地址编码体系。 | **必须设置专用的 I/O 指令**（如 x86 架构中的 `IN` / `OUT` 指令），不能使用普通访存指令。 | 1. I/O 端口不占用主存地址空间；<br>2. 指令语义明确，易于区分内存访问与外设控制。 | 1. 专用 I/O 指令功能单调、寻址方式少；<br>2. 需要额外的总线控制线（如 $M/\overline{IO}$ 信号线）来区分访存还是访 I/O。 |

### 1.8.2 四大 I/O 数据传输控制方式深度剖析

计算机系统中，CPU 控制 I/O 设备与主存之间进行数据交换的方式经历了四个发展阶段，其核心演进目标是：**不断降低 CPU 的干预程度，提升 CPU 与外设的并行工作效率**。

```
I/O 控制方式演进（CPU 负担由重到轻 · 并行度由低到高）：
【程序查询方式】 ──► 【程序中断方式】 ──► 【DMA 直接内存存取】 ──► 【通道/I/O处理机】
  (CPU全程轮询)       (外设就绪发中断)        (硬件接管成块直传)        (专用处理器全权调度)
```

---

#### 1. 程序查询方式（Programmed I/O / 轮询 Polling）

- **工作机制**：
  1. CPU 向 I/O 接口发出读/写命令；
  2. CPU **通过程序循环不断读取并检查 I/O 状态寄存器的状态标志**（即“踏步等待”）；
  3. 直到 I/O 设备准备就绪，CPU 才逐字/逐字节从 I/O 接口读取数据存入主存（或反向写入）。
- **数据通路**：$\text{I/O 设备} \longleftrightarrow \text{I/O 接口} \longleftrightarrow \mathbf{CPU 寄存器} \longleftrightarrow \text{主存}$
- **核心缺点**：
  - **CPU 与 I/O 设备完全处于串行工作状态**，CPU 绝大部分时钟周期都在空耗轮询，**CPU 资源利用率极低**；
  - 无法发现和处理突发的紧急故障。
- **适用场景**：早期的简易计算机系统，或结构极其简单的单片机/嵌入式轮询任务。

---

#### 2. 程序中断方式（Interrupt-Driven I/O）

- **工作机制**：
  - 当 CPU 启动 I/O 设备后，**不再主动查询其状态，而是立即返回继续执行自身的主程序**；
  - I/O 设备在自身硬件准备就绪（或接收完数据）后，**主动向 CPU 发出中断请求信号（INTR）**；
  - CPU 在**当前指令执行周期的末尾（指令结束点）**检测并响应中断请求；
  - CPU 暂停当前正在执行的程序，转去执行**中断服务程序（ISR）**完成 1 个字/字节的数据传输，处理完毕后返回原被打断的程序继续执行。

```
CPU 活动:   [ 执行主程序 ...... ] ──► [ 响应中断: 关中断/保断点/进服务 ] ──► [ 执行中断服务程序 (ISR) ] ──► [ 恢复现场/开中断/返回 ] ──► [ 继续执行主程序 ]
                                               ▲                                                            │
I/O 活动:   [ 启动设备 -> 准备数据 ] ──────────┴── 发送中断请求 (INTR)                                       └── 恢复等待下一次
```

- **中断处理完整生命周期（8 大经典步骤）**：
  1. **中断请求（Interrupt Request）**：外设硬件发出中断信号；
  2. **中断判优与响应**：硬件排队器根据中断优先级仲裁响应，**在指令周期结束点响应**；
  3. **关中断（Disable Interrupt）**：硬件自动将中断允许触发器置 0，屏蔽同级或低级中断；
  4. **保存断点（Save PC & PSW）**：将当前程序计数器 $PC$ 和程序状态字 $PSW$ 压入系统堆栈；
  5. **引出中断服务程序（寻找中断向量）**：通过**硬件向量法**或软件查询法获取中断服务程序入口地址，送入 $PC$；
  6. **保护现场（Save Context）**：在中断服务程序开头，将需要用到的通用寄存器压栈保存；
  7. **执行中断服务程序（I/O 读写）**：进行实际的 I/O 数据传输与设备状态更新；
  8. **恢复现场、开中断并中断返回（Restore Context & IRET）**：出栈恢复寄存器值，开中断，执行 `IRET` 指令将断点弹回 $PC$，恢复主程序执行。

##### ⭐ 软考高频易混概念极速辨析（必考 1 题）

| 核心术语 | 英文对照 | 核心定义与考查本质 | 存储位置 |
| :--- | :--- | :--- | :--- |
| **中断向量<br>（Interrupt Vector）** ⭐ | Interrupt Vector | **中断服务程序的入口地址**（即中断发生后 $PC$ 应该跳转的目标内存物理地址）。 | 存放在中断向量表中 |
| **中断向量表<br>（Vector Table）** ⭐ | Vector Table | **存放所有中断源的中断向量（入口地址）的一维数组/映射表**。 | 存放在**主存储器的特定低端地址区域**（如 0 号物理页） |
| **向量地址<br>（Vector Address）** ⭐ | Vector Address | **中断向量在中断向量表中的存储单元地址**（即“中断入口地址的存放地址”）。由硬件中断响应电路（编码器）生成。 | 硬件中断产生电路 / 寄存器 |

> 📌 **一句话区分秒杀法**：
> - **中断服务程序入口地址** $\longrightarrow$ 就是 **中断向量**；
> - **中断向量自身的存放地址** $\longrightarrow$ 就是 **向量地址**；
> - **把所有中断向量集中排成一个表格** $\longrightarrow$ 就是 **中断向量表**。

- **适用场景**：键盘、鼠标、串口等**中低速外设**，或实时突发事件报警处理。

#### 3. 直接内存存取方式（DMA · Direct Memory Access ⭐ 必考）

- **核心概念与设计思想**：
  - 在**主存与高速 I/O 设备之间建立一条直接的数据硬件通路**；
  - 由专用的硬件芯片 **DMA 控制器（DMAC）** 接管总线控制权，直接控制数据以**数据块（Block）**为单位在主存与外设间高速流动，**传输过程中完全无需 CPU 的干预（CPU 不负责逐字中转）**。

```
传统中断方式数据流:   [ I/O 设备 ] <=====> [ CPU 内部累加器 AC/DR ] <=====> [ 物理主存 ]  (CPU 沦为数据搬运工，极耗时)
DMA 方式直接数据流:   [ I/O 设备 ] <========================================> [ 物理主存 ]  (通过专用 DMA 通路直接对拷)
                                           ▲ (DMAC 全程硬件控制)
```

- **CPU 在 DMA 过程中的介入时机（必背考点）**：
  - **传输开始前**：CPU 仅需执行几条指令对 DMAC 进行**初始化配置**（写入主存起始地址、传送字节数、传送方向等）；
  - **传输过程中**：CPU **完全脱离，无需干预**，继续并行执行其他与当前总线无关的计算程序；
  - **传输结束后**：DMAC 发出一个**中断请求**通知 CPU“整块数据已经传输完毕，请做后处理与校验”。
  - 👉 **结论**：**DMA 方式在传输开始前和结束后各需 CPU 介入一次，传输期间由 DMAC 独立完成**。

- **DMA 响应时机与传送方式**：
  - **响应时机**：DMA 请求在**总线存取周期结束时**即可响应（无需等待整条机器指令执行完毕，这一点与中断方式有本质区别！）。
  - **三种传送总线控制方式**：
    1. **停止 CPU 访存（独占总线）**：DMA 传送时，CPU 放弃总线控制权并暂停访存，直到整个数据块传送完毕；
    2. **周期挪用 / 周期窃取（Cycle Stealing · 最常用）**：当 I/O 发出 DMA 请求时，DMAC **挪用/窃取 1 个总线存取周期**访问主存传送 1 个字，传送完立即归还总线。此时 CPU 仅暂停 1 个周期的访存或在内部寄存器继续运算；
    3. **交替访存（分时复用）**：将一个 CPU 周期一分为二，前半周期供 CPU 访存，后半周期供 DMA 访存，CPU 与 DMA 互不冲突。

- **适用场景**：固态硬盘（SSD）、机械硬盘、网卡、高速视频采集卡等**高速、大批量成块数据传输设备**。

##### ⭐ 软考经典对比：程序中断方式 vs DMA 方式（上午必考）

| 对比维度 | 程序中断方式 (Interrupt) | DMA 方式 (Direct Memory Access) ⭐ |
| :--- | :--- | :--- |
| **数据传送单位** | **字（Word）或字节（Byte）** | **数据块（Block / 连续数据流）** |
| **数据传输通路** | 外设 $\to$ **CPU** $\to$ 主存（CPU 逐字中转） | 外设 $\longleftrightarrow$ 主存（**硬件直连，不经 CPU**） |
| **硬件控制核心** | 中断控制器 + **CPU 软件指令执行** | 专用硬件 **DMA 控制器（DMAC）** |
| **CPU 响应时机** | **一条机器指令执行结束时（指令周期末尾）** | **一个总线存取周期结束时（总线周期末尾）** |
| **CPU 干预程度** | 频繁介入（每个字/字节传输都要执行中断程序） | 极少介入（仅在数据块**传输开始前与结束后**介入） |
| **典型应用场景** | 键盘、鼠标、中低速外设、异常处理 | 硬盘读写、千兆网卡、显卡数据对拷等高速外设 |

#### 4. 通道控制方式（Channel Control）与 I/O 处理机（IOP）

- **通道基本概念**：
  - **通道（Channel）** 是一种专门负责管理和控制 I/O 操作的**专用硬件微处理器**（具有专用的通道指令集，由操作系统编写**通道程序**）。
  - 能够独立执行通道程序，控制多台不同类型的外设与主存之间进行复杂的数据交换。
  - **实现“三级并行”**：CPU 与通道并行工作；通道与通道之间并行工作；各通道所挂接的多台外设之间并行工作。
- **I/O 处理机（IOP）**：
  - 通道的进一步演化升级，拥有完全独立的 CPU 指令集和内存，不仅能控制数据传输，还能独立完成数据格式转换、码制转换、校验码计算和外设错误恢复，彻底解放宿主主机 CPU。
- **适用场景**：大型机（Mainframe）、大型企业级数据中心服务器。

### 1.8.3 四大 I/O 传输方式横向全景对比表

| I/O 控制方式 | 数据传送单位 | 数据传输通路 | 硬件代价 | CPU 与外设并行度 | 适用设备类型 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **程序查询方式** | 字 / 字节 | 设备 $\to$ **CPU** $\to$ 主存 | 极低（纯软件轮询） | **完全串行**（CPU 踏步等待） | 早期微机、简单低速外设 |
| **程序中断方式** | 字 / 字节 | 设备 $\to$ **CPU** $\to$ 主存 | 较低（需中断控制器） | **部分并行**（就绪后打断 CPU） | 键盘、鼠标、打印机等中低速设备 |

### 1.8.4 I/O 考点经典计算与分析例题

> 💡 **例题 1（DMA 与中断响应时机对比）**：  
> 在计算机系统中，CPU 响应外部中断请求和响应 DMA 请求的时机分别是什么？  
> - **解析**：
>   - **中断请求响应时机**：CPU 必须在**当前执行的机器指令周期结束时**响应（保证当前指令逻辑完整执行）；
>   - **DMA 请求响应时机**：CPU 在**当前总线存取周期结束时**即可响应（只需让出总线，无需等整条指令跑完）。

> 💡 **例题 2（DMA 传送效率计算）**：  
> 某磁盘接口采用 DMA 方式向主存传输数据，磁盘数据传输率为 $4\text{MB/s}$，每次传输 1 个字（32 位 / 4 Byte），系统总线时钟周期为 $50\text{ns}$，主存存取周期为 $200\text{ns}$。若采用周期挪用方式传输，则 DMA 传送时占用主存周期的比例是多少？  
> - **解析**：
>   1. 传输 1 个字所需的时间间隔 $= \frac{4\text{ Byte}}{4\text{ MB/s}} = \frac{4\text{ B}}{4 \times 10^6\text{ B/s}} = 1\mu\text{s} = 1000\text{ns}$；
>   2. 每次传输 1 个字需挪用 1 个主存存取周期（耗时 $200\text{ns}$）；
>   3. 占用主存周期的比例 $= \frac{200\text{ns}}{1000\text{ns}} = \mathbf{20\%}$。

> 💡 **考场关键特性速记**：
> - **逻辑异或（$\oplus$）**：**不进位的二进制加法**！
>   - 自反性：$A \oplus A = 0$；$A \oplus 0 = A$；$A \oplus 1 = \overline{A}$；
>   - 交换律与结合律：$A \oplus B = B \oplus A$，$(A \oplus B) \oplus C = A \oplus (B \oplus C)$。
> - **逻辑同或（$\odot$）**：与异或严格互补，$\mathbf{A \odot B = \overline{A \oplus B}}$。

### 1.9.3 布尔代数核心公式与化简定律全矩阵（必背）

| 定律名称 | 逻辑与（AND）形式 | 逻辑或（OR）形式 | 软考实战应用价值 |
| :--- | :--- | :--- | :--- |
| **同一律 / 0-1 律** | $A \cdot 1 = A, \quad A \cdot 0 = 0$ | $A + 0 = A, \quad A + 1 = 1$ | 快速消去常量项 |
| **重叠律（幂等律）** | $A \cdot A = A$ | $A + A = A$ | 合并重复变量 |
| **互补律** | $A \cdot \overline{A} = 0$ | $A + \overline{A} = 1$ | 经典化简消除依据 |
| **交换律** | $A \cdot B = B \cdot A$ | $A + B = B + A$ | 调整运算次序 |
| **结合律** | $(A \cdot B) \cdot C = A \cdot (B \cdot C)$ | $(A + B) + C = A + (B + C)$ | 自由加减括号 |
| **分配律** ⭐ | $A + (B \cdot C) = (A + B) \cdot (A + C)$ | $A \cdot (B + C) = (A \cdot B) + (A \cdot C)$ | **$A + BC = (A+B)(A+C)$ 极高频！** |
| **反演律（德·摩根定律）** ⭐ | $\mathbf{\overline{A \cdot B} = \overline{A} + \overline{B}}$ | $\mathbf{\overline{A + B} = \overline{A} \cdot \overline{B}}$ | **求反拆号、与变或、或变与** |
| **吸收律** ⭐ | $A \cdot (A + B) = A$ | $A + (A \cdot B) = A$ | **大项直接被小项吸收** |
| **扩展吸收律** ⭐ | $A + \overline{A}B = A + B$ | $\overline{A} + AB = \overline{A} + B$ | **消去冗余反变量** |

### 1.9.4 逻辑运算中的“短路求值”问题（Short-Circuit Evaluation · 必考编程与概念）

在高级编程语言（如 C/C++、Java、Python、JavaScript）及软考上午程序设计基础题中，**逻辑与（`&&`）** 与 **逻辑或（`||`）** 遵循**短路求值原则**：

```
短路求值法则：
1. 表达式 (A && B)：若 A 为 0 (假)，则整体必然为 0 (假)，系统将【不再计算表达式 B】！
2. 表达式 (A || B)：若 A 为 1 (真)，则整体必然为 1 (真)，系统将【不再计算表达式 B】！
```

#### 💡 短路求值经典代码计算例题

> 📝 **真题分析示例**：  
> 给定 C 语言代码片段：
> ```c
> int a = 1, b = 2, c = 3;
> int result = (a > 2) && (++b < 5);
> ```
> 问：执行后变量 `a`, `b`, `c` 和 `result` 的值分别是多少？
> 
> - **分步深度解析**：
>   1. 计算左操作数 `(a > 2)`：由于 `a = 1`，故 `1 > 2` 为 **假（`0`）**；
>   2. 触发 **逻辑与（`&&`）短路机制**：因为左边已经为假，整个逻辑与表达式的结果必然为 `0`；
>   3. **右操作数 `(++b < 5)` 被完全跳过（不执行运算！）**，因此 `++b` 不会发生；
>   4. 最终结果：`a = 1`，`b = 2`（未自增！），`c = 3`，`result = 0`。

### 1.9.5 逻辑表达式经典真题化简例题

> 📝 **化简典型例题**：  
> 化简逻辑函数表达式：$F = A \cdot B + A \cdot \overline{B} + \overline{A} \cdot C + B \cdot C$
> 
> - **标准代数化简步骤**：
>   1. **提取公因子与互补律**：前两项提取 $A$：
>      $$A \cdot B + A \cdot \overline{B} = A(B + \overline{B}) = A \cdot 1 = A$$
>   2. **代入原式**：
>      $$F = A + \overline{A} \cdot C + B \cdot C$$
>   3. **运用扩展吸收律（$A + \overline{A}C = A + C$）**：
>      $$F = (A + C) + B \cdot C = A + (C + B \cdot C)$$
>   4. **运用基本吸收律（$C + BC = C$）**：
>      $$F = A + C$$
> - **最终化简结果**：$\mathbf{F = A + C}$。
