### 数据库中char和varchar
-`CHAR` 和 `VARCHAR` 都是 MySQL 中用于存储字符数据的类型，但它们在存储方式和使用场景上有一些显著的区别：

#### 1. **存储方式**

- **`CHAR`**：
    
    - **定长**：`CHAR` 类型的列总是分配固定的空间，不管实际存储的数据长度是多少。
        
    - 如果插入的数据长度小于指定长度，MySQL 会自动用空格填充，直到达到指定的长度。
        
    - 例如，`CHAR(10)` 字段存储字符串 `"Hello"`，会存储为 `"Hello "`（总共10个字符，其中后面的空格是自动填充的）。
        
- **`VARCHAR`**：
    
    - **变长**：`VARCHAR` 类型的列根据实际存储的数据长度分配空间，不会自动填充空格。
        
    - 例如，`VARCHAR(10)` 字段存储字符串 `"Hello"`，只会存储 `"Hello"`，并不会有额外的空格。
        
    - `VARCHAR` 类型的列需要额外存储一个字节来记录字符串的实际长度（最大为 65535）。
        

#### 2. **存储空间**

- **`CHAR`**：
    
    - 总是占用固定的空间，指定长度的字符数。即使插入的内容小于定义的长度，仍然会占用相同的空间。
        
    - 适合存储长度固定的字符串，如国家代码（2个字符），邮政编码（固定长度的字符串），等。
        
- **`VARCHAR`**：
    
    - 存储空间与实际内容的长度成正比。例如，`VARCHAR(100)` 类型列存储 `"Hello"` 会占用5个字符的空间。
        
    - 适合存储长度不固定的字符串，如姓名、地址等。
        

#### 3. **性能差异**

- **`CHAR`**：
    
    - 对于较短且长度固定的数据，使用 `CHAR` 类型会稍微更高效，因为它不需要记录实际字符串的长度，且存取速度可能稍快（因为长度固定）。
        
- **`VARCHAR`**：
    
    - 对于变长数据，`VARCHAR` 类型更加节省空间，但在读取时需要读取额外的字节来确定实际长度，存取速度略慢。
        

#### 4. **使用场景**

- **`CHAR`**：
    
    - 适合存储长度固定的字符串。例如：国家代码（如`US`、`CN`）、性别（`M`、`F`）、电话号码区号等。
        
- **`VARCHAR`**：
    
    - 适合存储长度不固定的字符串。例如：用户姓名、电子邮件地址、地址等。
        

#### 5. **兼容性与限制**

- **`CHAR`**：
    
    - 不能直接存储超出最大长度的字符串，会进行截断。
        
    - 适合存储简单、较小且长度固定的字符串。
        
- **`VARCHAR`**：
    
    - 最大长度是 65535 个字符，受限于行的总字节数。如果数据库表的行太大，`VARCHAR` 可能会受到限制。
        
    - 支持变长存储，节省空间，但在存储过程中会有额外的开销。
        

#### 6. **总结对比**

|特性|`CHAR`|`VARCHAR`|
|---|---|---|
|存储方式|定长|变长|
|空间占用|固定长度，填充空格|按实际数据长度存储|
|性能|对于固定长度数据稍快|对于变长数据稍慢|
|使用场景|长度固定的字符串|长度不固定的字符串|
|最大长度|255字符|65535字符（受行的限制）|

#### 选择建议：

- 如果数据长度是固定的，使用 `CHAR` 比较合适。
    
- 如果数据长度不固定，使用 `VARCHAR` 可以节省存储空间。

## 索引和主键
在 MySQL 中，**主键（Primary Key）**和**索引（Index）**都是用于提高查询效率的重要机制，但它们在功能和约束方面有一些区别。

### 1. 主键（Primary Key）

**主键**是用来唯一标识表中每一行数据的字段。每个表只能有一个主键，并且该主键的值必须唯一，且不能为 `NULL`。主键通常用于查询、插入、更新等操作时进行数据定位。

#### 特性：

- **唯一性**：主键值必须唯一，不能重复。
    
- **非空**：主键字段不能为 `NULL`。
    
- **自动创建索引**：当你为某个字段定义主键时，MySQL 会自动为该字段创建一个唯一的索引（唯一索引也叫主键索引），以提高查询性能。
    
- **只能有一个**：每个表只能有一个主键。
    

#### 示例：

```sql
CREATE TABLE users (
    id INT NOT NULL,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100),
    PRIMARY KEY (id)
);
```

在这个例子中，`id` 是主键，MySQL 自动为 `id` 创建一个索引以保证其唯一性。

### 2. 索引（Index）

**索引**是为了提高查询速度而创建的数据结构。通过索引，数据库可以更快速地查找、排序和过滤数据。索引可以应用于一个或多个字段。

#### 特性：

- **提高查询效率**：通过索引可以大大提高对表的查询速度，尤其是大数据量的情况下。
    
- **允许重复值**：与主键不同，普通索引允许字段值重复。
    
- **可以是单列或多列**：可以对单个字段或多个字段（复合索引）创建索引。
    
- **可以有多个**：一个表可以有多个索引，但每个表只能有一个主键索引。
    

#### 索引类型：

- **普通索引（INDEX）**：这是最常见的索引类型，适用于任何可以加速查询的列。
    
- **唯一索引（UNIQUE）**：与普通索引类似，但它要求索引列的值必须唯一。它不同于主键的地方在于，唯一索引允许有 `NULL` 值。
    
- **全文索引（FULLTEXT）**：用于对文本数据进行全文搜索。
    
- **联合索引（Composite Index）**：包含多个列的索引，用于加速多列的查询。
    

#### 示例：

```sql
CREATE TABLE users (
    id INT NOT NULL,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100),
    INDEX idx_username (username)
);
```

在这个例子中，我们为 `username` 字段创建了一个索引 `idx_username`，这会加速通过 `username` 字段的查询。

### 3. 主键与索引的区别

|特性|主键（Primary Key）|索引（Index）|
|---|---|---|
|唯一性|必须唯一|普通索引允许重复值，唯一索引要求唯一但允许 NULL|
|NULL 值|不允许为 `NULL`|普通索引可以包含 `NULL`，唯一索引也允许单个 `NULL`|
|数量限制|每个表只能有一个主键|每个表可以有多个索引|
|自动创建|自动创建唯一索引|需要手动创建索引|
|用途|唯一标识一条记录|提高查询效率，尤其是针对 `SELECT` 查询|

### 4. 如何创建索引和主键

- **创建主键**：
    
    ```sql
    CREATE TABLE users (
        id INT NOT NULL,
        username VARCHAR(50) NOT NULL,
        PRIMARY KEY (id)
    );
    ```
    
- **创建索引**：
    
    ```sql
    CREATE INDEX idx_email ON users (email);
    ```
    
- **创建唯一索引**：
    
    ```sql
    CREATE UNIQUE INDEX idx_username ON users (username);
    ```
    
- **创建复合索引**：
    
    ```sql
    CREATE INDEX idx_name_email ON users (first_name, last_name);
    ```
    

### 5. 注意事项

- **索引的开销**：虽然索引提高了查询效率，但也会带来额外的开销，特别是在进行插入、更新和删除操作时，因为这些操作需要更新索引。
    
- **选择性**：对于高选择性的列（即列的值大部分不重复），创建索引更有效。低选择性（值重复度高）的列通常不适合建立索引。
    
- **主键和外键**：主键常用于外键约束的参考字段，确保外键关系的完整性。
    

### 总结

- **主键**用于唯一标识每一行数据，并且会自动创建索引。
    
- **索引**用于加速查询，允许重复值，可以对单个或多个字段创建。
    
## 自增
在 MySQL 中，**自增（AUTO_INCREMENT）** 是一个非常常见的特性，通常用于自动生成唯一的数字值，常见于主键字段。自增值会在每次插入新记录时自动递增，通常用于确保每一条记录都有一个唯一的标识符。

### 1. **使用 AUTO_INCREMENT 创建自增字段**

当你在创建表时定义一个字段为自增字段时，可以使用 `AUTO_INCREMENT` 关键字。通常，`AUTO_INCREMENT` 会与主键（Primary Key）一起使用。

#### 语法：

```sql
CREATE TABLE 表名 (
    字段1 数据类型 AUTO_INCREMENT,
    字段2 数据类型,
    PRIMARY KEY (字段1)
);
```

#### 示例：

```sql
CREATE TABLE users (
    id INT NOT NULL AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100),
    PRIMARY KEY (id)
);
```

在这个例子中，`id` 字段会自动递增，每次插入新记录时，`id` 字段的值会自动增加。

### 2. **插入数据时自动生成自增值**

你在插入数据时，不需要显式地为自增字段赋值。MySQL 会自动为自增字段分配一个唯一的值。

#### 示例：

```sql
INSERT INTO users (username, email) 
VALUES ('Alice', 'alice@example.com');
```

在这个例子中，`id` 字段会自动生成并递增。

### 3. **自增字段的初始值与步长**

- **初始值**：自增字段默认从 `1` 开始递增，但你可以通过设置自增的起始值来改变它。
    
- **步长**：默认情况下，每次递增的步长为 `1`，但你也可以通过修改步长来改变它。
    

#### 3.1 设置初始值

你可以在创建表时使用 `AUTO_INCREMENT` 关键字后面的 `AUTO_INCREMENT = 初始值` 来设置自增字段的初始值。

```sql
CREATE TABLE users (
    id INT NOT NULL AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100),
    PRIMARY KEY (id)
) AUTO_INCREMENT = 1001;
```

在这个例子中，`id` 字段从 `1001` 开始递增。

#### 3.2 修改自增步长

如果你想改变自增的步长，可以使用 `SET` 语句：

```sql
SET @@auto_increment_increment = 5;
```

这会把自增步长设置为 `5`，即每次插入数据时，自增值会增加 `5`。

### 4. **查询当前自增值**

如果你想查询某个表的下一个自增值，可以使用 `SHOW TABLE STATUS` 命令，或者查询 `INFORMATION_SCHEMA` 中的 `AUTO_INCREMENT` 信息。

```sql
SHOW TABLE STATUS LIKE 'users';
```

你也可以通过查询 `INFORMATION_SCHEMA` 来获取：

```sql
SELECT AUTO_INCREMENT 
FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_NAME = 'users' AND TABLE_SCHEMA = '数据库名';
```

### 5. **修改现有表的自增字段**

如果你想为已经存在的表添加自增功能，可以通过 `ALTER TABLE` 来修改字段。例如，将 `id` 字段设置为自增：

```sql
ALTER TABLE users MODIFY id INT NOT NULL AUTO_INCREMENT;
```

### 6. **删除自增字段**

如果你不再需要自增字段，可以通过 `ALTER TABLE` 删除它：

```sql
ALTER TABLE users MODIFY id INT;
```

### 7. **注意事项**

- **自增字段不可为 NULL**：自增字段必须是 `NOT NULL`，因为 MySQL 会自动为其分配一个值。
    
- **自增值唯一**：自增字段保证每个值的唯一性，但在某些操作下（如删除行）可能会导致自增值的间隙。
    
- **删除数据后，自增值不自动回收**：如果你删除了一些记录，自增值会继续递增，而不会从已删除的记录的 ID 回收。例如，如果你删除了 ID 为 1 和 2 的记录，下一次插入会使用 ID 为 3 的值。
    

### 总结

- **自增字段**常用于生成唯一的标识符，尤其是在主键中。
    
- **初始值**和**步长**可以自定义。
    
- **插入数据时**无需指定自增字段的值，MySQL 会自动处理。
    
# 增、删、改、查
## 增
在 MySQL 中，**插入数据**使用的是 `INSERT INTO` 语句。你可以向表中添加一条或多条记录。下面是 `INSERT INTO` 的常见用法。

### 1. **插入单条数据**

最基本的 `INSERT INTO` 语法如下：

```sql
INSERT INTO 表名 (字段1, 字段2, ..., 字段n)
VALUES (值1, 值2, ..., 值n);
```

#### 示例：

假设你有一个表 `users`，它有 `id`、`username` 和 `email` 三个字段。要插入一条新数据：

```sql
INSERT INTO users (username, email)
VALUES ('Alice', 'alice@example.com');
```

- `id` 字段是自增的，所以不需要在插入时提供该字段的值，MySQL 会自动为其生成一个唯一的值。
    

### 2. **插入多条数据**

你可以一次性插入多条数据，多个值可以用逗号分隔。

#### 语法：

```sql
INSERT INTO 表名 (字段1, 字段2, ..., 字段n)
VALUES
    (值1_1, 值1_2, ..., 值1_n),
    (值2_1, 值2_2, ..., 值2_n),
    ...;
```

#### 示例：

```sql
INSERT INTO users (username, email)
VALUES 
    ('Alice', 'alice@example.com'),
    ('Bob', 'bob@example.com'),
    ('Charlie', 'charlie@example.com');
```

### 3. **插入所有字段的值**

如果你在表中定义了字段顺序，并且要插入数据时填充所有字段的值，可以省略字段名称列表，直接插入数据。

#### 示例：

```sql
INSERT INTO users
VALUES (NULL, 'Alice', 'alice@example.com');
```

- 在这种情况下，`id` 字段通常是自增的，所以你可以使用 `NULL` 或完全省略它，MySQL 会自动生成该值。
    

### 4. **插入数据时使用默认值**

如果某个字段定义了默认值，你可以在插入时忽略该字段，MySQL 会自动使用默认值。

#### 示例：

假设 `users` 表中有一个 `age` 字段，并且它的默认值是 `18`，你可以省略 `age` 字段，在插入时使用默认值。

```sql
INSERT INTO users (username, email)
VALUES ('Alice', 'alice@example.com');
```

- 在这种情况下，`age` 字段会使用其默认值 `18`，而不是 `NULL`。
    

### 5. **插入数据时使用 SELECT 子查询**

你还可以通过 `SELECT` 子查询从另一个表或同一表中选择数据，并将结果插入到目标表中。

#### 语法：

```sql
INSERT INTO 表名 (字段1, 字段2, ..., 字段n)
SELECT 字段1, 字段2, ..., 字段n FROM 源表 WHERE 条件;
```

#### 示例：

假设你有一个表 `archived_users`，并且想将其部分数据插入到 `users` 表：

```sql
INSERT INTO users (username, email)
SELECT username, email FROM archived_users WHERE is_active = 1;
```

这个查询将从 `archived_users` 表中选择所有 `is_active = 1` 的记录，并插入到 `users` 表中。

### 6. **使用 ON DUPLICATE KEY UPDATE 处理重复键**

如果你插入数据时遇到重复的主键或唯一索引，你可以使用 `ON DUPLICATE KEY UPDATE` 来更新已存在的记录。

#### 语法：

```sql
INSERT INTO 表名 (字段1, 字段2, ...)
VALUES (值1, 值2, ...)
ON DUPLICATE KEY UPDATE 字段1 = 新值1, 字段2 = 新值2;
```

#### 示例：

假设 `email` 字段是唯一索引，你想要插入新的用户数据，如果 `email` 已经存在，则更新 `username`。

```sql
INSERT INTO users (username, email)
VALUES ('Alice', 'alice@example.com')
ON DUPLICATE KEY UPDATE username = 'Alice Updated';
```

如果 `email` 已存在，则会更新 `username` 字段；如果 `email` 不存在，则插入新记录。

### 7. **插入数据时使用表达式或计算**

你可以在 `INSERT INTO` 语句中使用一些表达式或计算，例如在插入时使用当前时间。

#### 示例：

```sql
INSERT INTO orders (order_date, amount)
VALUES (NOW(), 100.50);
```

在这个例子中，`NOW()` 函数会插入当前的日期和时间。

### 8. **总结：插入数据的常见方法**

- **单条插入**：使用 `INSERT INTO` 插入一行数据。
    
- **多条插入**：使用 `INSERT INTO` 插入多行数据。
    
- **插入所有字段的值**：省略字段名，直接提供所有值。
    
- **使用默认值**：如果字段有默认值，可以省略该字段，MySQL 会自动使用默认值。
    
- **通过 SELECT 插入**：从其他表或同一表选择数据并插入。
    
- **避免重复插入**：使用 `ON DUPLICATE KEY UPDATE` 来处理主键冲突。

## 删
在 MySQL 中，删除数据可以通过 `DELETE` 语句来实现。根据你的需求，你可以删除表中所有数据或删除特定的数据。

### 1. **删除所有数据**

如果你想删除表中的所有数据（但保留表结构），可以使用 `DELETE` 语句，而不加任何 `WHERE` 条件。

#### 语法：

```sql
DELETE FROM 表名;
```

#### 示例：

```sql
DELETE FROM emp;
```

这个语句会删除 `emp` 表中的所有记录，但表结构仍然存在。注意，如果表有自增字段（如 `eid`），自增计数器不会重置。若要重置自增值，可以使用 `ALTER TABLE`。

### 2. **删除特定的数据**

如果你只想删除满足特定条件的数据，可以在 `DELETE` 语句中使用 `WHERE` 子句来指定条件。

#### 语法：

```sql
DELETE FROM 表名 WHERE 条件;
```

#### 示例：

假设你只想删除 `eid` 为 101 的员工记录：

```sql
DELETE FROM emp WHERE eid = 101;
```

这个语句会删除 `eid` 等于 101 的记录。

### 3. **删除数据并重置自增值**

如果你删除了所有数据，并且希望重置自增计数器（使下次插入数据时从 1 开始），你可以使用 `TRUNCATE` 语句。

#### 语法：

```sql
TRUNCATE TABLE 表名;
```

#### 示例：

```sql
TRUNCATE TABLE emp;
```

`TRUNCATE` 会删除表中的所有数据并重置自增计数器。它比 `DELETE` 更高效，但注意 `TRUNCATE` 不能添加 `WHERE` 条件。

### 4. **注意事项**

- `DELETE` 语句会逐行删除数据，因此删除大量数据时可能会较慢。
    
- `TRUNCATE` 会删除所有数据，并重置自增计数器，但它不会触发 `DELETE` 触发器（如果有的话），而且删除过程无法撤销。
    
- 在执行删除操作时，最好先备份数据，尤其是在删除大量数据或使用 `TRUNCATE` 时。
    

### 总结

- **`DELETE FROM 表名`**：删除表中所有数据。
    
- **`DELETE FROM 表名 WHERE 条件`**：删除符合条件的特定数据。
    
- **`TRUNCATE TABLE 表名`**：删除表中所有数据并重置自增值。
    
## 改

在 MySQL 中，修改数据使用 `UPDATE` 语句。你可以更新表中的一条或多条记录，根据条件修改字段的值。

### 1. **修改单条记录**

要修改表中的某条记录，使用 `UPDATE` 语句，并结合 `WHERE` 子句来指定要更新的记录。

#### 语法：

```sql
UPDATE 表名
SET 字段1 = 新值1, 字段2 = 新值2, ...
WHERE 条件;
```

#### 示例：

假设你有一个 `emp` 表，想要修改 `eid` 为 101 的员工的 `salary` 和 `dept` 信息。

```sql
UPDATE emp
SET salary = 55000, dept = 'HR'
WHERE eid = 101;
```

这个语句将更新 `eid` 为 101 的员工的薪水为 `55000`，并将部门设置为 `'HR'`。

### 2. **修改多条记录**

你可以通过 `WHERE` 子句修改多个符合条件的记录。如果不加 `WHERE` 子句，将会修改表中的所有记录。

#### 示例：

假设你想将所有员工的 `age` 增加 1：

```sql
UPDATE emp
SET age = age + 1;
```

这个语句会将 `emp` 表中所有员工的 `age` 字段的值加 1。

### 3. **修改数据时使用表达式**

你可以在 `UPDATE` 语句中使用各种表达式进行计算、日期处理、字符串操作等。

#### 示例：修改薪水并增加10%的奖金

```sql
UPDATE emp
SET salary = salary * 1.10
WHERE dept = 'IT';
```

这个语句会将 `IT` 部门所有员工的薪水增加 10%。

### 4. **修改多个字段**

你可以一次修改多个字段。

#### 示例：

```sql
UPDATE emp
SET ename = 'John Doe', age = 35, salary = 60000
WHERE eid = 102;
```

这个语句会将 `eid` 为 102 的员工的 `ename`、`age` 和 `salary` 一次性修改。

### 5. **没有 WHERE 子句的 UPDATE**

如果不加 `WHERE` 子句，将会更新表中所有记录。这通常不建议使用，除非你确实想更新所有行的数据。

#### 示例：

```sql
UPDATE emp
SET salary = 50000;
```

这个语句会将 `emp` 表中的所有员工薪水都更新为 `50000`。因此，使用时需要小心。

### 6. **注意事项**

- **WHERE 子句**：一定要小心使用 `WHERE` 子句，确保你只更新你想更新的记录。如果没有 `WHERE` 子句，所有记录都会被修改。
    
- **事务控制**：如果你修改了重要数据，最好在事务中进行操作，确保可以在出错时回滚。
    
    - 开始事务：`START TRANSACTION;`
        
    - 提交事务：`COMMIT;`
        
    - 回滚事务：`ROLLBACK;`
        

#### 示例：

```sql
START TRANSACTION;

UPDATE emp
SET salary = 55000
WHERE eid = 101;

-- 如果没问题，提交事务
COMMIT;

-- 如果有问题，回滚事务
-- ROLLBACK;
```

- 注意`!=`和`<>`都可以表示“不等于”

### 总结

- 使用 `UPDATE` 语句来修改表中的数据。
    
- 使用 `SET` 指定要更新的字段和新值。
    
- 使用 `WHERE` 子句指定修改的条件，确保只修改需要更新的记录。
    
- 不加 `WHERE` 会更新所有记录，需谨慎使用。

#### 7️⃣ 模糊查询（LIKE）

```sql
select * from 表名 where 字段 like '值%';
```

- `LIKE`：用于模糊匹配字符串
    
- 通常配合 **通配符** 使用
    

---

##### 通配符说明

- `%`：匹配 **任意长度（0 个或多个）字符**
    
- `_`：匹配 **1 个字符**
    
    - ⚠️ 与中英文无关
        
    - **1 个 `_` = 1 个字符（不是字节）**
        

---

##### 使用示例

```sql
-- 查询姓刘的所有人
select * from 表名 where 字段 like '刘%';
```

```sql
-- 查询姓刘，且名字只有两个字的人
select * from 表名 where 字段 like '刘_';
```

```sql
-- 查询名字第二个字是“明”的人
select * from 表名 where 字段 like '_明%';
```

---

##### 正确写法（重要）

✅ **LIKE 必须搭配字符串，并使用单引号**

```sql
select * from 表名 where 字段 like '刘_%';
```

❌ 错误写法：

```sql
select * from 表名 where 字段 刘_% ;
```

❌ 错误写法：

```sql
select * from 表名 where 字段 like 刘_% ;
```

---

##### LIKE 使用注意事项（重点）

1️⃣ **LIKE 只能用于字符类型字段**

- `varchar`
    
- `char`
    
- `text`
    

---

2️⃣ **通配符放的位置决定匹配方式**

|写法|含义|
|---|---|
|`'刘%'`|以“刘”开头|
|`'%明'`|以“明”结尾|
|`'%明%'`|包含“明”|
|`'刘_'`|姓刘且名字两个字|

---

3️⃣ **`_` 匹配的是“字符”，不是字节**

- 中文 1 个字 = 1 个 `_`
    
- 英文 1 个字母 = 1 个 `_`
    

---

4️⃣ **LIKE 区分不区分大小写**

- 默认 **不区分大小写**（取决于字段的排序规则 collation）
    
- 可通过 `COLLATE` 强制区分
    

---

5️⃣ **LIKE 与索引**

- `'刘%'` 👉 可以使用索引
    
- `'%刘%'` 👉 **不能使用索引**（性能差）
    

---

##### LIKE 与占位符（参数）结合（补充）

```sql
select * from 表名 where 字段 like ?;
```

参数示例：

```text
刘%
```

⚠️ 通配符 `%`、`_` **必须包含在参数中**

---

##### 一句话总结（可直接写在笔记里）

> `LIKE` 用于模糊查询，`%` 匹配任意多个字符，`_` 匹配 1 个字符，匹配的是字符数量，与中英文无关，通配符位置决定匹配规则。


## 子查询

---

### 一、什么是子查询（Subquery）

> **子查询：在一条 SQL 语句中，嵌套的另一条查询语句**

```sql
SELECT ...
FROM 表
WHERE 字段 运算符 (SELECT ...);
```

📌 **子查询先执行，外层查询后执行**

---

### 二、子查询常见分类（必考）

#### ① 按“返回结果”分类 ⭐

|类型|返回结果|
|---|---|
|标量子查询|1 行 1 列|
|列子查询|多行 1 列|
|行子查询|1 行 多列|
|表子查询|多行 多列|

---

### 三、1️⃣ 标量子查询（最常见）

#### 特点

- 返回 **一个值**
    
- 常配合：`= > < >= <=`
    

#### 例 1：查询 **分数高于平均分的学生**

```sql
SELECT *
FROM std
WHERE score > (
    SELECT AVG(score)
    FROM std
);
```

📌 内层先算平均分，外层再比较。

---

### 四、2️⃣ 列子查询（多行单列）

#### 常配合的运算符

|运算符|说明|
|---|---|
|IN|在集合中|
|NOT IN|不在集合中|
|ANY / SOME|满足任一|
|ALL|满足全部|

---

#### 例 2：查询 **成绩在 3 年级学生中的所有成绩**

```sql
SELECT *
FROM std
WHERE score IN (
    SELECT score
    FROM std
    WHERE grade = 3
);
```

---

#### ⚠️ NOT IN 易错点（重点）

```sql
-- 如果子查询结果中有 NULL，会导致外层查不到任何数据
NOT IN
```

👉 实战中 **优先用 `NOT EXISTS`**

---

### 五、3️⃣ 行子查询（1 行多列）

#### 例：同时比较多个字段

```sql
SELECT *
FROM std
WHERE (grade, subject) = (
    SELECT grade, subject
    FROM std
    WHERE student_name = '张三'
);
```

📌 要求子查询 **只能返回一行**

---

### 六、4️⃣ 表子查询（多行多列）

#### 用在 FROM 后（当临时表）

```sql
SELECT t.subject, AVG(t.score)
FROM (
    SELECT subject, score
    FROM std
    WHERE score > 80
) t
GROUP BY t.subject;
```

📌 子查询结果要 **起别名**

---

### 七、子查询常见出现的位置（必背）

#### ① WHERE 中（最常见）

```sql
WHERE score > (SELECT AVG(score) FROM std)
```

---

#### ② FROM 中（派生表）

```sql
FROM (SELECT ...) t
```

---

#### ③ SELECT 中（了解）

```sql
SELECT student_name,
       (SELECT AVG(score) FROM std) AS avg_score
FROM std;
```

---

### 八、EXISTS / NOT EXISTS（进阶重点）

#### 特点

- 只关心 **是否存在**
    
- 不关心返回什么
    
- 性能通常优于 IN
    

---

#### 例：查询 **有成绩大于 90 的学生**

```sql
SELECT *
FROM std s
WHERE EXISTS (
    SELECT 1
    FROM std
    WHERE score > 90
      AND student_name = s.student_name
);
```

---

### 九、子查询 vs JOIN（面试/实战）

|对比|子查询|JOIN|
|---|---|---|
|可读性|好（逻辑清晰）|中|
|性能|一般|较好|
|复杂查询|易写|稍复杂|

📌 **能用 JOIN 的，优先 JOIN**

---

### 十、子查询易错点总结（考试高频）

#### ❌ 1. 标量子查询返回多行

```sql
WHERE score = (SELECT score FROM std); -- 错
```

#### ❌ 2. 子查询没加括号

```sql
WHERE score > SELECT AVG(score) FROM std; -- 错
```

#### ❌ 3. FROM 中子查询不写别名

```sql
FROM (SELECT ...)  -- 错
```

---

### 十一、一页口诀（强烈推荐背）

> **子查询先执行  
> 一值用比较  
> 多值用 IN  
> 判存在用 EXISTS  
> FROM 子查询要别名**

---

### 十二、结合你之前学的题（示例）

#### 查询 **每科平均分高于整体平均分的科目**

```sql
SELECT subject, AVG(score) AS avg_score
FROM std
GROUP BY subject
HAVING AVG(score) > (
    SELECT AVG(score)
    FROM std
);
```

## 多表查询

### 一、多表查询概述

- 多表查询：从 **两张或多张表** 中获取数据
    
- 核心前提：**表之间存在逻辑关系**
    
    - 一对一
        
    - 一对多（最常见）
        
    - 多对多
        
- 实现方式：
    
    - 连接查询（JOIN）
        
    - 子查询
        

---

### 二、表之间的关系

#### 2.1 一对多

- 例子：班级 —— 学生
    
- 实现方式：
    
    - 在“多”的一方建立 **外键**
        

```sql
student.class_id → class.id
```

#### 2.2 多对多

- 例子：学生 —— 课程
    
- 实现方式：
    
    - 建立 **中间表**
        
    - 中间表至少包含两个外键
        

---

### 三、连接查询（JOIN）

#### 3.1 内连接（INNER JOIN）

- 只返回 **满足连接条件** 的数据
    

```sql
SELECT *
FROM student s
INNER JOIN class c
ON s.class_id = c.id;
```

**特点：**

- 两张表都存在匹配数据才显示
    

---

#### 3.2 左外连接（LEFT JOIN）

- 返回 **左表全部数据**
    
- 右表没有匹配则为 `NULL`
    

```sql
SELECT *
FROM student s
LEFT JOIN class c
ON s.class_id = c.id;
```

**使用场景：**

- 查询“所有学生（即使没班级）”
    

---

#### 3.3 右外连接（RIGHT JOIN）

- 返回 **右表全部数据**
    

```sql
SELECT *
FROM student s
RIGHT JOIN class c
ON s.class_id = c.id;
```

---

### 四、多表查询的条件过滤

#### 4.1 WHERE 与 ON 的区别

- `ON`：控制 **表如何连接**
    
- `WHERE`：控制 **最终结果过滤**
    

```sql
SELECT *
FROM student s
LEFT JOIN class c
ON s.class_id = c.id
WHERE s.score > 80;
```

⚠️ **LEFT JOIN + WHERE 可能变成 INNER JOIN**

---

### 五、多表分组查询

#### 5.1 多表 + GROUP BY

```sql
SELECT c.class_name, AVG(s.score)
FROM student s
JOIN class c
ON s.class_id = c.id
GROUP BY c.class_name;
```

---

#### 5.2 HAVING 过滤分组结果

```sql
SELECT c.class_name, AVG(s.score) avg_score
FROM student s
JOIN class c
ON s.class_id = c.id
GROUP BY c.class_name
HAVING avg_score > 85;
```

📌 **HAVING 用于聚合函数**

---

### 六、多表查询执行顺序（重点）

```text
FROM
→ JOIN / ON
→ CHECK JOIN CONDITION
→ WHERE
→ GROUP BY
→ HAVING
→ SELECT
→ ORDER BY
→ LIMIT
```

---

### 七、子查询在多表中的应用

#### 7.1 子查询作为条件

```sql
SELECT *
FROM student
WHERE class_id IN (
    SELECT id FROM class WHERE class_name = '三年级'
);
```

---

#### 7.2 子查询作为临时表（派生表）

```sql
SELECT AVG(cnt)
FROM (
    SELECT COUNT(*) cnt
    FROM student
    GROUP BY class_id
) t;
```

⚠️ **派生表必须有别名**

---

### 八、多表查询常见错误

#### 8.1 字段歧义

```sql
-- 错误
SELECT id FROM student JOIN class;

-- 正确
SELECT student.id FROM student JOIN class;
```

---

#### 8.2 GROUP BY 使用错误

```sql
SELECT class_id, student_name
FROM student
GROUP BY class_id;
```

❌ 非聚合字段未出现在 GROUP BY 中

---

### 九、多表查询性能建议

- 明确字段，避免 `SELECT *`
    
- JOIN 字段建立索引
    
- 小表驱动大表
    
- 能用 INNER JOIN 不用 OUTER JOIN
