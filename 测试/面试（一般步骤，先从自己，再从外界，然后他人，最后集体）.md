## 第一部分：网络通信和协议

### 1、什么是 HTTPS 和 HTTP?

**答：** HTTP 是超文本传输协议，协议用于定义客户端与 web 服务器通迅的格式。

### 2、什么是 HTTPS？

**答：** HTTPS（安全版超文本传输协议）：简单讲是 HTTP 的安全版，就是在 http 和 TCP 之间有一层 SSL 层，多了一个加密传输数据的协议。即 HTTP 下加入 SSL 层。

### 3、HTTP 格式是什么？（或者你描述一下 http 的内容是什么？）

**答：** 
*   HTTP 的请求格式为：请求行、请求头、请求数据体
*   HTTP 的响应格式为：状态码、响应头、响应数据体（响应数据体就是服务器返回的资源的内容）

### 4、HTTP 请求头包含哪些内容？

**答：** 请求方法(get or post)、域名、端口、用户代理(user-Agent)、cookie、accept 接收类型、编码格式等等

### 5、HTTPS 和 HTTP 的区别主要为以下 3 点：

**答：**
1.  https 协议需要到 ca 申请证书 （放心网站，一般免费证书很少，需要交费）。
2.  http 是明文传输，https 则是加密传输协议。
3.  http 和 https 使用的端口也不一样，前者是 80，后者是 443。

### 6、HTTPS 和 HTTP 协议的请求方式？

**答：** 请求方式常见的有 GET，POST，PUT，DELETE
*   GET 表示： 请求资源；
*   POST 表示：提交表单；
*   PUT 表示： 更新资源；
*   DELETE 表示：删除资源;

### 7、HTTP 协议的版本？

**答：** HTTP/1.0、HTTP/1.1

### 8、http1.0 和 http1.1 区别？

**答：** 
*   http1.0 是短链接，建立一个TCP链接后，只能发起一个http请求，获得一个web资源
*   http1.1 是长链接，建立一个TCP链接后，能发起多个http请求，可以获得多个web资源

### 9、HTTP 协议中的 get 和 post 方法区别？

**答：**
（1） GET 用于从服务器端获取数据，POST 用于向服务器提交数据，提交表单信息的。
（2）提交数据的长度方面：
    *   GET：提交的数据长度是有限制的，在 URL 地址后附带的参数是有限制的，其数据容量通常有限制（URL 长度）
    *   Post：提交的数据长度是无限制的（请求方式为 POST 方式，则可以在请求的实体内容中向服务器发送数据）
（3） 传输速度方面：get 传输数据速度快，post 速度慢
（4）安全性方面：POST 的安全性要比 GET 的安全性高
    *   POST 请求数据放在 body 中，URL 地址栏中不显示目标地址
    *   get 请求数据放在 URL 地址中，直接显示目标地址了

### 10、谈谈你对 HTTP 协议的了解？（必问）

**答：** 超文本传输协议，端口为 80，特点(无记忆功能、快速)是由请求和响应两部分组成；请求由请求头、请求行、请求正文组成；响应是由响应头、响应行、响应正文组成，https =http+ssl 协议 端口 443。

HTTPS是安全的超文本传输协议，在HTTP协议到基础上使用 SSL证书，也称为服务器 SSL证书，是遵守 SSL 协议的一种数字证书，将SSL证书安装在网站服务器上，可实现网站身份验证和数据加密传输双重功能。SSL证书需要到CA机构申请，然后部署到网站的服务器端，网站就可以实现ssl加密访问了。

### 11、HTTP 响应状态码 200 ,302, 404,500 表示什么意思？

**答：**
*   **200 OK**：请求成功。
*   **302 Found**：临时重定向，表示请求的资源临时搬到了其他位置。
*   **404 Not Found**：表示服务器找不到请求的资源。
*   **500 Internal Server Error**：表示服务器执行请求的时候出错了。

**详细状态码：**
*   **2xx（成功）**：
    *   200 ok （请求成功）
    *   204 no content （请求成功，但是没有结果返回）
*   **3xx（重定向）**：
    *   301 Moved Permanently 永久重定向，表示请求的资源已经永久的搬到了其他位置
    *   302 Found 临时重定向，表示请求的资源临时搬到了其他位置
*   **4xx（客户端错误）**：
    *   400 Bad Request 表示请求报文存在语法错误或参数错误，服务器不理解
    *   401 Unauthorized 表示发送的请求认证失败了
    *   403 Forbidden 表示对请求资源的访问被服务器拒绝了
    *   404 Not Found 表示服务器找不到请求的资源
*   **5xx（服务端错误）**：
    *   500 Internal Server Error 表示服务器执行请求的时候出错了
    *   503 Service Unavailable 表示服务器超负载或正停机维护，无法处理请求(暂时的)
    *   504 网关超时，服务器作为网关或代理，但是没有及时从上游服务器收到请求

### 12、HTTP：（服务器报错）500 错误有哪些可能情况?

**答：** 1：服务停止了 2：数据库有问题 3：程序内部处理错误 4：服务器上程序的文件夹权限不够

### 13、接口请求方式有哪些？分别表示什么意思？

**答：**
*   GET 请求获取资源
*   POST 提交数据
*   PUT 更新数据
*   DELETE 删除数据

### 14、输入 URL 到页面加载显示完成的发生了什么？（百度输入网址，发送请求的过程？）

**答：** 浏览器根据请求的 URL 地址交给 DNS 域名解析得到真正的 IP 地址，向服务器发送请求；HTTP 三次握手，浏览器与服务器建立连接会话；服务器接收处理请求返回报头，浏览器开始下载服务器传来的资源（HTML、JS、图片等），同时进行缓存；浏览器对加载到的资源进行解析，渲染页面完成。

### 15、说一下什么是 TCP 三次握手？

**答：**
1.  客户端 发送 SYN 包到服务器；SYN 是 ：同步序列编号；
2.  服务器 收到 SYN 包后，会回复 SYN+ACK 包给客户端；
3.  客户端 收到服务器的 SYN+ACK 包后，向服务器发送确认包 ACK。

以上包都发送成功后，完成三次握手。这时候客户端才向服务器传送数据。

### 16、为什么是 3 次握手，不 2 次握手？

**答：** 两次握手只能保证单向连接是畅通的。因为 TCP 是一个双向传输协议，只有经过第三次握手，才能确保双向都可以接收到对方的发送的数据。

### 17、说一下什么是 Tcp 的四次挥手？

**答：**
（1） 客户端发送一个 FIN，用来关闭客户到服务器的数据传送。
（2） 服务器收到这个 FIN，它发回一个 ACK，确认序号为收到的序号加 1。和 SYN 一样，一个 FIN 将占用一个序号。
（3） 服务器关闭客户端的连接，发送一个 FIN 给客户端。
（4） 客户端发回 ACK 报文确认，并将确认序号设置为收到序号加 1。

### 18、四次挥手的作用是什么？

**答：** 主要是为了防止已经失效的连接请求报文突然又传送到了服务器，从而导致不必要的错误和资源的浪费。

### 19、什么是 Tcp 和 Udp？Tcp 和 Udp 的区别？

**答：**
*   **Tcp**：传输控制协议，面向链接的协议，即发送数据之前需要建立连接，传输数据比较可靠，传输速度慢，将大块的数据分割成小的数据包进行可靠的传输只支持一对一通信，适用于要求可靠传输的应用（比如打电话）。
*   **Udp**：用户数据报协议，面向无链接的协议，即发送数据之前不需要建立连接，传输数据不可靠，传输速度块，支持一对一，一对多通信，适用于实时性的应用，UDP 是面向无连接的通讯协议，由于通讯不需要连接，不可靠，主要用户实现广播发送功能.

### 20、TCP 和 UDP 的区别？

**答：**
*   TCP：传输控制协议，是面向链接的协议，传输数据比较可靠
*   Udp：用户数据报协议，是面向无链接的协议，传输数据不可靠

### 21、什么是 DNS？

**答：** DNS 是域名系统 (Domain Name System)，DNS 是用来做域名解析的,它会在你上网输入网址后，把它转换成 IP，然后去访问对方服务器；没有它，你想上百度就要记住百度的 IP，但有了 DNS 的处理，你只需要记住对应网站的域名，即网址就可以了。

### 5、搭建环境方法 2：Linux+JDK+MySQL+Tomcat 如何搭建的？

**答：**

**第三步 安装 Tomcat**
将下载好的 Tomcat 压缩包传到建好的 tomcat 文件下并解压，设置永久关闭防火墙，再启动 tomcat ，`service tomcat start`，在你的浏览器中输入 ：`http://ip:8080`，如果出现 tomcat 的主界面那么就启动成功。

**第四步 项目部署**
在 eclipse 或者 idea 中将项目导出成 war 包，通过 XFtp 上传到 tomcat/webapps 文件夹下，然后停止重启 tomcat，在浏览器输入 `http://ip:8080/项目名` 就可以了。

### 6、如果网址搭建好，也进入不网址，或者首页打不开？一般什么情况怎么处理？

**答：**
1：JDK环境变量没设好（重装jdk或者重新设置）
2：JDK版本不匹配（下载相匹配的jdk，JDK版本也要和tomcat版本相匹配，Tomcat8只支持jdk1.7及1.7以上的jdk）
3：tomcat没启动 （没解压war包，启动war包，如果tomcat启动了，但是war没解压，这种情况就是JDK没配好）
4：数据库访问密码和程序连接的密码不一致
5：没有导入数据库脚本
5：程序本身错误
6：防火墙没开放端口号

## 第三部分：mysql 数据库

### 1、数据库的常用操作有哪些？

**答：** 学习数据库的目的是：检查界面显示的数据是否正确，和数据库是否一致。

**常用操作：**
*   增/删/改/查/
*   内连接查询、左连接查询、右连接查询
*   聚合函数 `sum`（值相加）、`count`（行数）、`avg`、`max`、`min`
*   `Distinct` 去重复记录
*   `Limit` 查前几行，定制查询，分页查询
*   `Order by` 排序： `Asc` 升序、`desc` 降序
*   `Group by` 分组查询 （分组的目的就是要使用聚合函数，一般和聚合函数同时出现，同时还应该加上一个分组的字段，用于显示那个字段分组）
*   `Having`：分组后，并且使用聚合函数计算出来的结果，再一次过滤

**建表语句：**
*   加主键：`alter table 表名 add primary key (字段名);`
*   在 XX 字段上加索引：`alter table 表名 add index(字段名);` 默认索引名称同字段名

**增删改查语句：**
*   `insert` 添加：`insert into 表名称 (字段 1,字段 2,..) values (值 1,值 2,..) `//值数量需要和插入的字段个数一致
*   `Delete` 删除：`Delete from tablename where 条件`
*   `Update` 更新：`Update 表名 set 字段 1=“字段值”，字段 2=“字段值” where id=1；`
*   `Select` 查询：`select *或字段名或函数 from 表名 where 条件 group by 分组的字段名 having 条件 order by 字段名 排序规则 limit a,b；`

### 2、怎么插入大量数据？

**答：** 写一个存储过程，然后使用 一个 while 循环 + `insert into` 插入记录语句 就可以了。

### 3、多表怎么查？

**答：** Join 方式 （3 个表的形式 join）
`select 表 A.字段, 表 B.字段, 表 C.字段 from 表 A join 表 B on 表 A.字段 (相同意思的字段）= 表 B.字段 (相同意思的字段) join 表 C on 表 C.字段 = 表 A.字段 + （where + group byhaving + order by+ limit）`

### 4、什么是左连接、右连接、内联接？

**答：**
*   `left join` (左联接) 以左表记录条数为基准合并列出，右表少记录，则补 NULL 值
*   `right join`(右联接) 以右表记录条数为基准合并列出，左表少记录，则补 NULL 值
*   `inner join`(内联结) 只返回两个表中联结的记录

**答：** 它就是一组 SQL 命令，是虚表，基于基本表，不是真的表。新建 View，`Create view view_name As select 字段 from 基本表`

### 7、in 和 not in 的区别：

**答：**
1.  意思相反
2.  `In` 的取值范围里面可以包含 `null` 值，最多就是 `null` 值显示不出来，并不影响其他值的查询结果

### 8、什么是数据库索引？

**答：** 索引是数据库中的索引可以类比为书本的目录。索引和目录的原理理解起来是很相似的，索引表中关键字就是要查找的知识点，索引中的地址就是这个知识点对应的位置。使用索引可以，可以大大加快 数据的检索速度，这也是创建索引的最主要的原因。

**（2）索引的好处？**
*   通过创建索引,可以在查询的过程中,提高系统的性能；
*   通过创建唯一性索引,可以保证数据库表中每一行数据的唯一性；
*   在使用分组和排序子句进行数据检索时,可以减少查询中分组和排序的时间；

**（3）索引的坏处？**
*   创建索引和维护索引要耗费时间,而且时间随着数据量的增加而增大；
*   索引需要占用物理空间,如果要建立聚簇索引,所需要的空间会更大；
*   在对表中的数据进行增加删除和修改时需要耗费较多的时间,因为索引也要动态地维护；

### 5、敏捷测试和敏捷开发的特点？

**答：** **敏捷开发**的核心思想是：以人为本，适应变化。2 周一个迭代。
	**敏捷测试**的特点：高度迭代、高度自动化、研发周期性短，并且能够及时、持续地响应客户的频繁反馈，以人为本，注重灵活。

### 6、什么时候结束测试？（发版的标准）

**答：** 所测版本经过几轮测试后，
1、软件需求分析说明书中定义的所有功能已全部实现，达到要求。
2、所有测试项没有残余的一级二级三级的错误。
3、立项文档、需求分析文档、设计文档和编码实现一致。
所有测试用例执行完毕，问题非常少，剩余问题不影响重要功能的使用，而且测试时间已经达到了测试计划的时间节点，由项目经理，测试经理，开发经理等领导会议决定停止测试，就可以结束测试了。

### 7、发版的标准是什么？

**答：**
*   全量测试用例执行率 100%，通过率 95%
*   缺陷 L1，L2 修复率达到 100%
*   遗留缺陷 L3，L4 不超过总缺陷 5%
*   按照系统测试计划完成了系统测试，满足了产品需求，符合发版要求。

### 7、什么时候开始测试？

**答：** 开发已经联调结束，自测没有问题，并且开发提测后，收到提测邮件，测试小组可以进行测试了。

### 8、关于测试点覆盖率的问题？（了解）

**答：** 功能需求测试覆盖率达到争取达到 100%
1、测试覆盖率 100%是一个理想的情况，是很难达到的；
2、因为总有需求没考虑到，或被客户遗漏，开发也没发现，测试也不知道
2、测试覆盖率 100%不能说明我们做了完全的测试；
3、较低的测试覆盖率能说明我们的测试还不够；
4、同一模块高覆盖率相对于低覆盖率，能说明我们做了更多的测试工作；
5、测试覆盖率达到多少要考虑到软件整体的覆盖率情况，以及项目成本，包括人力，时间等等，测试覆盖率还是具体要看投入产出是否合理。

### 9、如何保证测试的覆盖率？怎么编写好测试用例？怎么保证产品质量？（必问）

**答：**
1）首先要充分的理解需求，将不同需求来源(包括隐式需求）划分成一个个需求点，针对每一点需求进行测试点分析
2）要保证测试用例能够全面覆盖测试需求，测试场景覆盖需求中的业务逻辑
3）当测试用例设计完成后，要组织测试用例的评审，这样可以吸取别人的意见，减少遗漏，补全测试用例
5）测试用例编写完成后，就是测试执行要 100%
6）在测试执行过程中，要继续对测试用例补充完善，确保提高测试覆盖率
7）在整个测试过程中，需求都是不可能不变的，所以要及时的更新测试需求、测试用例

### 10、如何提高测试效率?

**答：**
1) 首先肯定是要深入理解测试需求，掌握适当的测试颗粒度
2) 将测试工作细分、评估每个小阶段的效率，根据优先级，去解决这些问题，以提升整个项目的效率
3) 要善于总结，不断学习好的思维方法

### 11、项目版本执行过程中，测试人员如何把控测试进度？

**答：** 在项目的系统测试过程中，测试负责人要及时了解测试进度，跟踪 BUG 提交、修复及验证情况。若发现有较多 BUG 未解决，则应主动联系 产品经理及研发人员召开 BUG 分析会， 会确定问题的解决时间。若发现有较多 BUG 未验证，则应提醒项目组的测试人员及时进行回归验证。

### 12、什么是白盒测试、黑盒测试、灰盒测试？

**答：**
*   **白盒测试**：又称结构测试，把程序看作是一个透明的盒子，关心软件内部设计和程序实现，对所有逻辑路径进行测试，主要测试依据是模块设计文档。测试方法：有代码检查法、路径测试法等。
*   **黑盒测试**：也称功能测试，把程序看作一个不能打开的黑盒子，不关心软件内部，只关心输入输出，在已知产品应具有的功能的条件下，主要针对软件界面和软件功能进行测试。主要测试依据是需求文档。测试方法：等价类划分法、边界值分析法、错误推测法、场景法等等。

### 13、常见的测试类型的概念？（了解）

**答：**
*   **冒烟测试**：主要测试软件的重要功能，检测能否正常使用，避免正式提交到测试部进行系统测试时发生严重缺陷。（减少测试阻塞情况）
*   **回归测试**：对产品进行一轮测试之后，开发人员会对发现的 bug 进行修改，修改后会提交一个新的程序版本到测试部，测试人员再次对新版本进行测试验证，验证之前发现的 bug 是否在本版本得到修改的活动的测试。

### 25、为什么要对 bug 跟踪？

**答：**
1: 缺陷跟踪系统是帮助开发、测试、项目经理搜集和控制软件中发现的缺陷
2: 跟踪 bug，可以实时了解自己所提 bug的状态，是被接受了，还是已经处理了，处理成什么样了？ 是修改，还是挂起，还是非问题，实时了解，可以让自己对 bug的状态有了掌握，以决定下一步工作或者沟通。如非问题，就需要和开发进一步沟通处理
3：有些bug如果分配到研发人员哪里了，但是一直未修改，比如会影响到自己下一个版本测试，则可以提醒研发人员
4：bug是测试人员提的，也只能由测试人员关闭，那么它中间处于什么状态，也需要关心
5：通过bug跟踪可以理解产品整体质量，还可以通过其他测试人员所提的问题单学习其他测试人员的测试思维
6: bug跟踪还可以观察这个bug的修改历史，修改信息，是自己充分了解出错原因，受影响的部分是哪些，然后有针对性的测试。

### 26、设计用例的 5 大方法？（黑盒测试）

**答：** 1：等价类 2：边界值 3:场景法 3：错误推断法 5: 判定表
*   **（1）等价类划分法**：
    1.  将输入区域划分为若干个等价的类别，具体的分为有效等价类、无效等价类
    2.  有效等价类是依据规格说明书中的要求设计用例
    3.  无效等价类是违反规格说明书中的要求进行设计用例
*   **（2）边界值分析法**：
    1.  依据输入数据的范围进行用例设计，一般选择边界点上的 3个值进行用例设计
    2.  通常选择比最小值正好小一点的值、最小值、最大值、比最大值刚刚大一点的数据作为用例
*   **（3）场景法**：
    1.  主要对业务流程进行测试
    2.  将业务流区分为基本流和备选流，基本流按照正确的流程设计用例，备选流测试各种错误流程
*   **（4）决策表法（也叫判定表法）**：
    1.  分析不同输入的各种组合产生不同的输出
*   **（5）错误推测法**：
    1.  基于经验和直觉推测程序中所有可能存在的各种错误, 从而有针对性的设计测试用例的方法

### 30、开发不认可你提交的 bug 怎么办？

**答：**
**（答案一）** 首先找一个合适的时间，跟开发人员单独沟通，把自己的想法告诉他，从客户角度分析要有理有据，或者重新演示给他看，明确这确实是一个问题，跟他讲明利害关系，进行进行充分沟通，如果开发人员能接受则更好，如果仍然拒绝，就找上级领导，如项目经理和产品经理（或者测试经理）解决。

**（答案二）** 首先分析或与开发沟通开发不认可的原因。
*   如果拒绝原因是提交的不是缺陷，而且自己分析后，的确不是缺陷，则应该注意以后再 做测试时要做好复现，认真研读需求，提高自己找缺陷的能力。
*   如果拒绝原因是认可缺陷，但不予修复，如果自己觉得必须修复，则拿出充分理由和证据和不修复的不利影响和影响范围，再与开发沟通。
*   注意沟通技巧，合理的论述，向开发说明自己的判断的理由，注意客观、严谨，不掺杂 个人情绪。
*   把问题交给测试经理，等待测试经理做出最终决定，如果仍然存在争议，可以通过公司 政策所提供的渠道，向上级反映，并由上级做出决定。
*   先自己查阅需求文档，并询问其他的同事看法。如果他们跟你意见的一致也认为这是一个 bug，此时私底下找个空闲的时间跟开发聊一聊，比如中午吃饭的时候，接水的时候，上厕所的时候，阐述你看的想法。如果这个开发死不承认，这个时候才找产品。由产品经理来决定这是不是一个 bug

### 44、如何处理难以重现的缺陷？

### 5、会看日志吗，会日志分析吗，如何进行日志分析？

**答：** 会分析日志，monkey 测试就是要分析日志才知道测试的情况。看 Monkey 的运行日志，如果显示 monkey finished，表示本次测试是 ok 的，没有问题。否则，就查看日志信息 ，在日志文件中搜索 ANR /exception/ crashed /error/fail (无响应/ 异常/崩溃/错误/失败）关键字。如果出现这些关键字，则表明程序运行有错误。那么我们就导出日志，并提问题单。

### 6、如果问道你知道是哪个模块出错吗？

**答：** 一般出错会抛出异常信息，出错的异常信息中一般会有出错的方法名称或者类名或者一些关键字，大概可以看出是哪个类，哪个方法出错，结合详细设计文档，查看这个类或者方法属于哪个模块的，大致可以定位出问题是哪个模块了。

### 7、Monkey 做稳定性测试和压力测试的时间？

**答：** 通过测试标准：1、：monkey 脚本跑 3 个小时以上，间隔时间 300 毫秒，错误日志无 crash 信息、anr 信息。

### 7、如何进行 monkey 测试？（monkey 怎么用的？）

**答：**
1: 首先安装 JDK，并配置 JDK 环境变量
2：然后再下载一个 adb 工具，并配置 adb 环境变量
3：安装模拟器或者使用一个手机链接电脑
4：在模拟器中或者手机中安装 app 程序
5：利用 adb 工具调用 monkey 对 app 程序进行压力测试
6：monkey 正常运行结束，表示本次测试没问题， 如果运行异常终止，则导出错误日志，并提问题单。
出现如下关键字则表示 monkey 运行失败： Crash 崩溃、exception 异常、error 错误、ANR 应用程序无响应

### 8、APP 测试和 web 测试的区别？

**答：** 它们体现在以下几个方面，就是系统架构方面、性能方面、兼容性方面。
*   **系统架构方面**：
    *   web 项目，是 B/S 架构，基于浏览器的。软件测试只需更新了服务器端就可以。
    *   app 项目，是 C/S 架构，必须要有客户端，用户需要安装客户端。App 项目测试则需要分别更新客户端和服务器。
*   **性能方面**：
    *   web 页面 会关注响应时间。
    *   而 app 则除了关心响应时间外，还需要关心流量、电量、CPU、内存这些 （移动的短板比较多）。
*   **兼容性方面**：
    *   Web 兼容性测试主要考虑浏览器不同版本，系统的不同版本，不需要考虑安装卸载
    *   App 兼容性测试则要看不同的分辨率，屏幕尺寸，还要看不同手机品牌、不同系统版本，app 还需要考虑安装、卸载、更新。
    *   APP 除此之外还要考虑到一些异常场景的测试，比如包括安装时的中断、弱网，电量低等

### 9、APP 测试有哪些特点？（除了功能性测试之外，还有那些专项测试？）

**答：** （除了按需求说明书外的 功能测试 之外还需要进行如下测试，下面这些测试叫专项测试）
1： 兼容性测试（也叫适配性测试，不同的安卓版本，不同厂商，不同手机品牌）

## 第六部分：Fiddler 和 SVN

### 1、什么时候会用到使用 Fiddler?

**答：**
1）定位问题，当测试时发现缺陷，用 fiddler 抓包，定位该问题是前端还是后台的问题；
2）模拟弱网环境。

### 2、怎么抓取 HTTPS 协议的网站？

**答：** 我们安装一个 Fiddler 证书，然后设置一下抓取 HTTPS 这个选项就可以抓取了。

### 3、Fiddler 在测试中做什么用？

**答：** 可以用来查看请求数据、返回数据、限制网速、看响应时间、设置断点等。
**Fiddler 在测试中还可以用来分析定位问题。（必问）**
1：分析请求的数据是否正确，有没有重复请求，有没有错误的请求。有错误的请求和不合理的请求就提单
2：分析返回的数据的内容是否正确？ 包括返回状态码 + 返回的具体内容
3：限制网速，模拟不同的网络环境来测试我们的系统
4：查看服务器响应时间是否合理 ( 时间单位是毫秒，1 秒=1000ms ) 2 秒 5 秒 8 秒；2秒内理想时间，5秒内是可接受时间，5-8勉强接受区间，8秒外是超出忍受区间（提单）
5：还可设置断点，可修改请求的或者返回的数据，以判断程序处理是否正确（修改请求参数，欺骗服务器，测试它的返回内容是否合理或者修改服务器返回内容，检查客户端解释是否正确）

### 4、断点有哪几种？

**答：** 有 2 种，分为请求前断点和响应后断点。
*   `before response`=请求前断点，也就是发送请求之后，这时可以修改请求的数据。
*   `after request`=响应后断点，也就是服务器响应之后，可以修改响应的结果。

**Fiddler 断点在工作中有什么作用？**
当我们在测试的时候，仅仅通过页面来发起请求进行测试，会因为前端的一些输入限制，导致测试不能覆盖所有场景。
（1）比如微信发送红包金额前端限制 0.01-200 元，那我们测试的时候，通过抓包，需要修改请求红包金额超过 200，验证服务器端是否正常处理超出数据。
（2）比如我们很多项目都会涉及到支付功能，假设购买 1 件商品，在提交订单后、跳转到支付窗口之前，通过抓包能抓取到支付金额及数量的请求信息，并去篡改了支付金额或数量，然后以超低价格购买到多数量的高额商品。那就是严重 bug 了！
（3）进行接口测试时，拦截和修改数据，测后端功能。比如：图书网的某本小说的售价是 100 元，进行网页前端的功能测试时，只能输入 100 元进行购买！但是通过 fiddler 抓包工具可以拦截，修改数据。万一有些别有用心的人跳过前端输入框验证，然后修改数据，输入-100 元进行购买。这样的话，不仅买到了小说，账户余额还增加了 100 元。这就说明后端接口不对。

**怎么断点的**
请求前断点：比如断点一个登陆业务，先打开登录页面，然后在Fiddler的“自动断点菜单”中选择“请求前断点”，再登陆，则会抓住登陆的请求参数，可以修改这个参数后，然后放行这个请求，观看服务端处理结果  
响应后断点：比如断点一个登陆后的处理操作，先打开登录页面，然后在Fiddler中选择“响应后断点”，再登陆，则会抓住登陆后的处理结果页面，再修改这个返回的结果内容，再放行，然后观察客户端的显示情况
### 5、Fiddler 怎么抓包？Fiddle 怎么用的？

**答：** （默认按照抓 web 包来说）

### 7、Fiddler 抓包原理？

**答：** Fiddler 是一个 HTTP 代理工具，当打开 Fiddler 后，Fiddler 会自动将浏览器上网设置为代理模式，代理的端口就是 Fiddler 自己的端口，设置完毕后，客户端的所有请求都要先经过 Fiddler，然后转发到相应的服务器，反之，服务器端的所有响应，也都会先经过 Fiddler 然后发送到客户端，就这样，Fiddler 就可以抓包了。

### 10、常见弱网问题和原因分析（弱网测试的方面和场景？）

### 11、SVN 常用命令？

**答：**
*   **Checkout**：（检出）把SVN仓库的代码下载到本地。
*   **Commit**：（提交）当你完成一部分开发后并且程序中没有其它的错误，你可以通过commit提交代码到SVN服务器。重要提示：每次必须先先update再Commit。

### 17、Fiddler 怎么模拟弱网测试？

**答：** 通过延迟请求和响应的数据接收时间来模拟弱网。首先手机和电脑连接同一个路由器，手动设置电脑 IP 为服务器，添加端口，用 fiddler 把延时加大。我会用 fiddler 工具模拟出弱网的情况，首先设备和 fiddler 工具和设备连接起来，然后在自定义规则里搜索 upload 或 download 关键字，会出现延迟参数，我们通过修改这个参数来模拟出 3g、4g、5G/wifi 网络情况，这个参数是改的越高网速越慢。

### 七、Fiddler 如何定位前后端 bug？

**答：**
1.如果 Fiddler 在没有设置任何过滤的情况下面，没有抓到任何的请求消息，那么大概率就是前端的 bug，或者是一些很明显的 js 错误也是前端的 bug；
2.如果抓取到的请求数据有问题，那么就是前端的问题；
3.如果抓取到的请求返回的状态码是 500，说明是后端出了错误，是后端的 bug；
4.如果 Fiddler 抓取到的请求返回的 http 响应状态码是 404 的话，有可能是服务器上根本就没有这个请求地址，也有可能是前端在 js 提交的时候，提交错了这个错误地址。

## 第七部分：接口测试汇总

### 1、没有接口文档如何做接口测试？

**答：**
1.没有接口文档，那就需要先跟开发沟通，然后整理接口文档（接口文档是开发需要写的）
2.没有接口文档，可以抓包看接口请求参数，然后不懂的跟开发沟通

### 2、接口测试流程？怎么做接口测试？给一个系统怎么做接口测试？

**答：** 我们项目前后端调用主要是基于 http 协议的接口，所以测试接口时主要是通过工具进行 http 请求的发送与接收。工具有很多如：postman、jmeter，我们使用的是 apipost。
1) 首先我们要熟悉接口文档，获得接口功能描述、接口请求方式、请求地址、请求参数、返回参数等
2) 使用等价类、边界值、场景法分析输入参数，以及接口是否有前后依赖关系
3) 熟悉了接口文档后，我们就会写一个接口测试用例
4) 接下来，就会依照接口测试用例编写接口脚本，打开 jmeter，添加线程组，cookie 管理器，信息头管理器，默认请求值、HTTP 请求，输入参数，加入断言和查看结果树
5) 再执行接口测试用例
6) 接口测试用例执行完毕后，会对分析接口测试结果，是否和接口返回参数一致
7) 再后写接口测试报告
8) 大概就是这个样子

### 3、结合项目来说一个具体的接口测试是怎么做的？（了解）

**答：** 我就说我最近做的一个电商项目有前后关联的一个接口吧，首先进行登陆，然后在购物车里添加商品。登录之后会生成 token,加入购物车接口就需要使用到 token.
1） 首先打开工具 jmeter，添加一个线程组
2） 添加信息头管理器，HTTP 默认请求值
3） 向信息头管理器里添加请求体的数据类型
4） 再添加一个 HTTP 登陆请求元件，依次填入登陆的 URL 地址、端口、请求方法
5） 然后添加一个 JSON 提取器，用于提取登陆所生成的 token 数据
6） 添加一个 JSON 断言判断返回结果
7） 然后添加编写在购物车里添加商品的 http 请求并输入 url 地址，端口和请求方法
8） 添加使用 json 提取的 tokenD 作为参数
9 再添加一个查看结果树，然后执行
10 如果断言没有错误，则表示执行成功（也可以看查看树具体的请求和响应来判断）
11 大概就是这么一个步骤

### 16、请简述一下 cookie、session 以及 token 的区别？

**答：**
(1)cookie 数据存放在客户的浏览器上，session 数据放在服务器上。而 token 是接口测试时的鉴权码（令牌），一般情况下登陆后才可以获取到 token，然后在每次请求接口时需要带上 token 参数。
(2)cookie 不是很安全，别人可以分析存放在本地的 cookie 并进行 cookie 欺骗，考虑到安全应当使用 session，session 会在一定时间内保存在服务器上。当访问增多，会比较占用你服务器的性能，考虑到减轻服务器性能方面应当使用 cookie
(3)可以将登陆信息等重要信息存放为 session；其他信息需要保存，可以放在 cookie
1. 由于 HTTP 协议是无状态的协议，所以服务端需要记录用户的状态时，就需要用某种机制来识具体的用户，这个机制就是 Session.
2. Session.是在服务端保存的一个数据结构，用来跟踪用户的状态.
3. Cookie 是客户端保存用户信息的一种机制，用来记录用户的一些信息，也是实现 Session 的一种方式
4. Token 是服务端生成的一串字符串，以作客户端进行请求的一个令牌，当第一次登录后，服务器生成一个 Token 便将此 Token 返回给客户端，以后客户端只需带上这个 Token 前来请求数据即可，无需再次带上用户名和密码。

## 第八部分：Jmeter 性能测试

### 1、怎么做性能测试？性能测试流程？jmeter 怎么用的？（给一个网站你怎么做性能测试？你这个 XX 项目的性能是怎么做的？）

**答：** Jmeter 是一个开源测试工具，可以用来做性能测试（或接口测试）。
1) 我们先要熟悉性能测试需求
2) 然后制定相应的性能测试计划
3) 编写相应的性能测试用例
4) 打开 jmeter，添加线程组、http,cookies 管理器，http 信息头管理器，然后添加 http 请求
5) 编写测试脚本，对脚本进行参数化、添加事务、集合点、关联、断言以及各种监听器包括 TPS、响应时间等。
6) 再设置线程数模拟多用户，再设置一个压测时间进行性能测试。
7) 最后分析性能测试结果，将结果写入测试报告中。

### 2、性能测试怎么分析的？怎么判断系统存在瓶颈？

**答：** 主要看性能指标曲线走势图、以及事务响应时间图来分析的，我们一般通过不断的增加用户数增加系统负载来测试，观察系统的性能指标如 TPS/HPS /吞吐量等的变化情况，观察当负载逐渐加大时，曲线图的走势是否和压力成正比，如成正比上升则被测程序正常，表示还可以增加容量，我们还可以继续加大压力，如果观察到系统响应时间变长了，同时这些指标的曲线上升变化开始缓慢，走势变得平摊，甚至开始下降了，则说明系统遇到瓶颈了。

### 3、Jmeter 怎么参数化？会参数化吗？

**答：** Jmeter 参数化一般有 2 个方式，文本参数化和数据库参数化
1) 文本参数化我们一般通 CSV 配置元器件元件来实现的，通过 csv 或 txt 实现参数化，还可以通过函数助手实现参数化。
2) 数据库参数化，则是通过 JDBC 的两个元件来实现，JDBC 配置元件用于连接数据库的，JDBC 请求元件用户获取数据（select 语句）都是使用它们的变量名称替换脚本中静态的值，就可以达到参数化目的的。

### 4、性能指标有哪些（做性能测试分析哪些参数？）

**答：**
1) Average Transaction Response Time（响应时间：平均事务响应）：场景运行期间每秒内的事务执行时所花费的平均时间。时间越小说明系统处理速度越快。
2) Transactions per Second（TPS 每秒事务数）：系统每秒内处理事务的最大能力。这个数值越高，说明系统处理能力越强。
3) Hits per Second（HPS 每秒点击数）：当前负载对系统所产生的点击量记录，是虚拟用户每秒向服务器提交的 HTTP 请求数。这是数值越高越好，说明系统处理能力强。
4) Throughput（吞吐量） 一般单位是 字节 Byte/秒 ，也可是 MB/s：单位时间内通过网卡数据量之和，在单位时间内，系统能处理的吞吐量越大，表明系统的性能越好
5) CPU 利用率 ---看 cpu 占用率多少 %Processor Time 处理器时间：利用率应 < 80%
6) memory 内存利用率—看可用内存剩余多少 Avaiable Mbytes （可用内存）：可用内存利用率 < 90%
7) disk 磁盘读写速度—磁盘读写速度占用时间 %Disk Time 磁盘使用时间：利用率应 < 30%
8) network 网络占用率-- 流进网卡每秒流量 /网络带宽大小Bytes Total /sec 每秒总流量：占用率 < 50%
9) 错误率：金融项目错误率 0，一般项目错误率 5%以下

### 4-1：响应时间不达标如何分析原因？

**答：**
*   **网络差**：查看事务所消耗的时间主要在网络传输导致的还是服务器导致的，如果是网络，就结合 Throughput(网络吞吐量)图，计算带宽是否存在瓶颈。
*   **CPU 或内存使用率过高**：如果主要时间是消耗在服务器上，就要分别查看 web 服务器和数据库服务器的 CPU，内存的使用率是否过高。

### 4-2 什么是响应时间？

**答：**
*   应用系统从用户发出请求开始，到客户端接收到所有数据所消耗的时间。
*   网页响应时间可以细分为网络传输时间、DNS 解析时间、应用服务器处理时间、数据库处理时间等。

### 5、TPS、用户数（或者性能指标）是怎么来的、设计的？

**答：**
*   **新系统**：TPS 数、并发用户数是需求定义的（或测试计划中定义好的）。
*   **旧系统**：（高峰时间可通过日志判断，最大访问量就为高峰期）
    *   并发用户数：取高峰时刻在线用户数的 5%
    *   TPS：取高峰时期 10 分钟内的 TPS（平均值）

### 6、性能测试时，你发现了什么问题，这些问题是如何解决的？

**答：**
1）页面请求超时 （通过查看页面细分图，可定位究竟在哪个子请求存在超时情况，然后通知开发定位修改）
2）事务成功率下降 （部分业务处理失败、可能是数据库连接池设置过低（TCP连接数），服务器连接数超过上限（TCP），数据库锁控制考虑不足、接近瓶颈值等、 降低并发数）
3）内存泄漏 （主要看私有内存是否一致上升，可用内存却一直下降，则表明存在内存泄漏，解决方式，暂时解决重启系统，找开发定位问题修改代码了）
4） CPU 利用率偏高（比如：高并发导致CPU使用率过高,程序死循环-算法）
5） 日志打印过多，服务器无硬盘空间 （减少打印量，或者定时清空前面旧日志）
6） 数据库死锁，导致业务执行失败 （在设计时候操作数据库要考虑对业务表上锁，以防止发生死锁情况，也可手动解锁unlock ）

### 32、 什么是内存泄露？（必问）

**答：** 指程序运行时分配了内存，但是在程序结束时没有释放这部分内存，从而造成这一部分内存不可用的情况。

### 33、 怎么判断存在内存泄露？

**答：**
**答案一：** 先运行这个程序一段时间，观察内存曲线的使用情况，然后关闭这个程序，检查内存曲线的使用情况是否会下降到之前的状态，如果没有恢复到之前的水平，则该程序存在内存泄露。
**答案二：** 内存溢出是指程序在申请内存时，没有足够的内存空间供其使用的情况；内存泄露是指程序运行时分配了内存，但是在程序结束时没有释放这部分内存，导致这部分内存不可用的情况。

### 34、什么是内存溢出？

**答：** 是指程序在申请内存时，没有足够的内存空间供其使用的这种情况 ( 或者说出现 out of memory 这种情况)。
**内存的溢出，什么原因导致的？**
（加载的数据量太大，超过分配的内存了；对象引用后未及时释放，查询数据库没有及时关闭连接、死循环等）

### 36、 什么是性能测试、负载测试、压力测试？

**答：**
*   **负载测试**：在一定的负荷下，观察给系统造成的影响及系统响应的时间。目标是测试当负载逐渐增加时，观察系统各项性能指标的变化情况。
*   **压力测试**：在一定的负荷条件下，长时间连续运行给系统性能造成的影响。（目标是测试在一定的负载下系统长时间运行的稳定性，考察各项性能指标是否在指定范围内，有无内存泄漏、有无功能性 bug）
*   **容量测试**：确定系统可处理极限值，使系统承受超额的数据容量来发现它是否能够正确处理。（容量测试就是用来确定极限值，短时间的测试，比如能承受多少用户并发量，这就是容量）
*   **稳定性测试**：通过给系统加载一定的业务压力（如 CPU 资源在 70% - 90%的使用率）的情况下，运行一段时间（7*24 小时），检查系统是否稳定。
*   **并发测试**：是测试多个用户同时访问同一个应用、同一个模块时是否存在性能问题。

## 44、简述性能测试流程？结合项目（你是如何做性能测试的）

### 答：

### 一、分析性能需求

我上一个项目做的是港银交易系统的性能测试，主要是挑选用户使用最频繁的场景来测试，先做单一场景，比如用户登录、买股票、卖股票、查询交易记录。在做复合场景：登录与买卖股票，买卖股票与查询股票。

确定性能指标，比如：

- 事务通过率为 **100%**
    
- 响应时间是 **5 秒以内**
    
- 最大并发用户为 **1000 人**
    
- **CPU** 和内存的使用率在 **70% 以下**
    

---

### 二、测试前的准备工作

功能测试全部通过，确保功能上没有问题；环境也要搭建好。

#### （1）硬件环境

包括服务器环境、客户端环境与网络环境，要保证服务器的型号以及是否和其它应用程序共享此服务器；如有架设负载均衡，要保证有相同的部署和配置；网络部件保证相同。

#### （2）软件环境

要保证操作系统、数据库、应用软件的版本一致性，测试环境服务器安装成功，服务布置成功。

---

### 三、编写测试脚本

可以手写脚本，也可以在 **JMeter** 里面设置代理进行录制脚本。

---

### 四、脚本增强和优化

设置检查点、参数化、关联、集合点、事务，调整思考时间，删除冗余脚本。

- 如需考虑并发，则加入集合点
    
- 考察某一部分业务处理响应时间，则需要插入事务
    
- 为检查系统是否进行正确的执行而考虑断言
    
- 输入不同的业务数据，则需要进行参数化
    
- 为解决脚本中存在的动态数据问题，需要进行关联
    

在登录、买入股票提交、卖出股票提交、查询交易记录业务上设置集合点，因为这些业务是核心业务，其业务响应时间直接反应了用户的体验。

在登录这一事务后建议插入检查点，因为登录后显示的欢迎词、图片等是作为判断是否登录成功的依据。

登录的用户名和密码应该进行参数化，否则无法模拟多个用户同时登录的场景。

将买入股票部分生成事务，将卖出股票也生成事务，这样则可以在测试可以准确分析买入股票、卖出股票的单一事务响应时间等指标。

---

### 五、设计测试场景

尽量模拟真实场景下用户的使用情况，使用频繁的业务。

比如客户在 **8:55 – 9:05** 的大约 **10 分钟** 时间内将有 **200 个用户并发登录**，业务峰值保持 **300 分钟**，我们场景的设计就要依这个作为依据进行。

先做单一场景，比如用户登录、买股票、卖股票、查询交易记录。  
再做复合场景：登录与买卖股票，买卖股票与查询股票。

---

### 六、执行性能测试

在 **JMeter** 中把脚本调通，在非 **GUI** 模式下跑脚本，进行性能测试。

在时间充裕的情况下，最好执行 **3 次**，**3 次结果相近**才证明测试是成功的。

---

### 七、性能测试数据分析

脚本在 **JMeter** 里面跑完后，会生成相关性能测试数据，进行数据分析，定位性能问题。

随着压力的增大，某个资源的使用达到了极限，系统性能出现急剧下降，于是产生了“拐点”现象。当得到“拐点”附近的资源使用情况时，就能定位出系统的性能瓶颈。

在聚合报告中：

- 事务的最大、最小响应时间有一定的参考意义
    
- 平均响应时间是比较关键的指标项，反应的是总体水平
    
- **90%** 反应的是大部分的事务响应时间，通常不应该超过 **10 秒**
    
- 通过的事务数、失败的事务数是系统处理能力
    
- 吞吐量反应了在该设计场景下系统能够完成的业务交易量
    
- 正确率要达到 **90%**，错误率不超过 **10%**
    

---

### 八、性能调优与回归测试

根据测试的结果，找出系统瓶颈，开发人员对系统进行调整以后，继续进行第二轮、第三轮测试。

每一轮测试后与以前的测试结果进行对比，从而确定经过调整以后系统的性能是否有提升。

对于调整的策略，通常一次调整一项内容或者一类内容，以避免一次调整多项内容而引起性能提高却不知道是由于调整哪一项关键指标而改善性能的。

调优有由易到难的顺序是：

1. 硬件（Hardware）问题
    
2. 网络（Network）问题
    
3. 应用服务器、数据库服务器等的配置问题
    
4. 源代码、数据库脚本问题
    
5. 系统架构问题
