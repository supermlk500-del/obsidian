| 列名               | 含义                  | 备注                                                |
| :--------------- | :------------------ | :------------------------------------------------ |
| **#**            | Fiddler为会话生成的ID号    | 方便用户追踪会话 [1]                                      |

| **Content-Type** | 响应头的`Content-Type`值 | 例如 `text/html`, `image/*`, `application/json` [1] |
| **Comments**     | 通过脚本或右键添加的注释信息      |                                                   |

### 这里是几个选项的区别

| **选项**              | **快捷键**         | **含义**                                    | **视觉图标 (Session List)** | **常用场景**                                       |
| ------------------- | --------------- | ----------------------------------------- | ----------------------- | ---------------------------------------------- |
| **Before Requests** | **F11**         | **请求前断点**：数据还没发给服务器。此时请求停在 Fiddler 中。     | 🔴 (图标左侧有红色盾牌/T型)       | **篡改请求参数**。比如：修改购买数量、修改支付金额、修改用户 ID 等。         |
| **After Responses** | **Alt + F11**   | **响应后断点**：服务器已处理完并返回了数据，但数据还没传给你的浏览器/App。 | ⏸️ (图标右侧有红色盾牌/T型)       | **篡改返回结果**。比如：把余额 0 元改写成 100 万、伪造服务器报错、修改状态码等。 |
| **Disabled**        | **Shift + F11** | **禁用断点**：关闭所有自动拦截模式，恢复正常的网络抓包状态。          | (恢复普通图标)                | 调试完成后，恢复正常抓包逻辑。                                |

#### 🤖 AutoResponder 是什么意思？

如果说“断点”是**手动拦截**（你得停下来自己改），那么 **AutoResponder** 就是**自动拦截并替换**。

它允许你定义一套规则：**“只要发现请求符合 A 条件，就自动给它返回 B 内容”**，而不需要请求真正到达服务器。

### 核心功能拆解

- **Mock 数据（模拟数据）**：当后端接口还没写好时，你可以用 AutoResponder 自己造一个 JSON 响应，让前端先跑起来。
    
- **重定向资源**：把你图中的 `www.baidu.com` 直接定向到你电脑上的一个本地 HTML 文件。
    
- **模拟弱网或错误**：自动让某个接口返回 404 或 500 错误，测试 App 的崩溃处理能力。
