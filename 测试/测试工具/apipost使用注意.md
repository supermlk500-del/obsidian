# 两种存储数据的方式

## 一、CSV（Comma-Separated Values）

### 1️⃣ 概念

**CSV** 是一种用**分隔符（通常是逗号）**来表示数据的**纯文本格式**，  
本质上就是一张“没有样式的表格”。

📌 一行 = 一条记录  
📌 一列 = 一个字段

---

### 2️⃣ 基本结构示例

```csv
id,name,age,city
1,Tom,18,Beijing
2,Alice,20,Shanghai
3,Bob,22,Shenzhen
```

---

### 3️⃣ 特点

✅ 结构简单，易读易写  
✅ 占用空间小，适合大量数据  
❌ 只能表示**表格型数据**  
❌ 不支持层级、嵌套结构  
❌ 数据类型不明显（全是字符串）

---

### 4️⃣ 常见使用场景

- Excel / WPS 表格数据导入导出
    
- 测试数据准备（接口测试、参数化）
    
- 日志数据、批量数据交换
    
- 数据分析（Python、Pandas 常用）
    

---

### 5️⃣ 测试视角注意点（重点 ⭐）

- 是否包含**表头**
    
- 分隔符是 `,` 还是 `;`
    
- 是否有**空值**
    
- 是否存在**中文乱码**
    
- 行数是否正确（是否丢数据）
    

---

## 二、JSON（JavaScript Object Notation）

### 1️⃣ 概念

**JSON** 是一种**轻量级数据交换格式**，  
以 **键值对（key-value）** 形式存储数据，支持**嵌套结构**。

---

### 2️⃣ 基本结构示例

```json
{
  "id": 1,
  "name": "Tom",
  "age": 18,
  "city": "Beijing"
}
```

数组形式：

```json
[
  {
    "id": 1,
    "name": "Tom"
  },
  {
    "id": 2,
    "name": "Alice"
  }
]
```

---

### 3️⃣ 特点

✅ 支持对象、数组、嵌套  
✅ 数据结构清晰，可读性强  
✅ 天然适合接口传输  
❌ 相比 CSV 文件体积更大  
❌ 对格式要求严格（少个逗号直接报错）

---

### 4️⃣ 常见使用场景

- 前后端接口数据传输
    
- 配置文件（如 `config.json`）
    
- 接口自动化测试数据
    
- NoSQL 数据库存储格式
    

---

### 5️⃣ 测试视角注意点（重点 ⭐）

- JSON 是否**格式正确**
    
- 字段是否缺失 / 多余
    
- 字段类型是否符合接口要求
    
- 嵌套层级是否正确
    
- 数组为空、null、不存在的区别
    

---

## 三、CSV vs JSON 对比表

|对比项|CSV|JSON|
|---|---|---|
|数据结构|表格|对象 / 数组|
|支持嵌套|❌ 不支持|✅ 支持|
|可读性|一般|好|
|文件大小|小|较大|
|数据类型|不明显|明确|
|典型用途|表格、测试数据|接口、配置|

---

## 四、总结一句话记忆

- **CSV**：👉 “表格型数据，简单高效”
    
- **JSON**：👉 “结构化数据，接口之王”
