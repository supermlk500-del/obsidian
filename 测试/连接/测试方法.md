## 一、等价类划分（★★★★★ 重点）

### 1️⃣ 是什么

**等价类划分**：  
把所有可能的输入数据划分成若干“等价”的集合，在同一个集合中，**任取一个数据，系统处理结果是一样的**。

👉 核心思想：

> **用最少的测试用例，覆盖最多的情况**

---

### 2️⃣ 分类

- **有效等价类**：合法、符合需求的数据
    
- **无效等价类**：非法、不符合需求的数据
    

---

### 3️⃣ 怎么用（步骤）

1. 找输入条件
    
2. 划分有效 / 无效等价类
    
3. 每个等价类至少选 **1 个代表值**
    
4. 组合成测试用例
    

---

### 4️⃣ 举例

**需求**：

> 年龄范围：18～60 岁

- 有效等价类
    
    - 18～60
        
- 无效等价类
    
    - <18
        
    - > 60
        
    - 非数字 / 空
        

**测试值示例**：

- 20（有效）
    
- 10（无效）
    
- 70（无效）
    
- abc（无效）
    

---

### 5️⃣ 使用场景 / 面试说法

- 表单输入
    
- 接口参数校验
    
- 配合边界值一起用
    

📌 面试金句：

> 等价类划分用于减少测试用例数量，提高测试效率。

---

## 二、边界值分析（★★★★★ 重点）

### 1️⃣ 是什么

**边界值分析**：  
错误**最容易出现在边界附近**，所以重点测边界。

---

### 2️⃣ 核心原则

> **边界 + 边界内 + 边界外**

通常测试 5 个值：

- 最小值
    
- 最小值+1
    
- 正常值
    
- 最大值-1
    
- 最大值
    

---

### 3️⃣ 举例

**需求**：密码长度 6～12 位

| 类型    | 示例  |
| ----- | --- |
| 最小值-1 | 5   |
| 最小值   | 6   |
| 正常值   | 8   |
| 最大值   | 12  |
| 最大值+1 | 13  |

---

### 4️⃣ 使用场景 / 面试要点

- 数值范围
    
- 字符长度
    
- 次数、金额、时间
    

📌 面试常问：

> 边界值是等价类的一种特殊情况。

---

## 三、错误推测法（★★★★☆ 重点）

### 1️⃣ 是什么

**错误推测法**：  
基于经验、直觉、历史 bug，**“猜系统可能会错在哪里”**。

---

### 2️⃣ 常见错误来源

- 空值 / null
    
- 特殊字符（!@#￥%）
    
- 超长输入
    
- 重复提交
    
- 网络异常
    
- 并发操作
    

---

### 3️⃣ 举例

登录功能可能的错误：

- 用户名为空
    
- 密码为空
    
- 连续点击登录
    
- 输入 emoji
    
- SQL 注入字符
    

---

### 4️⃣ 使用场景 / 面试说法

- 经验型测试
    
- 回归测试
    
- 探索式测试
    

📌 面试加分说法：

> 错误推测法依赖测试经验，无法穷举，但对发现隐藏 bug 非常有效。

---

## 四、判定表法（★★★★★ 重点）

### 1️⃣ 是什么

**判定表法**：  
当**条件组合很多，规则复杂**时，用表格来表示「条件 → 动作」。

---

### 2️⃣ 适合什么场景

- 多条件、多规则判断
    
- if-else 特别多
    
- 业务规则复杂
    

---

### 3️⃣ 判定表组成

- 条件桩（条件）
    
- 动作桩（结果）
    
- 条件项 / 动作项
    

---

### 4️⃣ 举例

**需求**：

> 是否允许下单

- 是否登录
    
- 是否有库存
    

| 是否登录 | 是否有库存 | 是否允许下单 |
| ---- | ----- | ------ |
| 是    | 是     | 允许     |
| 是    | 否     | 不允许    |
| 否    | 是     | 不允许    |
| 否    | 否     | 不允许    |

---

### 5️⃣ 面试要点

📌 常问：

> 什么情况下用判定表？  
> ✔ 条件之间有组合关系时

---

## 五、正交实验法（★★★★☆ 重点）

### 1️⃣ 是什么

**正交实验法**：  
当参数很多、每个参数取值也很多时，  
**用最少的组合覆盖最多的情况**。

---

### 2️⃣ 核心思想

> 不测试所有组合，而是选“最有代表性”的组合

---

### 3️⃣ 举例

一个 App 有：

- 手机型号：3 种
    
- 系统版本：3 种
    
- 网络环境：3 种
    

👉 全组合：27 种  
👉 正交实验：可能只测 9 种

---

### 4️⃣ 使用场景

- 兼容性测试
    
- 配置组合测试
    
- 性能测试
    

---

### 5️⃣ 面试说法

📌

> 正交实验法可以在保证覆盖率的前提下，大幅减少测试用例数量。

---

## 六、场景法（★★★★★ 重点）

### 1️⃣ 是什么

**场景法**：  
从**用户真实使用流程**出发，设计测试用例。

---

### 2️⃣ 核心概念

- **基本流**：正常流程
    
- **备选流**：异常 / 分支流程
    

---

### 3️⃣ 举例（电商下单）

**基本流**：

1. 登录
    
2. 搜索商品
    
3. 加入购物车
    
4. 下单
    
5. 支付成功
    

**异常流**：

- 未登录下单
    
- 库存不足
    
- 支付失败
    
- 网络中断
    

---

### 4️⃣ 使用场景 / 面试要点

- 业务测试
    
- 端到端测试
    
- 验收测试
    

📌 面试金句：

> 场景法更贴近真实用户行为，常用于业务流程测试。

---

## 总结速记版（面试秒答）

| 方法   | 关键词  |
| ---- | ---- |
| 等价类  | 减少用例 |
| 边界值  | 容易出错 |
| 错误推测 | 经验   |
| 判定表  | 多条件  |
| 正交实验 | 多参数  |
| 场景法  | 用户流程 |
