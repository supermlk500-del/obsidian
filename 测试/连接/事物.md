# 一、什么是事务（核心概念）

### ✅ 标准定义（必背）

> **事务（Transaction）是数据库中对数据进行操作的一个逻辑执行单元，由一组 SQL 语句组成，这组语句要么全部成功执行，要么全部失败回滚，用来保证数据的一致性和安全性。**

---

### ✅ 通俗理解

> **事务 = 打包执行的一组数据库操作**

- 不允许“做一半”
    
- 成功 → 一起生效
    
- 失败 → 全部撤销
    

---

# 二、为什么需要事务？

如果**没有事务**，会出现：

- 转账只扣钱，没加钱 ❌
    
- 订单生成了，库存没减 ❌
    
- 数据做到一半系统崩溃 ❌
    

👉 **事务的作用：防止数据“半成品状态”**

---

# 三、事务的四大特性（ACID）

这是事务最核心的理论内容 ⭐⭐⭐

## 1️⃣ 原子性（Atomicity）

> 事务中的操作是一个整体，不可再分割

- 成功：全部执行
    
- 失败：全部撤销（ROLLBACK）
    

---

## 2️⃣ 一致性（Consistency）

> 事务执行前后，数据库从一个合法状态变到另一个合法状态

例如：

- 余额不能变成负数
    
- 主键不能重复
    

---

## 3️⃣ 隔离性（Isolation）

> 多个事务并发执行时，彼此互不干扰

一个事务未提交：

- 其他事务一般看不到中间结果
    

---

## 4️⃣ 持久性（Durability）

> 事务一旦提交，数据永久保存

即使：

- 服务器断电
    
- 数据库重启  
    数据也不会丢失
    

---

# 四、事务的基本操作（MySQL）

```sql
START TRANSACTION;   -- 开启事务

-- 一组 SQL 操作
UPDATE ...
INSERT ...

COMMIT;              -- 提交（生效）
ROLLBACK;            -- 回滚（撤销）
```

---

# 五、事务的执行流程（理解版）

1️⃣ 开启事务  
2️⃣ 执行多条 SQL  
3️⃣ 判断是否出错

- 没问题 → COMMIT
    
- 出错 → ROLLBACK

# 六、事务与存储引擎的关系（重点）

### ✔ 支持事务的引擎

- **InnoDB**（默认，常用）
    

### ❌ 不支持事务的引擎

- MyISAM
    

👉 **实际开发中：必须使用 InnoDB**

# 七、事务的隔离级别（事务相关的重要内容）

事务并发时可能产生的问题：

|问题|说明|
|---|---|
|脏读|读到未提交的数据|
|不可重复读|同一数据多次读取结果不同|
|幻读|多出或少了几行|

---

### MySQL 的 4 个隔离级别（从低到高）

|隔离级别|能否避免问题|
|---|---|
|READ UNCOMMITTED|几乎不隔离|
|READ COMMITTED|避免脏读|
|REPEATABLE READ（默认）|避免脏读、不可重复读|
|SERIALIZABLE|完全隔离|

---

# 八、事务的使用注意事项（易错点）

### ❗1️⃣ DDL 语句不能回滚

以下语句会 **自动提交事务**：

```sql
CREATE
DROP
ALTER
TRUNCATE
```

---

### ❗2️⃣ 只有 InnoDB 才支持事务

```sql
SHOW TABLE STATUS;
```

---

### ❗3️⃣ 自动提交问题

MySQL 默认：

```sql
autocommit = 1
```

关闭自动提交：

```sql
SET autocommit = 0;
```

# 十、一句话总结（终极版）

> **事务是数据库中保证一组操作要么全部成功、要么全部失败的机制，通过 ACID 特性确保数据的一致性、安全性和可靠性。**
