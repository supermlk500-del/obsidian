## 第一部分：Selenium 自动化元素定位与交互

### 0. 导入必备模块
```python
## 只需要导入这三个，足够应对大部分场景
import time
from selenium import webdriver
from selenium.webdriver.common.by import By
```
> **⚠️ 导入注意事项：**
> - 不要导入用不到的模块。例如 `from re import search`（定位元素用不到）或 `from selenium.webdriver.common.devtools.v148.dom import BackendNode`（与浏览器特定版本强绑定，更新浏览器就会报错）。
> - 后续如果用到显式等待，再追加导入 `WebDriverWait` 和 `expected_conditions as EC`。

### 1. 元素定位的 8 种方法

#### 1.1 根据 id 定位 (By.ID) - ⭐ 首选
```python
driver = webdriver.Edge()
driver.get("https://www.sogou.com")

# 💻 实操：搜狗的输入框 id="query"，搜索按钮 id="stb"
inputBox = driver.find_element(By.ID, "query")
inputBox.send_keys("mlksuper.top")

searchBtn = driver.find_element(By.ID, "stb")
searchBtn.click()
```
> **⚠️ 避坑：** 现代前端框架（Vue/React等）经常生成**动态 ID**（例如 `id="el-dialog-2345"`，刷新后数字会变）。遇到规律性变化的 ID 坚决不用。

#### 1.2 根据 name 定位 (By.NAME)
```python
# 💻 实操：搜狗的输入框恰好 name 也是 "query"
inputBox = driver.find_element(By.NAME, "query")
inputBox.send_keys("mlksuper.top")
```
> **⚠️ 注意：** name 属性不一定是唯一的。如果有多个相同的 name，`find_element()` 只会返回找到的第一个。

#### 1.3 根据 class name 定位 (By.CLASS_NAME)
```python
# 💻 实操：百度AI搜索框完整 class 为 "chat-input-textarea chat-input-scroll-style"
# 只能取其中一个唯一的单词来定位
inputBox = driver.find_element(By.CLASS_NAME, "chat-input-textarea")
```
> **⚠️ 致命避坑：绝对不能使用复合类名！** 如果写成 `By.CLASS_NAME, "btn btn-primary large"`（包含空格）会直接抛异常。如需组合，请用 CSS 选择器。

#### 1.4 XPath 定位 (By.XPATH) - ⭐ 最万能
支持路径、属性、逻辑组合和**文本匹配**，能解决 90% 的疑难杂症。
```python
# 绝对路径极度脆弱，坚决不用！例如：/html/body/div/input
# 永远使用 // 开头的相对路径

# 💻 实操：XPath 的三种常见组合方式
# ① 路径 + 属性组合：
driver.find_element(By.XPATH, '//span[@class="sec-input-box"]/input')

# ② 路径 + 索引 (注意: XPath 索引从 1 开始！)：
driver.find_element(By.XPATH, '//span[1]/input')

# ③ contains 模糊匹配属性或文本：
driver.find_element(By.XPATH, '//a[contains(@href,"zhihu")]')
driver.find_element(By.XPATH, '//*[contains(text(), "登录")]')
```

#### 1.5 CSS 选择器定位 (By.CSS_SELECTOR) - ⭐ 最快
语法简洁，浏览器原生引擎解析，速度最快。完美解决复合类名问题。**唯一弱点是不支持文本匹配。**
```python
# 💻 实操：CSS 选择器的多种写法对比 (均定位同一元素)
driver.find_element(By.CSS_SELECTOR, '#query')              # ① ID选择器（#）
driver.find_element(By.CSS_SELECTOR, '.sec-input')          # ② Class选择器（.）
driver.find_element(By.CSS_SELECTOR, 'input[type="text"]')  # ③ 属性选择器
driver.find_element(By.CSS_SELECTOR, 'span[class="box"] > input')  # ④ 层级选择器

# 💻 实操：按同类标签顺序定位 (类似 XPath 索引)
driver.find_element(By.CSS_SELECTOR, 'span:nth-of-type(1) > input')
```

#### 1.6 其他定位方法
- **By.TAG_NAME (标签名)**：极少用于单个元素，通常配合 `find_elements` 抓取一组。
- **By.LINK_TEXT (超链接纯文本)**：仅对 `<a>` 标签有效，必须精确匹配完全可见的内容。
- **By.PARTIAL_LINK_TEXT (超链接部分文本)**：模糊匹配，确保截取的片段在页面上足够独特。

#### 📌 单个 vs 多个元素
- `find_element()`：返回第一个 WebElement。找不到抛出 `NoSuchElementException` 异常导致程序崩溃。
- `find_elements()`：返回列表 (list)。找不到返回空列表 `[]`，**不会抛出异常**。（常用于断言元素是否存在）。

### 2. 常见等待方式 (极其重要)
为了解决"代码执行过快，页面元素还没加载出来就去定位导致报错"的问题。

```python
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

# 1. 强制等待 (死等，浪费时间)
time.sleep(3)

# 2. 隐式等待 (全局生效，轮询DOM树，找不到最多等10秒)
driver.implicitly_wait(10)

# 3. 显式等待 (针对某个具体元素的高级等待，企业实战首选)
wait = WebDriverWait(driver, 10)
element = wait.until(EC.presence_of_element_located((By.ID, "query")))
```
> **⚠️ 避坑指南：**
> - **隐式和显式尽量不要混用！** 混用可能导致底层超时时间叠加出现难以排查的 Bug。
> - 强烈建议封装 **显式等待**：它能指定条件（如 `visibility_of_element_located` 等待可见，`element_to_be_clickable` 等待可点），抗网络波动能力最强。

### 3. 高阶交互操作实战

#### 3.1 元素基础操作
```python
inputBox.send_keys('mlksuper.top') # 输入文本
inputBox.clear()                   # 清除输入框内容
searchBtn.click()                  # 点击元素
text = element.text                # 获取元素的可见文本内容
```
> **⚠️ 注意：** `element.text` 只能获取元素在页面上可见的文本。如果要获取输入框里填的值，应该用 `element.get_attribute("value")`。

#### 3.2 鼠标悬停 (ActionChains)
必须鼠标移上去才显示的菜单，直接定位会报"不可见"错误。
```python
from selenium.webdriver import ActionChains

more = WebDriverWait(driver, 1).until(EC.visibility_of_element_located((By.XPATH, '...')))
# 把鼠标移动到元素上悬停
ActionChains(driver).move_to_element(more).perform()
```
> **⚠️ 避坑：** 链式操作最后一定要加上 `.perform()`，否则动作绝对不会执行！

#### 3.3 Iframe 表单嵌套切换
页面中如果有 `iframe`，**必须先切进去才能定位里面的元素！**
```python
# 【优雅写法】等待 iframe 加载并直接切进去
vipBtnIframe = (By.CSS_SELECTOR, 'iframe[id^="x-URS-iframe"]')
WebDriverWait(driver, 10).until(
    EC.frame_to_be_available_and_switch_to_it(vipBtnIframe)
)

# 此时可以定位 iframe 内部元素了...

# 操作完毕，切回主页面默认表单：
# driver.switch_to.default_content() 
```

#### 3.4 多标签页窗口切换
点击链接弹出了新标签页，Selenium 的控制权默认还在老页面，必须切句柄。
```python
# 获取所有窗口的句柄 (返回类似: ['CDwindow-8C9...', 'CDwindow-34A...'] 的列表)
allHandle = driver.window_handles

# 切换到第二个窗口（索引 1）
driver.switch_to.window(allHandle[1])

# 此时控制权到了新页面，可以定位新页面的元素了
```

#### 3.5 标准下拉菜单 (Select)
```python
from selenium.webdriver.support.select import Select

selectorBox = wait.until(EC.visibility_of_element_located((By.CSS_SELECTOR, '[id="s1"]')))

# 三种选择方式：
Select(selectorBox).select_by_index(5)           # 按索引 (从0开始)
Select(selectorBox).select_by_value('46')        # 按 option 的 value 属性
Select(selectorBox).select_by_visible_text("Fax")# 按页面显示的文本 (最直观常用)
```
> **⚠️ 注意：** 仅限 `<select>` 标签。现代框架用 div 拼凑的假下拉框无效，必须分两步 click（先点展开，再点选项）。

### 4. 【核心工程化思想】PO 模式 (Page Object Model) 抽取模板

随着项目越来越大，把定位和断言全写在 `test_` 文件里会导致代码冗余极高，维护简直是灾难。**PO 模式** 是企业级自动化测试的灵魂，它的核心思想是：**页面元素操作与测试逻辑(业务用例)分离**。

以下是结合日志记录 (`logging`) 的**企业级三层架构模板**：

#### 4.1 第一层：BasePage (基类封装层)
**职责**：封装所有页面共用的底层操作（显式等待、异常捕获、日志记录）。其他所有具体的页面类都要继承它。
> **💡 DRY 原则 (Don't Repeat Yourself)**：底层包好后，上层业务无需操心元素到底有没有出现。同时，每次点击或输入都会被自动记入日志！

```python
# base_page/basePage.py
from selenium.common.exceptions import TimeoutException
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.support.wait import WebDriverWait
from utils.log_util import logger

class BasePage:
    def __init__(self, driver, timeout=10):
        self.driver = driver
        self.wait = WebDriverWait(self.driver, timeout)

    def find_element(self, locator):
        """等待并返回元素，包含异常处理和日志"""
        try:
            logger.debug(f"查找元素: {locator}")
            element = self.wait.until(EC.presence_of_element_located(locator))
            logger.debug(f"元素 {locator} 查找成功")
            return element
        except TimeoutException:
            logger.exception(f"等待元素超时: {locator}")
            raise  # 把异常抛给用例让它失败

    def click_element(self, locator):
        """带有可点击状态检查的安全点击"""
        logger.debug(f"点击元素: {locator}")
        try:
            self.wait.until(EC.element_to_be_clickable(locator)).click()
            logger.debug(f"元素 {locator} 点击成功")
        except TimeoutException:
            logger.exception(f"等待可点击元素超时: {locator}")
            raise

    def input_text(self, locator, text):
        logger.debug(f"向元素: {locator} 输入文本: {text}")
        element = self.find_element(locator)
        element.clear()
        element.send_keys(text)
        logger.debug(f"输入完毕")
```

#### 4.2 第二层：Page Object (页面对象层)
**职责**：一个真实的网页对应一个 Class。
1. **抽离定位器**：把页面上所有的元素定位（Locator）写在类属性里。以后前端改了元素属性，只需在这里改一次！
2. **封装业务动作**：将点击、输入等原子操作组合成业务动作（如 `login`），供第三层调用。

```python
# pages/loginPage.py
from selenium.webdriver.common.by import By
from base_page.basePage import BasePage

class LoginPage(BasePage):
    # 1. 纯数据：抽离页面元素定位器
    username_loc = (By.CSS_SELECTOR, '[name="username"]')
    password_loc = (By.CSS_SELECTOR, '[name="password"]')
    submitBtn_loc = (By.CSS_SELECTOR, '[name="submit"]')

    # 2. 封装业务动作：只调基类封装好的安全方法
    def login(self, username, password):
        """提供给外部调用的：一条龙登录操作"""
        self.input_text(self.username_loc, username)
        self.input_text(self.password_loc, password)
        self.click_element(self.submitBtn_loc)
```

#### 4.3 第三层：Test Case (测试用例层)
**职责**：真正的自动化测试用例。在这里组装数据、调用页面类的业务动作，并进行最终的**断言（Assert）**。
**完美效果**：用例代码看起来就像英语短文一样清晰，没有任何丑陋的 `find_element`。

```python
# test_cases/test_login.py
import pytest
from pages.loginPage import LoginPage

class TestLogin:
    # driver 从 conftest.py 的全局 fixture 里自动注入
    def test_login_success(self, driver):
        # 1. 实例化页面对象
        login_page = LoginPage(driver)
        
        # 2. 调用傻瓜式的业务流动作
        login_page.login("admin", "123456")
        
        # 3. 干净利落的断言
        assert login_page.get_text((By.XPATH, "//p")) == "登录成功"
```

> **🔥 整个 PO 模式的工作流闭环：**
> 测试用例 `test_login` 👉 实例化并调用 `LoginPage.login()` 👉 `LoginPage` 拿着类顶部的 `(By.ID, xxx)` 定位器去调用父类 `BasePage.input_text()` 👉 `BasePage` 打印日志，触发带显式等待的 `WebDriverWait` 并在浏览器上完成真实交互。
> 
> **这就是所有大厂 UI 自动化测试框架的标准骨架结构。**

## 第二部分：Pytest 自动化测试框架基础

Pytest 是目前最强大、流行的 Python 测试管理框架。

### 1. 基础编写规则
- **文件命名**：必须以 `test_` 开头（或 `_test.py` 结尾）。
- **类命名**：必须以 `Test` 开头，且**不能带有 `__init__` 构造方法**。
- **函数命名**：必须以 `test_` 开头。
- **断言机制**：摒弃了 unittest 繁琐的 assertEqual，全部使用原生的 `assert` 即可。

```python
def test_login():
    expected_res = '登录成功'
    actual_res = '恭喜.登录成功'
    
    # 判断包含关系
    assert expected_res in actual_res
    # 判断相等
    # assert expected_res == actual_res
```

### 2. pytest.ini 全局配置 (必须掌握)
在项目根目录下建立 `pytest.ini`，这是 Pytest 的心脏。它可以让你不需要每次都在命令行敲一堆参数。
```ini
[pytest]
# 指定默认执行的测试目录
testpaths = ./test_cases

# 更改默认的识别规则（比如你想让所有以 Test 打头的类都被识别）
python_files = test_*.py
python_classes = Test*
python_functions = test_*

# 预先注册自定义标记，解决控制台的 Warning 警告
markers =
    smoke: 标记冒烟测试用例
    regression: 标记回归测试用例
    performance: 标记性能测试用例

# 配置默认的执行参数 (例如 -vs 代表输出详细信息并打印 print)
addopts = -vs
```

### 3. 测试夹具 (Fixture) 与作用域 (Scope)
Fixture 用于数据共享、预置和清理（相当于 setUp 和 tearDown 的高级版）。

#### 3.1 四种作用域 (Scope) 的区别
在定义 fixture 时，可以通过 `scope` 参数指定该夹具的生命周期：
1. **`function`（默认）**：**函数级别**。每个测试用例（test_开头的函数）执行前后，都会运行一次 fixture。
2. **`class`**：**类级别**。整个测试类执行前后只会运行一次，不管类里面有多少个测试用例。非常适合做“打开浏览器/关闭浏览器”这类耗时操作。
3. **`module`**：**模块/文件级别**。整个 `.py` 测试文件执行前后运行一次。
4. **`session`**：**会话级别**。整个测试任务（可能包含几百个文件）启动和结束时只运行一次。通常写在专门的 `conftest.py` 文件中，用于做全局配置（如数据库连接、全局登录获取 Token）。

#### 3.2 conftest.py 与全局 Fixture
当你需要让所有测试文件都能共享同一个 Fixture 时，必须把它写在**名为 `conftest.py`** 的特殊文件里。Pytest 启动时会自动去扫这个文件，不需要你去 import 它！
```python
# test_cases/conftest.py
import pytest
from selenium import webdriver

# 【实战：基于类级别，一个测试类共用一个浏览器，执行完类中所有用例后再关闭】
@pytest.fixture(scope="class")
def driver():
    print('\n[环境预置] --> 打开浏览器')
    browser = webdriver.Edge()
    browser.maximize_window()
    browser.get("http://192.168.1.53/ecshop/")

    # yield 相当于 return，把初始化好的 browser 传给后面的页面对象使用
    yield browser

    print('\n[环境清理] --> 关闭浏览器')
    browser.quit()
```

#### 3.3 Fixture 实战用法 (在测试类中调用)
```python
class TestCreateTask:
    # 只需要在参数里写上 fixture 的函数名(driver)，即可自动触发并接收返回值
    def test_create_task(self, driver):
        print(f'接收到的浏览器对象是 : {driver}')
        assert True
        
    def test_delete_task(self, driver):
        print(f'用例2也会共享同一个浏览器对象 : {driver}')
        assert True
```
> **💡 小技巧 (autouse)：** 如果你在 `@pytest.fixture(autouse=True)` 中加了 `autouse=True`，这个 fixture 就会在指定的 scope 范围内**自动偷偷运行**，你甚至不需要在用例函数里把它的名字写到参数里。

### 4. 常用标记 (Marks)
用于分组运行、跳过用例或控制顺序。
```python
class TestMarks:
    # 1. 自定义分组标签（必须先在 pytest.ini 里注册）
    @pytest.mark.smoke
    def test_case_01(self):
        pass

    # 2. 条件跳过 (skipif) - 当条件满足时直接不执行
    @pytest.mark.skipif(1 == 1, reason='满足条件跳过此测试用例')
    def test_case_03(self):
        pass
        
    # 3. 控制执行顺序 (需要第三方插件)
    # @pytest.mark.run(order=1)
    def test_case_04(self):
        pass
```
> **⚠️ 避坑指南：**
> 控制执行顺序（如 `@pytest.mark.run(order=1)` 或 `@pytest.mark.order(1)`）**不是 Pytest 自带功能**，必须先执行 `pip install pytest-ordering` 插件才能生效！

### 5. 工程化利器：数据驱动与文件操作 (参数化)

Pytest 的精髓之一在于 `@pytest.mark.parametrize`，它可以让你将测试数据与测试逻辑分离（数据驱动测试）。搭配 YAML 等文件读取，可以实现灵活的自动化。

#### 5.1 获取项目绝对路径 (os.path)
在读写数据文件（如 YAML、Excel）时，为了防止代码换台电脑就报错，**绝对不能写死绝对路径**，必须通过代码动态获取项目根目录：
```python
import os

# __file__ 指代当前这个 Python 文件的路径
current_path = __file__

# os.path.dirname 可以获取当前文件的上一级目录
parent_path = os.path.dirname(current_path)

# 动态拼接出目标数据文件的绝对路径
# 假设当前文件在 utils 目录下，数据文件在同级的 data 目录下
def get_yaml_path(filename):
    # 向上返回两级，到达根目录
    root_path = os.path.dirname(os.path.dirname(__file__))
    # 用 os.path.join 拼接路径，它会自动处理 Windows(\) 和 Linux(/) 的斜杠差异
    yaml_file_path = os.path.join(root_path, "data", filename)
    return yaml_file_path
```

#### 5.2 读取 YAML 数据 (PyYAML)
YAML 是一种非常易读的配置数据格式。Python 需要安装 `PyYAML` 库来解析它。
```python
import yaml

def get_yaml_data(filename):
    # 使用上一步的路径获取函数，打开文件，指定 utf-8 编码防乱码
    with open(get_yaml_path(filename), "r", encoding="utf-8") as f:
        # yaml.safe_load 把 yaml 文件内容转换为 Python 的字典(dict)或列表(list)
        data = yaml.safe_load(f)
        return data
```

#### 5.3 parametrize 参数化测试
当你需要用多组不同的数据（比如：正确密码、错误密码、空密码）去测试同一个登录逻辑时，不要写多个测试用例，用 `@pytest.mark.parametrize` 搞定：
```python
import pytest
from utils.read_file import get_yaml_data

class TestLogin:
```

### 6. 工程化利器：日志处理 (Logging)

在无人值守的自动化执行过程中，记录完整的日志（包含时间、报错文件、执行结果）是排错的唯一线索。

我们可以自己封装一个全局的日志器（Logger）：
```python
import logging
import time
from utils.get_path import get_log_path

class Logger:
    """创建项目共用的文件及控制台日志器。"""
    def __init__(self) -> None:
        # 每天生成一个新的日志文件，如 2026-07-21.log
        self.logname = get_log_path() / f"{time.strftime('%Y-%m-%d')}.log"
        self.logger = logging.getLogger("autotest_logger")
        self.logger.setLevel(logging.DEBUG)

        # 避免重复加载时输出两遍日志
        if not self.logger.handlers:
            # 定义日志输出的格式: 时间 - 文件名 - 行号 - 级别 - 消息
            formatter = logging.Formatter(
                "【%(asctime)s】【%(filename)s %(lineno)d】【%(levelname)s】: %(message)s"
            )
            
            # 处理器1: 把日志写入到文件
            file_handler = logging.FileHandler(self.logname, mode="a", encoding="utf-8")
            # 处理器2: 把日志输出到控制台(屏幕)
            console_handler = logging.StreamHandler()
            
            for handler in (file_handler, console_handler):
                handler.setFormatter(formatter)
                self.logger.addHandler(handler)

# 实例化给外部调用
logger = Logger().logger
```
**如何使用它？**
只需要把它引入你的 `BasePage` 中，替换掉之前的 `print()`，不仅屏幕上能看到，错误还会自动写进文本里！而且在 `try...except` 块中，使用 `logger.exception(e)` 甚至能把完整的报错堆栈原封不动地记录下来！
