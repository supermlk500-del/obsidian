## 四、飞书群聊当前秩序

当前飞书通道已设置为：

- **`requireMention = true`**
- **群聊默认仅在被 @ 时响应**

这意味着：

- 所有 Agent 在飞书群聊中，**不被 @ 就不应该发言**
- 群内不会因为普通聊天内容而触发机器人乱插话
- 只有被明确点名的 Agent 才会回应

这是当前秩序的第一层约束。

### 群聊正式下令规则

在群聊中，下达正式任务时：

- **必须显式 `@某个agent`**
- 没有 `@某个agent`，不算正式派令
- 讨论、征求意见、背景说明，不等于正式任务

#### 正确示例
- `@taizi 帮我整理这个需求并转中书省`
- `@zhongshu 起草这个任务的执行方案`
- `@shangshu 把这个任务分派给六部执行`
- `@gongbu 开始开发这个功能`

#### 不正确示例
- `这个需求你们看看怎么做`
- `现在谁来处理一下`
- `这个要尽快推进`

以上这些如果没有明确 `@某个agent`，都不视为正式下令。

## 五、群聊中的接令回执与进度可见性

这是目前最关键的新规则之一，目的只有一个：

> **最高长官在群里下达任务后，必须能立刻知道任务有没有启动、执行到哪一步。**

### 1. 被点名后必须立即回执
被 `@` 的 agent 收到正式命令后，**不能静默处理**，必须先在群里明确回执。

可接受的回执示例：

- `已接令`
- `开始执行`
- `正在处理`
- `已接旨，开始起草`
- `已接令，正在分派`

### 2. 关键阶段必须继续汇报进展
如果任务不是立刻完成，而是要经过多个阶段，那么 agent 不能只在内部处理，必须继续在群里同步关键进展。

建议至少同步这些阶段：

- 已接令
- 开始处理
- 已进入下一阶段
- 遇到阻塞
- 已完成

### 3. 典型示例
- `中书省已接旨，正在起草方案`
- `尚书省已接令，正在分派六部`
- `工部已接令，开始开发`
- `兵部已接令，正在排查部署问题`
- `门下省已完成审议：准奏`
- `尚书省汇总完成，准备回奏`

### 4. 规则目标
这条规则是为了解决三个现实问题：

- 不知道命令有没有生效
- 不知道任务有没有开始
- 不知道任务执行到哪里了

因此现在群聊中的总原则是：

> **必须点名发令，必须回执接令，必须汇报进度。**

## 六、朝廷内部正式派令规则

除了飞书层面的 “被 @ 才响应”，还建立了内部官制规则：

> **凡上级向下级下达正式命令，必须显式使用 `@agent_id`；没有 `@`，不算正式派令。**

这条规则已经补进关键角色规范中，成为行为准则。

### 具体链路如下

#### 1. 太子
- 太子向中书省传旨时，必须使用：`@zhongshu`

#### 2. 中书省
- 向门下省发审议令时，必须使用：`@menxia`
- 向尚书省发执行令时，必须使用：`@shangshu`

#### 3. 门下省
- 只将带 `@menxia` 的内容视为正式审议令
- 不带 `@menxia` 的内容，只视为讨论、说明或草案

#### 4. 尚书省
- 向六部/吏部正式派令时，必须分别使用：
  - `@hubu`
  - `@libu`
  - `@bingbu`
  - `@xingbu`
  - `@gongbu`
  - `@libu_hr`

#### 5. 六部 / 吏部
- 只将带本部门 `@agent_id` 的内容视为正式派令
- 正式回奏尚书省时，应使用：`@shangshu`

#### 6. 早朝官
- 只将带 `@zaochao` 的内容视为正式派令
- 原则上不越级发令
