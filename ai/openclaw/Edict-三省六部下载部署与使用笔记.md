## 一、这是什么

`Edict` 是一套基于 **OpenClaw** 的多 Agent 协作系统，用“三省六部”的官制方式组织多个 Agent 分工协作。

你可以把它理解成：

- **最高长官 / 皇上**：你
- **main / main_feishu**：最高默认入口
- **太子（taizi）**：接旨、分拣消息
- **中书省（zhongshu）**：起草执行方案
- **门下省（menxia）**：审核方案，准奏/封驳
- **尚书省（shangshu）**：总调度，派发六部
- **六部**：具体执行
- **早朝官（zaochao）**：播报、简报类工作

它适合：

- 多 Agent 协作
- 代码任务编排
- 需求拆解 → 审核 → 执行 → 汇总
- 飞书群聊中的多人协作

## 三、部署前提

要跑 Edict，前提不是只有它自己，还包括整个运行环境：

### 1. OpenClaw 已安装
必须先有 OpenClaw 主体。

### 2. OpenClaw Gateway 可运行
Edict 的很多联动能力依赖 Gateway。

### 3. Windows + WSL
这是你当前环境的关键点。

因为：
- Edict 的 dashboard/server.py 依赖 Linux 环境特性（如 `fcntl`）
- **不能直接用 Windows Python 启动看板服务**
- 需要通过 **WSL** 跑看板和循环脚本

### 4. Python 环境
WSL 里要有 `python3`。

### 5. Feishu 机器人账号（如果要接飞书）
如果要做飞书协作，每个 Agent 或主要 Agent 需要各自的飞书机器人 appId / appSecret。

## 七、当前三省六部规则（很重要）

## 1. 最高长官
当前最高长官保持为：

- `main`
- `main_feishu`

它们是默认最高入口。

---

## 2. 群聊中只有被 @ 才能说话
当前飞书群聊已经收紧成：

- **只有被 @ 才响应**
- 不被 @ 不应主动发言

这条规则已经落实。

---

## 3. 正式派令必须 `@agent`
现在朝廷内部正式派令规则是：

> **凡正式下达命令，必须显式 `@某个agent`。没有 `@`，不算正式发令。**

例如：

- `@taizi 帮我整理这个需求`
- `@zhongshu 起草执行方案`
- `@shangshu 分派六部执行`
- `@gongbu 开始开发`

没有 `@` 的，只能当讨论，不算正式任务启动。

---

## 4. 接令后必须回执
你后来补充的一条关键制度是：

> **被点名的 Agent 不能静默处理，必须先回执。**

比如：

- `已接令`
- `开始执行`
- `已接旨，开始起草`
- `尚书省已接令，正在分派`

这一步是为了解决：

- 你在群里发了任务
- 但看不出来任务到底有没有开始

---

## 5. 关键阶段必须汇报进度
如果任务不是一条消息秒完成，就必须在群里继续同步关键进展。

例如：

- `中书省已接旨，正在起草方案`
- `门下省已接审议令，开始审核`
- `工部已接令，开始开发`
- `兵部已接令，正在排查部署问题`
- `尚书省汇总完成，准备回奏`

这条规则现在的总纲是：

> **必须点名发令，必须回执接令，必须汇报进度。**

## 八、电脑端怎么用

### 场景 1：查看整体状态
打开：

- `http://127.0.0.1:7892`

你可以看：

- 三省六部当前状态
- 当前任务流转
- 看板数据
- Agent 状态

### 场景 2：确认某项任务是否开始
看板会比群聊更直观。

如果你在群里下了任务，又不放心，就去电脑看板确认：

- 是否创建了任务
- 任务现在在哪一省/哪一部
- 有没有进展记录

### 场景 3：看任务卡在哪
如果任务长期没有推进，可以通过看板判断：

- 卡在中书起草
- 卡在门下审议
- 卡在尚书派发
- 卡在六部执行

处理方式：

- 走 pairing approve

也就是说：
