在 Java 中，**类变量（即静态变量，用 `static` 修饰的字段）** 的内存布局与实例变量有本质区别。理解其内存位置有助于掌握 JVM 内存模型和程序行为。

---

### 一、类变量存储在 **方法区（Method Area）**
> ⚠️ 注意：从 Java 8 开始，**方法区的实现由“永久代（PermGen）”变为“元空间（Metaspace）”**，但逻辑概念不变。

- **类变量属于类本身**，而不是某个对象。
- 当 JVM **加载一个类时**，会为该类的**所有静态变量在方法区中分配内存**。
- 这块内存**在整个应用程序生命周期内只有一份**，被该类的所有实例**共享**。

#### 示例：
```java
class Counter {
    static int count = 0; // 类变量，存放在方法区
    String name;          // 实例变量，存放在堆中（每个对象一份）
}
```

- 无论你创建多少个 `Counter` 对象（如 `new Counter()`），`count` 始终只有一份，位于方法区。
- 所有对象对 `count` 的修改，都会影响同一个内存位置。

---

### 二、与实例变量的对比

| 成员类型       | 存储区域     | 生命周期             | 是否共享 |
|----------------|-------------|----------------------|--------|
| **类变量（static）** | 方法区（Metaspace） | 类加载时初始化，JVM 退出时销毁 | 是（所有对象共享） |
| **实例变量**        | 堆（Heap）         | 对象创建时分配，GC 回收时销毁   | 否（每个对象独立） |

> 💡 补充：局部变量（方法内的变量）存储在 **虚拟机栈（Stack）** 中。

---

### 三、内存布局示意图（简化）

```
JVM Memory
┌──────────────┐
│   Method Area (Metaspace)      │ ←─ 类变量（如 Counter.count）
│   - Class metadata             │
│   - Static fields              │
└──────────────┘
│   Heap                         │ ←─ 实例变量（如每个 Counter 对象的 name）
│   - Object1: {name="A"}        │
│   - Object2: {name="B"}        │
└──────────────┘
│   Stack                        │ ←─ 局部变量、方法调用
│   - main()                     │
└──────────────┘
```

---

### 四、重要特性

1. **初始化时机**  
   - 类变量在**类初始化阶段**（<clinit> 方法执行时）被赋初值。
   - 比任何对象的创建都早。

2. **线程共享**  
   - 方法区是**所有线程共享**的，因此类变量也是**多线程共享的**。
   - 如果多个线程同时修改 `static` 变量，**需要同步控制**（如 `synchronized`）。

3. **基本类型 vs 引用类型**
   - `static int x = 10;` → `x` 的值直接存在方法区。
   - `static List<String> list = new ArrayList<>();` →  
     - **引用 `list`** 存在方法区，  
     - **实际的 `ArrayList` 对象** 仍创建在**堆**中。

---

### 五、常见误区

❌ “静态变量存在栈中” → 错！  
✅ 静态变量存在**方法区**（逻辑上属于非堆内存）。

❌ “每个对象都有自己的静态变量” → 错！  
✅ 所有对象**共享同一个**静态变量。

---

### 六、总结

- **类变量（static 字段）存储在 JVM 的方法区（Java 8+ 是 Metaspace）**。
- 它们在**类加载时分配**，**全局唯一**，**被所有实例共享**。
- 理解这一点，有助于分析内存使用、多线程安全和类加载机制。

如果你正在学习 Java 内存模型或准备面试，这是非常核心的知识点！
