# 📘 VisualSVN 

> 适用场景
> 
> - 第一次使用 SVN
>     
> - Windows 系统
>     
> - 使用 VisualSVN Server
>     
> - 本地已有文件（代码 / 笔记）
>     
> - 图形化操作为主，理解 SVN 工作流程
>     

---

## SVN 使用前必须先建立的认知

### SVN 是什么

SVN（Subversion）是一个 **集中式版本控制系统**  
所有代码和历史版本 **统一存放在服务器上**

开发时的核心思想是：

> **先从服务器拉代码 → 本地修改 → 提交回服务器**

---

### SVN 与 Git 的核心区别（一定要知道）

|对比点|SVN|Git|
|---|---|---|
|架构|集中式|分布式|
|是否必须依赖服务器|是|否|
|本地是否有完整历史|没有|有|
|提交是否立即到服务器|是|否|
|常见使用方式|图形化|命令行|

---

### VisualSVN 包含哪些东西

- VisualSVN Server  
    用来 **创建和管理 SVN 仓库**
    
- VisualSVN Client / TortoiseSVN  
    用来 **在本地操作 SVN**
    

---

## 使用 VisualSVN 之前要先准备的事情

### 安装 VisualSVN Server

- 下载 VisualSVN Server（Windows）
    
- 安装时选择默认配置即可
    
- 安装完成后，桌面会有 **VisualSVN Server Manager**
    

---

### 启动 VisualSVN Server Manager

打开后你会看到：

- Repositories（仓库）
    
- Users（用户）
    
- Groups（用户组）
    

这一步说明：

> **SVN 服务已经在本机运行**

---

## 创建 SVN 仓库（服务器端）

### 创建仓库的时机

当你需要让项目或笔记：

- 被版本管理
    
- 被多人访问
    
- 被统一存储
    

就需要创建 SVN 仓库

---

### 创建仓库的操作路径

- 打开 VisualSVN Server Manager
    
- 右键 Repositories
    
- 选择 Create New Repository
    
- 选择 Regular Repository
    
- 设置仓库名
    
- 保持默认结构（trunk / branches / tags）
    

📌 此时仓库已经存在于服务器

---

### SVN 标准目录结构的含义

- trunk  
    主开发分支，日常开发使用
    
- branches  
    分支目录，用于功能开发或版本隔离
    
- tags  
    标签目录，用于版本快照（只读）
    

---

## 创建 SVN 用户（服务器端）

### 为什么要创建用户

SVN 的每一次提交：

- 都必须绑定用户
    
- 用来区分是谁提交了代码
    

---

### 创建用户的操作路径

- 打开 Users
    
- 新建 User
    
- 设置用户名和密码
    

---

### 给仓库分配权限

- 选中仓库
    
- 打开 Properties / Security
    
- 给用户或用户组分配权限
    
- 一般选择 Read / Write
    

---

## 本地使用 SVN（客户端角度）

### SVN 的本地工作目录是什么

SVN 的本地目录本质是：

> **服务器仓库的一个“工作副本”**

它不是随便一个文件夹  
而是 **必须通过 SVN 检出（Checkout）得到**

---

## 从服务器拉取代码（第一次必须做）

### 什么情况下需要 Checkout

- 第一次接触某个 SVN 项目
    
- 本地还没有 SVN 工作副本
    
- 更换电脑
    

---

### Checkout 的正确方式

- 在本地选择一个空文件夹
    
- 右键 → SVN Checkout
    
- 输入仓库地址
    
- 选择 trunk 目录
    
- 输入用户名和密码
    

完成后：

- 本地文件夹中会出现 `.svn`
    
- 文件图标会显示绿色对勾
    

---

## SVN 文件状态的含义（必须会看）

|图标|含义|
|---|---|
|绿色对勾|与服务器一致|
|红色叹号|文件被修改|
|蓝色加号|新增文件|
|灰色问号|SVN 未管理|

---

## 把本地已有文件纳入 SVN 管理

### 使用场景

- 本地已有笔记或代码
    
- 想让它们进入 SVN 管理
    

---

### 正确操作方式

- 把文件复制到 SVN 工作副本中
    
- 右键 → SVN Add
    
- 文件状态变为蓝色加号
    

📌 此时只是“标记为新增”，并未提交

---

## 提交代码到服务器（核心操作）

### 什么时候需要 Commit

- 新增文件
    
- 修改文件
    
- 删除文件
    

---

### Commit 的操作流程

- 在工作副本中右键
    
- 选择 SVN Commit
    
- 填写提交说明
    
- 确认提交
    

提交完成后：

- 文件状态变回绿色对勾
    
- 服务器上已保存版本
    

### 正确判断方式

- 使用 SVN Status 查看状态
    
- 看文件图标颜色
    
- 是否存在 `.svn` 目录
    

---

## 从服务器获取他人的修改

### Update 的作用

Update 用来：

> **把服务器上的最新版本同步到本地**

---

### 什么时候需要 Update

- 提交前
    
- 发现别人改过代码
    
- 长时间未同步
    

---

### Update 的操作方式

- 在工作副本右键
    
- 选择 SVN Update
    

---

## 冲突的产生与解决

### 冲突出现的原因

- 本地修改了文件
    
- 服务器同一文件被别人提交
    
- Update 时无法自动合并
    

---

### 冲突的处理流程

- SVN 会标记冲突文件
    
- 手动编辑冲突内容
    
- 保存正确版本
    
- 标记冲突已解决
    
- 再次 Commit
    

---

## SVN 的核心工作流总结（一句话版）

> **Checkout → 修改 → Add → Commit → Update**

---

## SVN 使用时必须牢记的几个原则

- 不要直接在非工作副本中改文件
    
- 提交前先 Update
    
- 提交说明必须写清楚
    
- 冲突不要慌，先看内容再处理
    

---

## SVN 非常适合的场景

- 公司内部项目
    
- 强依赖权限管理
    
- 流程固定、人员稳定
    
- 以 Windows + GUI 为主的团队
